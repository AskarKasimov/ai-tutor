# Правила работы в репозитории

Действуют для всего репозитория. При изменениях frontend также прочитайте [локальный AGENTS.md](services/frontend/AGENTS.md). Видение, термины, статус реализации, запуск и проверки — в [README.md](README.md); чек-лист перехода — [checklist.html](checklist.html).

## Порядок работы

1. Определите слой изменения: services/backend, services/frontend, services/postgresql, services/caddy, services/course-graph, api или documents. Geek и course-graph — отдельные модули backend; LLM gateway — отдельный сервис `services/llm-gateway`.
2. Учебную логику сверяйте с видением в [README](README.md). Схема БД — [backend README](services/backend/README.md#бд-и-импорт); авторизация — [auth.md](documents/auth.md).
3. Для HTTP сверяйте код и [единый OpenAPI](api/openapi.yaml). implemented означает подключённую операцию, planned — проект. При изменении DTO/аннотаций обновляйте контракт генератором и соответствующие тесты.
4. В backend сохраняйте слои и направление зависимостей из [архитектуры](documents/backend-architecture.md). SQLC генерируйте из запросов. Применённые миграции дополняйте следующей версией; согласованный сброс расходной dev-БД допускает переработку начальной схемы без переноса старых данных.
5. Проверяйте затронутые сервисы командами из README и их локальной документации. В результате указывайте выполненные проверки и пропуски интеграционных DB-тестов.
6. При расхождении кода, требований и документации фиксируйте его явно. Доступность моделей и применение миграций подтверждайте фактическими запросами; успешный health проверяет backend и БД.

## Видение продукта

Действующее видение — Geek: устный экзамен и тренировка в диспуте по графу курса, построенному компонентой course-graph из материалов курса (README: [«Курс»](README.md#курс), [course-graph](README.md#course-graph-граф-знаний-курса), [Geek](README.md#geek-устный-экзамен-и-тренировка)). Исходная концепция проректора — [documents/](documents/Концепция_Репетитор_устного_экзамена.md); при расхождении действует трактовка из README. К показу 18.10.2026 — материалы курса, граф и диагностика с итогом (Must), пакет для преподавателя (Could); тренировка и аттестация с прокторингом — после показа (приоритеты — в README, «План работ до показа»). Пока модули не реализованы, это цель, а не текущее поведение.

- Содержание — только из материалов курса (лекции, лабы, туториалы по неделям). Оценка по шкале A/B/C/D предварительная; итоговую на аттестации ставит преподаватель. Не генерировать учебное содержание вне материалов, кроме правил ответа на вопросы студента в тренировке (ниже).
- Число недель и видов материалов не фиксируется: курс может иметь 8 недель или только лабы.
- Граф общего вида: темы и пререквизиты (у пререквизитов свои пререквизиты), без циклов; верхний уровень — темы, которые не служат пререквизитом другим. Вершина хранит название, текст, ID пререквизитов, ОР и вопросы (строки, пока могут быть пустыми); недели и источников у вершины пока нет. Одна версия графа на курс; у прошедших диагностик после пересборки остаётся только фидбэк.
- Экзамен: модель оценивает ответ по тексту вершины по четырём критериям (0/1/2), по ним теме ставится A–D (таблица в README); ответ с помощью — только B или C; статусы темы — самостоятельный ответ, ответ с помощью, пробел, недостаточно данных, засчитано по вышестоящей теме. Каждый вывод опирается на фрагменты диалога; непроверенная тема не считается неосвоенной. На тему — основной вопрос и не больше одного дополнительного; каждый вопрос можно один раз переформулировать, других подсказок нет. Тема на A/B/C засчитывает все свои пререквизиты, тема на D — пробел и ведёт к пререквизитам; пробел — самая глубокая неосвоенная вершина с освоенными пререквизитами. Предварительная оценка курса — средний балл тем верхнего уровня (A = 4, B = 3, C = 2, D = 1; темы со статусом «недостаточно данных» исключаются) в процентах от максимума 4: не меньше 90% — A, не меньше 75% — B, не меньше 60% — C, иначе D.
- Тренировка: вопрос «Сколько у тебя часов?», план — пробелы снизу вверх по пререквизитам; по подтеме — теория из лекции, практика по лабе или туториалу и диспут: возражения, контрпримеры, фиксируемые подсказки, итоговая задача без подсказки. Ответы вне материалов: слишком простые — по пререквизитам из листьев графа, слишком сложные — только название темы без ссылки; такие ответы помечаются и не расширяют объём проверки.
- Пакет для преподавателя (в админке): транскрипт с нумерацией строк, карта покрытия, наблюдения по критериям для пробелов со ссылками на строки.
- Всё на русском: материалы, граф, вопросы, диалог, интерфейс. Реплики Geek — текст с голосовым дублированием; ответ студента — голосом или текстом.
- LLM вызываются только через LLM gateway (четыре модели): OpenAI-совместимый HTTP или protobuf gRPC без поля model, с обязательной сложностью `complexity` и необязательной срочностью `urgent`. Backend (Geek) ходит в gateway по gRPC через модуль `services/shared`. Очередь и балансировка — в gateway. Этапы обработки course-graph выполняет отдельный Python-сервис `services/course-graph` (OCR — первый этап); оркестрация и хранение графа — в backend. Настройки gateway хранятся в его локальном config; адреса апстримов и секреты не передаются браузеру.
- Переиспользуйте существующие модули. **Удаление** модулей, таблиц, миграций, ручек, экранов и документов — только после явного согласования с владельцем продукта: сначала спросить, затем удалять.
- Открытые вопросы перечислены в [README](README.md#открытые-вопросы); не закрывайте их в коде молча — фиксируйте решение в README.

## Интеграции и данные

Настройки моделей и секреты находятся на backend; VITE_* доступны браузеру. Frontend обращается к backend через Caddy.

STT принимает multipart audio (WAV/Ogg/WebM до 25 МиБ), TTS — JSON text до 500 символов и возвращает WAV. Для длинной речи GigaAM нужны longform/VAD зависимости на сервере модели. Браузерный синтез речи не используется.

В dev корневой Compose запускает Vite и Air с исходниками; сервисные Compose для production запускают nginx и готовый бинарник. PostgreSQL хранит данные в постоянном volume: down сохраняет его, down -v удаляет данные. Удаление volume не является обычным перезапуском.
