# Правила работы в репозитории

Действуют для всего репозитория. При изменениях frontend также прочитайте [локальный AGENTS.md](services/frontend/AGENTS.md). Видение, термины, статус реализации, запуск и проверки — в [README.md](README.md); чек-лист перехода — [checklist.html](checklist.html).

## Порядок работы

1. Определите слой изменения: services/backend, services/frontend, services/postgresql, services/caddy, services/course-graph, api или documents. Geek, course-graph и клиент к 4 LLM — отдельные модули backend.
2. Новую учебную логику сверяйте с видением в [README](README.md). Для существующих модулей прежней модели — [сценарий](documents/voice-trainer-scenarios.md) и [алгоритм варианта](documents/Алгоритм_составления_варианта.md). Наблюдения перед реализацией диагностики — [PLAN.md](PLAN.md); схема и импорт — [backend README](services/backend/README.md#бд-и-импорт); авторизация — [auth.md](documents/auth.md).
3. Для HTTP сверяйте код и [единый OpenAPI](api/openapi.yaml). implemented означает подключённую операцию, planned — проект. При изменении DTO/аннотаций обновляйте контракт генератором и соответствующие тесты.
4. В backend сохраняйте слои и направление зависимостей из [архитектуры](documents/backend-architecture.md). SQLC генерируйте из запросов. Применённые миграции дополняйте следующей версией; согласованный сброс расходной dev-БД допускает переработку начальной схемы без переноса старых данных.
5. Проверяйте затронутые сервисы командами из README и их локальной документации. В результате указывайте выполненные проверки и пропуски интеграционных DB-тестов.
6. При расхождении кода, требований и документации фиксируйте его явно. Доступность моделей и применение миграций подтверждайте фактическими запросами; успешный health проверяет backend и БД.

## Видение продукта

Действующее видение — Geek: устный экзамен и тренировка в диспуте по графу курса, построенному компонентой course-graph из материалов курса (README: [«Курс»](README.md#курс), [course-graph](README.md#course-graph-граф-знаний-курса), [Geek](README.md#geek-устный-экзамен-и-тренировка)). Исходная концепция проректора — [documents/](documents/Концепция_Репетитор_устного_экзамена.md); при расхождении действует трактовка из README. К показу 18.10.2026 — диагностика, тренировка и базовый пакет для преподавателя; аттестация с прокторингом — следующий этап. Пока модуль не реализован, это цель, а не текущее поведение.

- Содержание — только из материалов курса (лекции, лабы, туториалы по неделям). Оценка по шкале A/B/C/D предварительная; итоговую на аттестации ставит преподаватель. Не генерировать учебное содержание вне материалов, кроме правил ответа на вопросы студента в тренировке (ниже).
- Число недель и видов материалов не фиксируется: курс может иметь 8 недель или только лабы.
- Граф: темы → подтемы, пререквизиты без циклов; вершина хранит текст, неделю и источники. Одна версия графа на курс; у прошедших диагностик после пересборки остаётся только фидбэк.
- Экзамен: модель оценивает ответ по тексту вершины по четырём критериям (0/1/2), по ним теме ставится A–D (таблица в README); ответ с помощью — только B или C; статусы темы — самостоятельный ответ, ответ с помощью, пробел, недостаточно данных, засчитано по вышестоящей теме. Каждый вывод опирается на фрагменты диалога; непроверенная тема не считается неосвоенной. На тему — основной вопрос и не больше одного дополнительного; каждый вопрос можно один раз переформулировать, других подсказок нет. Тема на A/B/C засчитывает поддерево, тема на D — пробел и ведёт к пререквизитам; пробел — самая глубокая неосвоенная вершина с освоенными пререквизитами. Предварительная оценка курса — средний балл верхнеуровневых тем (A = 4, B = 3, C = 2, D = 1; темы со статусом «недостаточно данных» исключаются) в процентах от максимума 4: не меньше 90% — A, не меньше 75% — B, не меньше 60% — C, иначе D.
- Тренировка: вопрос «Сколько у тебя часов?», план — пробелы снизу вверх по пререквизитам; по подтеме — теория из лекции, практика по лабе или туториалу и диспут: возражения, контрпримеры, фиксируемые подсказки, итоговая задача без подсказки. Ответы вне материалов: слишком простые — по пререквизитам из листьев графа, слишком сложные — только название темы без ссылки; такие ответы помечаются и не расширяют объём проверки.
- Пакет для преподавателя (в админке): транскрипт с нумерацией строк, карта покрытия, наблюдения по критериям для пробелов со ссылками на строки.
- Всё на русском: материалы, граф, вопросы, диалог, интерфейс. Реплики Geek — текст с голосовым дублированием; ответ студента — голосом или текстом.
- LLM вызываются только через клиент к 4 LLM (модели уровня gpt-oss-120b): для кода это одна модель с параллельными запросами, очередь и балансировка — в клиенте; этапы обработки course-graph выполняет отдельный Python-сервис `services/course-graph` (OCR — первый этап), он ходит в клиент по gRPC; оркестрация и хранение графа — в backend. Настройки и секреты — только на сервере.
- Переиспользуйте существующие модули. **Удаление** модулей, таблиц, миграций, ручек, экранов и документов — только после явного согласования с владельцем продукта: сначала спросить, затем удалять.
- Открытые вопросы перечислены в [README](README.md#открытые-вопросы); не закрывайте их в коде молча — фиксируйте решение в README.

## Правила действующей реализации (прежняя модель)

Код пока реализует карту компетенций и варианты. Эти правила действуют для изменений существующих модулей, пока их не заменили или не удалили после согласования.

- Основа — текущая карта ML CSV/XLSX; формат сохраняется, добавляются полные задания и TRUE. Сборка не требует ручной линковки ОР или дополнительных документов.
- Вариант строится по всей карте без выбора темы, только из ОР с TRUE в «Что должно войти в тест». Компетенция включается, только если в ней не меньше трёх готовых TRUE-ОР; иначе она пропускается с причиной. Основной — ОР с наибольшим рангом Блума, при равном ранге — с большей важностью, при полном равенстве — по порядку карты. Два базовых — самые простые из остальных ОР (ранг Блума по возрастанию, важность по убыванию, порядок карты); их ранг может совпадать с рангом основного. Число заданий считается по сохранённым позициям; прежние снимки не пересобираются (`competency-map-v4`).
- Рандом применяется только внутри пула выбранного ОР. Seed не нужен. Свободная тренировка тоже использует только TRUE-ОР.
- Variantgen реализован для сборки, сохранения снимков и доступа. Четыре операции `/variants` описаны в едином OpenAPI. Приём ответов, грейдинг, прохождение и тренировка вне его scope. Действующие taskgen и assessment сохраняются.
- ОС связана с ОР 1:1; отсутствие текста — NULL. Неполные фрагменты источника не выдаются как задания. Имена таблиц и полей — английские.
- Импорт атомарно заменяет активную карту и банк; пользователи и расшифровки сохраняются. Ошибка откатывает замену. Сохранённые варианты читаются из собственных снимков после переимпорта.
- В общем продукте основной оценивается в 0/1/3, базовый — в 0/1; диагностическая сумма учитывает основные и предъявленные базовые задания (максимум 3 балла на компетенцию). Непроверенные ОР не объявляются пробелами, техническая ошибка не считается учебным нулём, тренировка не меняет исходную диагностику.

## Интеграции и данные

Настройки моделей и секреты находятся на backend; VITE_* доступны браузеру. Frontend обращается к backend через Caddy. Эталоны и criteria не выдаются студенческим каталогом.

STT принимает multipart audio (WAV/Ogg/WebM до 25 МиБ), TTS — JSON text до 500 символов и возвращает WAV. Для длинной речи GigaAM нужны longform/VAD зависимости на сервере модели. В прежней модели TTS озвучивает сохранённую голосовую инструкцию задания: backend-worker заранее кладёт WAV в S3, frontend воспроизводит его; браузерный синтез речи не используется. Ответ — голосовой выбор и объяснение, без ручной правки расшифровки; если инструкция требует назвать вариант и объяснить, отсутствие названия словами даёт 0, одного номера недостаточно.

В dev корневой Compose запускает Vite и Air с исходниками; сервисные Compose для production запускают nginx и готовый бинарник. PostgreSQL хранит данные в постоянном volume: down сохраняет его, down -v удаляет данные. Удаление volume не является обычным перезапуском.
