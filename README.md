# Geek — устный AI-экзамен по университетскому курсу

Geek — цифровой педагог: проводит со студентом устный экзамен по конкретному курсу, находит пробелы и тренирует по ним в диспуте. Содержание берётся только из материалов курса (лекции, лабы, туториалы). Знания курса заранее раскладываются в граф тем с зависимостями-пререквизитами, и Geek ведёт экзамен по этому графу. Исходное видение — [концепция проректора «Репетитор устного экзамена»](documents/Концепция_Репетитор_устного_экзамена.md); ниже — принятая для нас трактовка.

## Курс

- **Демонстрационный курс** — Б1.О.17 Philosophy II (Introduction to AI) / Философия II (Введение в искусственный интеллект), профиль «Анализ данных и искусственный интеллект» (DSAI), Университет Иннополис, 4-й семестр, 144 ч, экзамен.
- **Источник содержания — материалы курса**: лекции, лабы и туториалы по неделям. При загрузке в админке у каждого материала указываются неделя и вид (лекция / лаба / туториал). Материалы демокурса — 28 PDF за недели 1–14 в [`documents/materials/`](documents/materials/); пока на английском, команда переведёт их на русский вручную. Структура у курсов разная: 8 недель, курс без лаб или туториалов, только лабы. Число недель и видов материалов не фиксируется в коде.
- **Предварительная оценка** диагностики — по шкале A «отлично», B «хорошо», C «удовлетворительно», D «неудовлетворительно». Каждая проверенная тема получает оценку A–D по критериям; оценка курса — средний балл тем верхнего уровня (A = 4, B = 3, C = 2, D = 1; темы со статусом «недостаточно данных» исключаются) в процентах от максимума 4: не меньше 90% — A, не меньше 75% — B, не меньше 60% — C, иначе D. Это ориентир для студента; итоговую оценку на аттестации ставит преподаватель.
- **Всё на русском**: материалы, граф, вопросы, диалог, интерфейс. Материалы курса команда переведёт на русский вручную; граф строится на русском уже сейчас.

## course-graph: граф знаний курса

Состоит из двух частей. Python-сервис `services/course-graph` выполняет этапы обработки (OCR, очистка, юниты, дедупликация, зависимости, валидация): у них тяжёлые зависимости (Docling, PyTorch), а распознавание долгое и нагружает CPU и память, поэтому сервис изолирован от API и масштабируется отдельно. Модуль backend запускает этапы, хранит граф в PostgreSQL и показывает результат в админке. Материалы курса загружаются в админке. Это сервис с повторяемыми этапами, а не набор разовых скриптов. LLM вызываются через отдельный LLM gateway: backend — по HTTP, сервис `services/course-graph` — по gRPC. Результат — граф курса в PostgreSQL, по которому работает Geek.

| № | Этап | Что делает |
| --- | --- | --- |
| 1 | OCR | PDF материалов → текстовые документы, по одному на лекцию, лабу и туториал каждой недели. |
| 2 | Очистка | LLM удаляет всё, что не относится к предмету: сведения о лекторе и команде курса, office hours, организационные объявления, «спасибо за внимание» и т. п. |
| 3 | Извлечение юнитов | Каждый документ недели (отдельно лекция, лаба, туториал) → несколько атомарных тем. Пример: лекция «Матрицы» → умножение матриц, нахождение обратной, транспонирование. |
| 4 | Дедупликация | Первый проход убирает дубли внутри недели, второй — одинаковые темы между неделями. |
| 5 | Зависимости | Для каждой темы — стрелки на темы курса, которые нужно знать, чтобы её понять. Пример: «ранг матрицы» → метод Гаусса, определение матрицы, миноры. |
| 6 | Валидация | Несколько прогонов LLM проверяют корректность стрелок и отсутствие циклов. |
| 7 | Сохранение | Граф записывается в PostgreSQL для Geek. |

**Структура графа**

- Граф общего вида: вершины (темы) и рёбра-пререквизиты «тема требует тему». У пререквизита могут быть свои пререквизиты; у вершины их может быть несколько. Граф ацикличен; плоский граф без рёбер — частный случай.
- Вершины верхнего уровня — те, что не служат пререквизитом ни одной другой вершины. С них начинается диагностика, по ним считается оценка курса.
- Вершина хранит название, текст темы из материалов, ID пререквизитов, образовательные результаты (ОР) и вопросы. ОР и вопросы — строки; пока они могут быть пустыми, позже их подготовят (вероятно, загрузят из карты компетенций). Неделя и источники у вершины пока не хранятся.
- Ручной проверки нет: граф публикуется после LLM-валидации. Красивая визуализация графа для собственного фактчекинга — в планах.
- На курс хранится одна версия графа. Пересборка заменяет граф целиком; у уже пройденных диагностик остаётся только фидбэк.
- Вопросы к вершинам можно сгенерировать на этапе препроцессинга; недостающие Geek генерирует в рантайме.
- Названия и тексты вершин — сразу на русском, даже если материалы пока на английском.
- Сборка запускается кнопкой «Собрать граф» в админке, а не автоматически после каждой загрузки.

## Geek: устный экзамен и тренировка

Geek проводит диагностику и тренировку только по графу курса.

### Диагностика — устный экзамен

1. Диалог ведёт LLM. Цель — выявить пробелы студента по материалам курса.
2. Вопросы — в формате устного экзамена: на рассуждение, с развёрнутым ответом. Тестовых вопросов по возможности нет.
3. Обход начинается с вершин верхнего уровня. Тема с оценкой A, B или C засчитана и засчитывает все свои пререквизиты, прямые и транзитивные: они получают отдельный статус «засчитано по вышестоящей теме», чтобы не смешивать их с проверенными. Тема с оценкой D — пробел: Geek спрашивает по каждому её пререквизиту и спускается дальше к более простым темам. Уже засчитанную тему повторно не спрашивают; если тему уже спросили, её собственный ответ важнее засчитывания.
4. На одну тему — основной вопрос и не больше одного дополнительного. Дополнительный вопрос углубляет проверку (пример, обоснование, контрпример, изменённые условия) или проясняет неоднозначный ответ.
5. Если студент затрудняется, Geek может один раз переформулировать вопрос. Других подсказок в диагностике нет; студент не может попросить повторить вопрос. «Не знаю» — пробел по этой теме.
6. Модель оценивает ответ по тексту вершины из материалов отдельно по каждому из четырёх критериев: 0 — не показал, 1 — частично, 2 — полностью.
   - К1. Предметная корректность и владение терминологией.
   - К2. Логичность суждений и обоснованность выводов.
   - К3. Способность отвечать на возражения и рассматривать контрпримеры.
   - К4. Применение знания в изменённых условиях и понимание ограничений ответа.

   Уверенность, скорость речи и красноречие не оцениваются. Из уровней критериев получается оценка темы:

   | Оценка темы | Условие |
   | --- | --- |
   | A | Ответ самостоятельный, все четыре критерия на 2. |
   | B | К1 и К2 на 2, К3 и К4 не ниже 1; либо ответ с помощью, все критерии не ниже 1. |
   | C | К1 не ниже 1 и хотя бы один критерий на 2; ответ с помощью, не дотянувший до B. |
   | D | Всё, что не дотянуло до C: К1 на 0, «не знаю», все критерии не выше 1 — пробел. |

   Ответ с помощью (после переформулировки) получает только B или C; если и после переформулировки тема на D, её статус — «пробел».
7. Статус темы — один из:
   - **самостоятельный ответ** — оценка A, B или C без переформулировки;
   - **ответ с помощью** — оценка B или C после переформулировки;
   - **пробел** — оценка D;
   - **недостаточно данных** — вывод сделать нельзя;
   - **засчитано по вышестоящей теме** — тема не спрашивалась: её засчитала тема, для которой она пререквизит.

   Для каждой проверенной темы фиксируются глубина понимания и фрагменты диалога, на которых основан вывод. Непроверенная тема не считается неосвоенной.
8. **Пробел** — самая глубокая неосвоенная вершина, все пререквизиты которой освоены.
9. Реплики Geek показываются текстом и дублируются голосом (TTS). Студент отвечает голосом или текстом.
10. Итог для студента: предварительная оценка A/B/C/D (по среднему баллу тем верхнего уровня) и список пробелов. Недели и источники к пробелам вернутся, когда вершина снова будет их хранить.

### Тренировка — обучение в диспуте

1. После итога задаётся вопрос «Сколько у тебя часов?».
2. План — пробелы в порядке пререквизитов, снизу вверх.
3. По каждой теме: теория из текста лекции, практика по лабе или туториалу, затем диспут. Студент предлагает ответ; Geek задаёт уточняющие вопросы, предъявляет возражения и контрпримеры, помогает сопоставить альтернативные объяснения; студент дополняет аргументацию или пересматривает вывод.
4. Подсказки в тренировке допустимы, каждая фиксируется. Объём поддержки сокращается по мере освоения; в конце студент применяет материал в новой задаче без подсказки.
5. Студент может задавать свои вопросы. Источники ответа Geek:
   - материалы курса — основной источник;
   - если вопрос слишком простой и его нет в материалах — пререквизиты, найденные в листьях графа;
   - если вопрос слишком сложный и его нет в материалах — Geek называет тему, которую стоит изучить, без ссылки на внешний источник.

   Ответ вне материалов курса явно помечается и не расширяет объём проверки.
6. Тренировка не меняет результат диагностики.

### Материалы для преподавателя

После диагностики формируется пакет; преподаватель смотрит его в админке:

- транскрипт диалога с разделением реплик студента и Geek и нумерацией строк;
- карта покрытия знаний — статус каждой темы графа по правилам выше;
- наблюдения по критериям оценки для пробелов со ссылками на номера строк транскрипта.

Смысловое сжатие беседы, события прокторинга и визуальное отображение карты — в будущем.

## LLM gateway

LLM gateway — отдельный HTTP-сервис `services/llm-gateway` со спецификацией [llm-gateway-spec.md](documents/llm-gateway-spec.md) и контрактом [openapi.yaml](services/llm-gateway/openapi.yaml). Он принимает OpenAI-совместимый `POST /v1/chat/completions` без выбора модели клиентом: обязательная сложность `complexity` (low / medium / high) и необязательная срочность `urgent`. Очередь — Redpanda, балансировка по четырём моделям — в gateway. Dev Compose запускает его с профилем `gateway`; локальный `services/llm-gateway/config.json` содержит настройки моделей. Backend и `services/course-graph` вызывают gateway из доверенной сети; CORS настроен в Caddy.

| Спуск при D | Тема на D → её пререквизиты, дальше рекурсивно (уточнено ниже: граф общего вида). |
| Диагностика | Модуль `diagnostic` и пути `/diagnostic-sessions` переделываются на месте; данные и прежние миграции не сохраняются. |
| Реплика студента | Синхронно: ответ Geek приходит в том же HTTP-запросе, с Idempotency-Key и повтором при сбое. |
| Тренировка | К показу не делаем. После показа — на существующих `/learning-plans`: план из пробелов в порядке пререквизитов. |
| LLM | Через LLM gateway коллеги: сейчас HTTP, позже также gRPC. |
| Верхнеуровневые темы | Тема — лекция недели, подтемы — юниты недели. Заменено решением ниже: иерархии «тема → подтема» нет. |
| Граф | Общего вида: вершины и пререквизиты, у пререквизитов свои пререквизиты, без циклов; плоский граф — частный случай. Верхний уровень — вершины, которые не служат пререквизитом другим. Вершина: название, текст, ID пререквизитов, ОР и вопросы (строки, пока могут быть пустыми). Неделя и источники у вершины пока не хранятся; итог показывает пробелы без них. |
| Общий пререквизит | Если тему уже засчитала другая тема (на A–C), её повторно не спрашивают; тогда пробелом становится тема на D, которая к ней ведёт. Если тему уже спросили, её собственный ответ важнее засчитывания. |
| Объём показа | Приоритеты по MoSCoW — в [плане работ](#план-работ-до-показа-1810). Тренировка в показ не входит. |

## Решения 16.10.2026: реализация Geek

| Вопрос | Решение |
| --- | --- |
| Переформулировка | Решает модель: если ответ на основной вопрос на D, Geek один раз переформулирует его. Ответ после переформулировки — «ответ с помощью», оценка темы не выше B. |
| «Не знаю» | Кнопкой или словами («не знаю» в голосе или тексте распознаёт модель): тема сразу становится пробелом, без переформулировки, и Geek переходит к её пререквизитам. Кнопка обрабатывается без вызова модели. |
| Вопросы на тему | Если ответ на первый вопрос не на D, задаётся второй — он проверяет К3 и К4 (возражение, контрпример, изменённые условия). Всего на тему не больше двух вопросов, не считая переформулировки. |
| Кто ставит оценку | Модель возвращает К1–К4 (0/1/2) и номера строк-оснований; оценку A–D, статусы и оценку курса считает код по таблице. |
| Источник вопроса | Если у вершины есть вопросы, первый берётся как есть; иначе модель генерирует вопрос по тексту вершины. |
| Порядок обхода | Темы верхнего уровня — в порядке массива; спуск в глубину: после темы на D сразу её пререквизиты до конца, затем следующая тема верхнего уровня. |
| Прогресс | Каждая тема верхнего уровня даёт равную долю (100% / их число). Ответы на её пререквизиты двигают прогресс внутри доли, но не выше неё; доля заполняется целиком, когда тема и спуск по ней завершены. Прогресс не уменьшается. |
| Недостаточно данных | Ответ не по теме или неразборчивый даже после переформулировки. Технический сбой статус не меняет: запрос повторяется. |
| Длина экзамена | Без ограничения; в конфиге есть необязательный максимум вопросов на сессию, по умолчанию выключен. |
| Данные для преподавателя | Критерии, строки-основания и транскрипт хранятся сразу; ручки пакета — позже (Could). |
| Повторная диагностика | После завершения можно начать новую; активная (незавершённая) — одна на курс. |
| Задержка | Цель — p95 ответа Geek не больше 20 с; frontend показывает, что Geek думает. |
| Нагрузка на показе | Не больше 5 студентов одновременно. |
| Сбой LLM | 503, состояние сессии не меняется; повтор с тем же Idempotency-Key, ответ студента не теряется. |
| Сложность запросов | Оценка ответа — `high`, генерация вопроса — `medium`, переформулировка — `low`. |
| Ответ модели | JSON (`response_format: json_object`), структура проверяется в коде. |
| LLM до мержа gateway | Мок по умолчанию; HTTP-адаптер к gateway включается адресом gateway в конфиге. |
| Источник графа | Адаптер: граф из БД, если он есть; иначе фикстура из `BACKEND_GEEK_GRAPH_FIXTURE`; без обоих — `GRAPH_NOT_READY`. |
| Логи | Логируется всё, включая промпты, ответы модели и тексты студентов. |
| Тесты | Unit-тесты обхода и оценки на фикстуре с фейковой LLM (A, D со спуском, общий пререквизит, «не знаю»), DB-тесты хранения, сквозной сценарий для репетиции. |

| Термин | Значение |

## Запуск

```bash
cp .env.example .env
# Задайте пароль БД и режимы API.
./dev.sh -d
```

На Windows вместо `dev.sh` используйте `.\up.ps1` из PowerShell: скрипт запускает Docker Desktop, при отсутствии создаёт `.env` из `.env.example` в режиме real со случайными секретами, выпускает сертификаты, поднимает стек, ждёт health и открывает сайт ученика и админ-панель. `.\up.ps1 -Logs` показывает логи, `.\up.ps1 -Down` останавливает стек с сохранением данных. Если PowerShell блокирует скрипты, один раз выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

Локально нужны Docker Compose и mkcert. Сайт ученика: https://localhost:8443, админ-панель: https://localhost:8443/admin, публичный API: `/api/v1`, health: `/api/v1/health`. Swagger доступен на `/docs/` при `COMPOSE_PROFILES=swagger`.

Для сервера: `.env.prod.example` → `.env`, готовые `certs/server.pem`/`server-key.pem`, сеть `ai-tutor_default`, затем `./prod.sh`. Dev-стек и серверные Compose используют общие имена сети и volumes; одновременно их не запускают.

- Frontend использует HTTP API для auth, предметов и материалов курса. Данные хранятся в PostgreSQL и переживают перезапуск backend. В dev VITE_* передаются контейнеру; после изменения .env пересоздайте frontend. В production значения применяются при сборке.
- Backend всегда использует действующие модели; настройки STT/TTS из `.env.example` обязательны.
- STT принимает WAV/Ogg/WebM до 25 МиБ и возвращает сохранённую расшифровку. TTS принимает до 500 символов и возвращает WAV. Без longform/VAD весов на сервере модели GigaAM отклоняет записи длиннее ~25 с, поэтому браузер переводит ответ длиннее 20 с в WAV 16 кГц, а backend режет его по паузам на части до 20 с и склеивает текст. Запись ответа автоматически останавливается через 1,5 минуты.
- PostgreSQL и S3 хранят данные в отдельных volumes. `down` сохраняет их; `down -v` удаляет. Миграции применяются при запуске API. Схема собрана заново 16.10.2026: volume с прежней историей миграций нужно один раз удалить (`down -v`).

### Live reload в Docker

Корневой `./dev.sh -d` запускает dev-образы: Vite HMR для frontend и Air для backend. Исходники подключены через bind mount; polling включён для Docker Desktop. HTTPS и HMR WebSocket проходят через Caddy.

Vite подхватывает изменения frontend. Air пересобирает и перезапускает API при изменениях Go, SQL, go.mod/go.sum; SQLC-код требует отдельной генерации. node_modules, модули Go, кеш сборки и dev-бинарник хранятся в отдельных volumes.

- Изменение .env: `docker compose up -d api frontend` для пересоздания затронутых контейнеров.
- Изменение package-lock.json: `docker compose restart frontend`; при старте dev-контейнер выполняет npm ci.
- Изменение Dockerfile: `docker compose up -d --build api frontend`.
- Изменение OpenAPI: `docker compose up -d --force-recreate swagger`; Swagger читает api/openapi.yaml.

Локальные Compose сервисов, используемые prod.sh, запускают готовый backend-бинарник и frontend с nginx.
