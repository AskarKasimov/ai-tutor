# Единый HTTP API

Контракт: [openapi.yaml](openapi.yaml), OpenAPI 3.1. Все пути относительны к `/api/v1`.

- `x-implementation: implemented` — подключённая операция: auth, предметы, voice, материалы и диагностика Geek, граф курса и health. Операции прежней модели удалены 16.10.2026 вместе с кодом.
- `x-implementation: planned` — проект до реализации; наличие planned-операции не означает наличие handler.

Материалы реализованы: `GET /admin/material-kinds`, загрузка `POST` и список `GET /admin/subjects/{subject_id}/materials`, правка недели/вида `PATCH .../materials/{material_id}`,
замена PDF `PUT .../materials/{material_id}/raw`, скачивание и удаление. Загрузка
принимает до 48 файлов; manifest `items` задаёт `client_id`, неделю и вид каждого
файла, а `results` связывает ответ с записью очереди. Старый multipart без manifest
сохраняет совместимость. Метаданные не запускают OCR; замена файла ставит новое
фоновое задание и отменяет устаревшие результаты предыдущего исходника.

Граф master: `GET /admin/subjects/{subject_id}/graph` возвращает snapshot со статусом,
сохранённым графом, `stale`, `inputs_ready` и `progress` идущей сборки (этап и шаги); `POST .../graph/build` запускает сборку.
Отдельный GET статуса по `/graph/build` не используется интерфейсом.
Диагностика реализована: `POST`/`GET /diagnostic-sessions`, чтение сессии,
`/{id}/answers`, `/{id}/result`, `/{id}/turns/{turn_id}/audio`. Ограничение «ровно одно
из `transcription_id`, `text`, `dont_know`» проверяет код: генератор не выражает `oneOf`.
Пакет для преподавателя остаётся planned: список диагностик курса и отчёт.

Внутренний API Python-сервиса course-graph — отдельный контракт [course-graph.yaml](course-graph.yaml): OCR, задание на сборку графа и его статус. Он не публикуется через Caddy.

Фикстура графа — [fixtures/course-graph.json](fixtures/course-graph.json): `Graph` по `course-graph.yaml`, 10 тем демокурса (поиск, недели 3 и 5–7) на русском. В ней есть цепочка пререквизитов глубиной 3, общие пререквизиты у тем верхнего уровня (`heuristic`, `uninformed-search`, `exploration-exploitation`), тема без связей (`agents-peas`) ОР заполнены только у `a-star`, основной вопрос заранее сгенерирован у всех вершин (`api prepare-questions`). Верхний уровень: `a-star`, `simulated-annealing`, `mcts`, `agents-peas`. Подходит для тестов экзамена, моков frontend и как запасной граф для показа.

Полная русская фикстура курса Introduction to AI — [fixtures/intro-to-ai.ru.graph.json](fixtures/intro-to-ai.ru.graph.json): 132 учебные темы и 20 диагностических групп, каждая сериализована как обычный `GraphNode`; порядок вершин топологический. Пять тем без учебного материала исключены. Направление 145 исходных учебных рёбер сохранено; у каждой диагностической группы её верховые темы указаны как `prerequisites`. В группах есть черновые комплексные вопросы. Это фикстура переведённого содержимого для интеграции с Geek, не новая версия OpenAPI-контракта.

Граф показа — [fixtures/intro-to-ai.weeks-1-2.ru.graph.json](fixtures/intro-to-ai.weeks-1-2.ru.graph.json): 16 тем недель 1–2 (лекции недель 1 и 2, туториалы недель 1 и 2) с ID, ОР и связями полного графа, без диагностических групп. Тексты — выдержки из PDF без меток источников; ссылка на пререквизит из другой недели (`AI-02-01`) убрана. Верхний уровень — 10 тем, самая длинная цепочка — AI-01-13 → AI-01-14 → AI-01-15 → AI-01-18. Основной вопрос задан у всех вершин. Используется по умолчанию (`BACKEND_GEEK_GRAPH_FIXTURE`), решение — в README от 17.10.2026.

Для экспертного просмотра граф выгружается в CSV: `api/fixtures/graph-json-to-csv.sh <граф>.json` (нужен `jq`) пишет `<граф>.csv` рядом с JSON — UTF-8 с BOM, колонки «Компетенция / тема», «Материал курса», «Образовательный результат», «Вопрос / критерий оценки» (вопросы и `assessment_guidance`), «Предварительные темы» (названия; «Нет» у тем верхнего уровня). Одна строка на ОР, тема без ОР — одной строкой с пустым результатом. Переформулировок в CSV нет: в файле графа их нет, Geek готовит их при старте api. [fixtures/intro-to-ai.weeks-1-2.ru.graph.csv](fixtures/intro-to-ai.weeks-1-2.ru.graph.csv) — выгрузка графа показа; файл сгенерирован, вручную не правится: после изменения JSON запустите скрипт заново.

Из `services/backend` контракт обновляется командой `bash scripts/generate-openapi.sh`. Генератор обновляет только операции, уже присутствующие в контракте, и сохраняет planned. Новую работающую ручку сначала явно добавьте в `openapi.yaml` со статусом `implemented`, затем запустите генератор. CI проверяет повторяемость генерации; контрактные тесты проверяют схемы и реальные ответы действующих операций. Swagger читает `api/openapi.yaml` через Compose.
