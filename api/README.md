# HTTP API по этапам разработки

Каждый файл — самостоятельный OpenAPI 3.1 с ручками, схемами, ошибками и примерами. Контракты **накопительные**: следующий этап включает предыдущий. Для разработки этапа достаточно его одного файла; внешних `$ref` нет. Контракты описывают планируемую систему, а не реализованные возможности текущих сервисов моделей.

## Группировка по модулям

Операции во всех контрактах сгруппированы тегами OpenAPI по пяти модулям. В ранних этапах показаны только модули, для которых уже предусмотрены ручки.

| Модуль | Ручки |
| --- | --- |
| Учебная база | В v0 — только `POST /admin/competency-map/import`: один CSV карты компетенций с ОР, заданиями и критериями, целиком заменяющий базу. Начиная с v1 — каталог `/courses*`, `/outcomes/{outcomeId}/tasks` и CRUD `/admin/*`. |
| Сессия | `/sessions*`: создание, история, состояние прохождения и переход к тренировке. |
| Грейдинг и фидбэк | `/tasks/{taskId}/answers`, `/answers/*`, `/assignments/{assignmentId}/answer`: приём учебного ответа, оценка, объяснение и повтор проверки. |
| Голос | `/voice/transcriptions` и `/voice/syntheses`: распознавание и синтез речи. |
| Auth | `/auth/*`: регистрация, вход, обновление токенов, выход и текущий пользователь. |

Итоговый фидбэк возвращается в составе сессии; это не требует отдельной ручки. Приём ответа на выданное задание относится к грейдингу и взаимодействует с модулем сессии. Теги обозначают функциональную ответственность, а не отдельные сетевые сервисы. Состав операций, URL, схемы и поведение сохранены.

## Учебная база v0

На первом этапе преподаватель/admin загружает **один CSV-файл карты компетенций** через
`POST /admin/competency-map/import`. Это не загрузка произвольного материала и не LLM-извлечение: сервер
детерминированно разбирает экспорт Excel или Google Sheets. Пустые ячейки объединённых полей `Ком`, `Сост` и
`ОР` наследуют значение из строки выше. Задания находятся справа парами колонок `Задание N` и `Критерии N`;
одна строка может содержать несколько заданий одного ОР. `Критерии N` — непрозрачный текстовый промпт: API его
не разбирает и не интерпретирует ни на одном этапе, а при оценивании передаёт LLM как есть. Ошибка любой строки
отменяет импорт целиком, поэтому предыдущая учебная база остаётся доступной. Просмотр и CRUD отдельных
сущностей появятся только в следующем контракте.

## Учебная модель

**ОР (образовательный результат) — это тема.** Отдельной сущности `Topic` нет. Связь: курс → составляющая РПД → ОР → несколько заданий. ОР могут образовывать дерево. Выбор темы использует `outcome_id`; список ОР доступен через `GET /courses/{courseId}/outcomes`, задания одного ОР — через `GET /outcomes/{outcomeId}/tasks`. Преподаватель управляет ОР через существующие ручки `/admin/constituents/{constituentId}/outcomes` и `/admin/outcomes/{outcomeId}`.

Для MVP семь основных заданий выбираются у одного выбранного ОР. Два базовых задания после ошибки относятся к указанным дочерним ОР; тренировка назначается по каждому неподтверждённому ОР.

## Поток запросов

1. **Голос:** `POST /voice/syntheses` с текстом → `200 audio/wav`. Запись ответа → `POST /voice/transcriptions` с multipart-полем `audio` → `200` с готовыми `id`, `text` и `created_at`. Пока запрос выполняется, интерфейс показывает обработку. Поллинг голоса не нужен.
2. **Один ответ:** выбор курса и ОР (темы) → `/outcomes/{outcomeId}/tasks` → распознавание записи → `POST /tasks/{taskId}/answers` с `transcription_id` → `/answers/{answerId}` с баллом и объяснением.
3. **MVP:** `POST /sessions` с `course_id` и `outcome_id` → ответ на `current_assignment_id` через `/assignments/{assignmentId}/answer` → чтение сессии и следующих заданий → диагностический итог → `POST /sessions/{sessionId}/training` → ответы и завершение.

`task` — запись в банке заданий; `assignment` — конкретное задание, выданное в учебной сессии. Распознавание отделено от учебного ответа: аудио загружается один раз, а оценивание получает `transcription_id` сохранённой сервером расшифровки. Студент видит текст, но не подтверждает и не редактирует его.

Тренировка содержит **два других неиспользованных задания на каждый неподтверждённый ОР**. Если банк не позволяет набрать нужное число, назначаются доступные задания и возвращается причина завершения `tasks_exhausted`. Диагностический балл остаётся неизменным.

При сбое или превышении времени ожидания голоса клиент повторяет исходный `POST`. Отдельных ручек чтения состояния, скачивания и повтора голоса нет. На этапе выпуска `Idempotency-Key` позволяет получить сохранённую расшифровку или те же WAV-байты после потери успешного ответа.

## Общие правила

- Даты — Unix timestamp в секундах (`integer/int64`); неизвестное время завершения — `null`.
- Авторизация — `Secure; HttpOnly; SameSite=Lax` cookies и HTTPS. Подробности: [авторизация](../documents/auth.md).
- Преподаватель/admin создаёт и редактирует записи через формы. Опубликованные данные используются по неизменяемой версии.
- Оценивание ответа и индексирование материалов возвращают `202`; клиент читает состояние отдельным `GET`. Распознавание и синтез возвращают готовый результат в `200`. Техническая ошибка не считается неправильным учебным ответом.
- Все студенческие ресурсы доступны только владельцу. Критерии и эталонные ответы не выдаются через студенческий каталог.
- На этапе выпуска клиент передаёт `Idempotency-Key` для безопасного повтора создающих запросов после потери ответа; поддержка заголовка описана в контракте этого этапа.

## Взаимодействие модулей

| Откуда → куда | Данные и ответственность |
| --- | --- |
| Интерфейс → общий HTTP API | Cookies, курс/ОР (тема), аудио, идентификаторы операций и ответов. |
| Голосовой модуль → GigaAM | Внутренний `POST /transcribe`: multipart-аудио → распознанный текст. |
| Голосовой модуль → VoxCPM2 | Внутренний `POST /synthesize`: JSON с текстом → WAV. |
| Модуль сессий → учебная база | Опубликованная версия, выбор и фиксация main/basic/training-заданий. |
| Модуль оценивания → учебная база и LLM | Расшифровка, снимок задания и рубрики, найденные фрагменты материалов → структурированная оценка. |
| Модуль оценивания → модуль сессий | Сохранённый вердикт и подтверждение ОР → атомарное назначение следующего шага. |

Учебная база, оценивание и сессии — логические модули общего API. Их отдельные сетевые сервисы этим планом не предписаны. Существующие HTTP API моделей остаются внутренними адаптерами и не совпадают с публичными ручками `/voice/*`.

Короткий endpoint GigaAM `/transcribe` ограничен записями до 25 секунд; общий контракт ограничивает размер 25 МиБ, но не длительность. Реализация backend v0 вызывает `/transcribe/longform`, который требует long-form зависимостей и VAD-весов на сервере моделей. VoxCPM2 принимает до 500 символов за запрос; такой же предел задан для публичного синтеза.

Сбор материалов, подготовка данных, тестирование со студентами и репетиция демо — задачи этапов без дополнительных HTTP-ручек. Полный сценарий: [диагностика и тренировка](../documents/voice-trainer-scenarios.md).

## Публичный адрес API

Контракты содержат пути от корня (`/auth/*`, `/voice/*`, `/admin/*`);
`servers.url: /api/v1` задаёт публичный префикс. Через Caddy клиент обращается
к `/api/v1/*`. Proxy удаляет `/api/v1` перед передачей в backend и переписывает
Path refresh-cookie с `/auth` на `/api/v1/auth`.
Публичная проверка доступности backend: `/api/v1/health`.
