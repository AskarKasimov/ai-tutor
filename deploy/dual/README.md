# Два режима на одном стенде

Стартовая страница с одним входом и двумя кнопками: «Обучение» — прежний поток диагностики, плана и тренировки из релиза v0.0.2.3 (v0.0.2 с паролем от 4 символов, возвратом к выбору режима и входом только через стартовую, ветка `legacy/v0.0.2`), «Симуляция экзамена» — Geek из свежего master (перед показом — из тега релиза). Релизы не объединяются: каждый запускается из своего git worktree со своей базой, S3 и сетью, а общий Caddy разводит их по имени хоста. Решение — в [README](../../README.md#решения-19102026-два-режима-на-одном-стенде).

| Адрес | Что |
| --- | --- |
| `https://<host>` | Стартовая: вход или регистрация сразу в обоих релизах; после входа — шапка с профилем и меню «Выйти», карточка «Выберите режим» |
| `https://learn.<host>` | v0.0.2.3; админ-панель — `/admin/competency-map` (импорт карты компетенций) |
| `https://exam.<host>` | master или тег релиза; админ-панель — `/admin` |

## Запуск

Нужны Docker Compose, git и openssl; mkcert — для доверенного сертификата. Скриптов два, с одинаковыми командами и переменными: `deploy/linux-dual.sh` — Linux и macOS, `deploy/windows-dual.ps1` — Windows PowerShell (openssl берётся из PATH или из Git for Windows).

```bash
deploy/linux-dual.sh up        # собрать и поднять, открыть стартовую и обе админки
deploy/linux-dual.sh status
deploy/linux-dual.sh logs learn   # learn | exam | front
deploy/linux-dual.sh down      # остановить; данные остаются
```

```powershell
.\deploy\windows-dual.ps1 up     # и status, logs learn, down
$env:DUAL_MODE = 'dev'; .\deploy\windows-dual.ps1 up   # переменные — через $env:
```

### Сброс данных

`deploy/linux-dual-reset.sh` (Windows: `.\deploy\windows-dual-reset.ps1`) останавливает стенд и безвозвратно удаляет volumes режима: базу, S3, состояние Caddy, у симуляции — ещё Redpanda и данные course-graph. Пользователи, курсы, карты и диагностики пропадают; `.env` и worktree остаются. Перед удалением скрипт показывает список и просит ввести `yes`. Модели course-graph (`course_graph_models`, долго качаются) и сертификаты стартовой (`tutor-dual_*`) остаются, если не задать `DUAL_RESET_MODELS=true` или `DUAL_RESET_TLS=true`. Основной стенд (`ai-tutor_*`) не затрагивается. Затем — обычный `up`.

```bash
deploy/linux-dual-reset.sh           # оба режима; learn | exam — один
deploy/linux-dual-reset.sh learn --yes   # без подтверждения
```

```powershell
.\deploy\windows-dual-reset.ps1 exam   # и all, --yes
```

curl на Windows не проверяет отзыв сертификата mkcert — для проверки из консоли нужен `--ssl-no-revoke`, браузеру это не мешает.

Локально `<host>` — `127-0-0-1.sslip.io` (резолвится в 127.0.0.1, нужен интернет для DNS). На ВМ:

```bash
DUAL_HOST=10-100-1-2.sslip.io DUAL_HTTPS_BIND=0.0.0.0 deploy/linux-dual.sh up
```

Без mkcert сертификат выпускает внутренний CA Caddy — браузер один раз предупредит на каждом из трёх адресов. Микрофон работает только по HTTPS, поэтому предупреждение нужно принять.

| Переменная | По умолчанию | |
| --- | --- | --- |
| `DUAL_HOST` | `127-0-0-1.sslip.io` | Базовое имя; поддомены `learn.` и `exam.` |
| `DUAL_HTTPS_BIND` / `DUAL_HTTPS_PORT` | `127.0.0.1` / `443` | Где слушает общий Caddy |
| `DUAL_MODE` | `prod` | `prod` — собранный frontend на nginx и бинарник backend; `dev` — Vite и Air, как `dev.sh`: правки видны сразу, но тяжелее и медленнее |
| `DUAL_LEARN_REF` / `DUAL_EXAM_REF` | `v0.0.2.3` / `master` | Версии: ветка — свежая с origin при каждом `up`, тег — фиксированная |
| `DUAL_WORKTREES` | каталог над репозиторием | Где лежат `ai-tutor-learn` и `ai-tutor-exam` |
| `DUAL_OPEN_BROWSER` | `true` | `false` — не открывать браузер |

## Перед показом

Симуляция по умолчанию идёт со свежего master. Перед показом выпустите релиз (например, `v0.0.4`), поменяйте значение по умолчанию `DUAL_EXAM_REF` (`master`) на тег в обоих скриптах и запустите `up`: worktree переключится сам, данные и миграции сохранятся, обучение останется на `v0.0.2.3`. Разово — `DUAL_EXAM_REF=v0.0.4 deploy/linux-dual.sh up` или `$env:DUAL_EXAM_REF = 'v0.0.4'` перед `windows-dual.ps1 up`.

## Как устроено

- `up` делает `git fetch`, создаёт worktree `ai-tutor-learn` и `ai-tutor-exam` и переключает их на нужную версию; worktree с незакоммиченными правками отслеживаемых файлов не переключается — ошибка. При первом запуске — `.env` из шаблона релиза со случайными секретами и настройками STT/TTS из `.env` основного checkout, для v0.0.3 — `config.json` gateway из основного checkout. Проверьте `.env` релизов, если модели или голос отличаются. `.env` не обновляется при смене версии: новые переменные добавьте вручную по `.env.example` этой версии.
- В релизах имена сети и volumes зашиты (`ai-tutor_*`), поэтому скрипт пишет в каждый worktree `compose.dual.yaml`: сеть `tutor-<релиз>`, volumes `tutor-<релиз>_*`, свои порты на 127.0.0.1 (learn: БД 5442, API 8012, S3 9010, Caddy 8444; exam: 5443, 8013, 9011, 8445) и в `prod` — финальную стадию Dockerfile без исходников. Данные основного стенда (`ai-tutor_*`) не затрагиваются; одновременно с `dev.sh` стенд работает, если у того свободны порты 3000, 8005, 8010 и 19092 (Grafana, course-graph, gateway, Redpanda).
- Общий Caddy (`docker-compose.yaml`, проект `tutor-dual`) подключён к обеим сетям и проксирует на Caddy релиза, который по-прежнему разводит API, админку и gateway.
- Вход: стартовая отправляет email и пароль в оба релиза (`fetch` с cookies). CORS открыт только для `/api/v1/auth/*` и только для origin стартовой. Cookies `SameSite=Lax`, поэтому все три адреса должны быть одним сайтом: sslip.io не входит в Public Suffix List, а `*.localhost` — разные сайты для Chrome и не подходят. Вход создаёт недостающий аккаунт во втором релизе с тем же паролем. Пароль — от 4 символов в обоих релизах. Сменённый внутри одного релиза пароль во втором не меняется; роль admin назначается в каждой базе отдельно.

## Ограничения

- Курсы, пользователи и данные у релизов раздельные: v0.0.2.3 строит обучение по карте компетенций, v0.0.3 — по графу.
- v0.0.2.3 вызывает модели напрямую (`BACKEND_TUTOR_*`, `BACKEND_TASKGEN_*`, `BACKEND_ASSESSMENT_*`), а не через LLM gateway — осознанное исключение только для этого релиза.
- Возврат из режима — пункт «К выбору режима» в меню профиля. Своей страницы входа у режимов нет: без сессии, в том числе после «Выйти», режим уводит на стартовую с `?logout` — она выходит из обоих. Регистрация и вход — только на стартовой, поэтому аккаунт (email, пароль, имя) у режимов общий. Оба пункта включает `VITE_MODE_SELECT_URL`, который скрипт стенда пишет в `.env` релизов (адрес стартовой); есть в v0.0.2.3 и в master после 19.10.2026 (в v0.0.2.2 — без перехода на стартовую при отсутствии сессии), в более старых версиях — нет.
- Обе версии вместе занимают около 3–4 ГБ памяти в `prod` (Redpanda и course-graph — около 2 ГБ).
