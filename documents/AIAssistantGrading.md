# Оценивание голосового ответа

> Новое видение от 15.10.2026 — [видение Geek и course-graph](../README.md): устный экзамен Geek по графу курса из материалов. Документ описывает прежнюю модель «карта компетенций → вариант», которую реализует текущий код; новые решения сюда не вносятся.

Правила оценивания обновлены 14 октября 2026. `POST /assessments/evaluate` принимает сохранённую расшифровку и variant ID/позицию; assessment загружает исторический снимок с проверкой владельца, строит контекст и вызывает соответствующий grader. `diagnostic` использует тот же application service напрямую, без HTTP loopback, и сохраняет принятую оценку в PostgreSQL.

## Контракт assessment

`POST /assessments/evaluate` принимает `transcription_id`, `variant_id` и `variant_task_id`; ответ содержит `score`, `max_score`, `verdict`, `criterion_results` и три строки `feedback`. Шкала задаётся ролью снимка: main 0/1/3, basic 0/1, training 0/1/2. Результат проверяется, но сам assessment-модуль его не сохраняет.

Для main: 3 — полностью верный ответ и требуемое объяснение; 1 — частичное понимание с ошибкой или пробелом; 0 — неверный ответ или отсутствие понимания. Если голосовая инструкция требует назвать вариант и объяснить выбор, prompt требует назвать вариант словами; одного номера недостаточно. Feedback — три связанных коротких предложения: наблюдение по ответу, главное уточнение и конкретный следующий шаг. В промпте целевая длина — до 180 символов суммарно, без искусственного увеличения. Если модель превышает 228 символов, backend сокращает фидбэк до этого лимита, не отклоняя корректную оценку из-за длины. По решению встречи 10.10.2026 ([план](ai-journey-plan.md)) после ответа студенту не показываются ни балл, ни вердикт — это реализовано. Оценка, вердикт и feedback каждого задания видны только в разборе ответов на экране итога; criterion_results остаются в API и не отображаются. Сбой модели возвращается ошибкой API.

## Интеграция с сохранённым вариантом

Промпт содержит одну последовательность правил оценки и краткий контракт JSON. Для модели остаются `reasoning_effort=medium` и `temperature=0`. Бюджет `max_tokens=4096` общий для рассуждений и итогового JSON; это потолок, а не требование использовать все токены. Цель в 180 символов относится только к фидбэку. Ответ с `finish_reason=length` по-прежнему отклоняется как неполный, без подмены учебной оценки.

Variantgen сохраняет вопрос, варианты, инструкцию, эталон (четвёртый блок ячейки задания, см. [формат](markdown-content.md)), criteria при наличии и профиль ОР с ОС. Серверный `variant.TaskReader` возвращает полный снимок по ownerID/variantID/variantTaskID и проверяет принадлежность. Публичный HTTP DTO скрывает эталон, criteria, ОС и сырой JSON снимка.

Позиция варианта имеет собственный устойчивый ID и роль main/basic. Сессия передаёт grader-модулю variant ID и `variant_task_id`; он получает исходный `task_id` и контекст из снимка. Сессия хранит позицию, исходное задание, транскрипцию, grader score/max_score, оценку и ответный feedback. Публичное API не выдаёт эталон и criteria.

Публичный контракт сессии: `POST /diagnostic-sessions`, `GET /diagnostic-sessions/{id}`, `GET /diagnostic-sessions/{id}/current/audio`, `POST /diagnostic-sessions/{id}/current/audio/regenerate`, `POST /diagnostic-sessions/{id}/answers`, `POST /diagnostic-sessions/{id}/skip`, `GET /diagnostic-sessions/{id}/result`; схемы и ответы ошибок находятся в едином [OpenAPI](../api/openapi.yaml). `variantgen` по-прежнему не принимает ответы и не управляет фазами прохождения.

## Итоговый фидбэк диагностики

Модуль `diagnosticfeedback` читает результат завершённой сессии и предоставляет `GET /diagnostic-sessions/{id}/feedback`. Освоенные проверенные ОР, пробелы и советы собираются детерминированно из сохранённых разборов ответов; модель пишет только общий абзац строго по ним. Фидбэк строится при первом запросе и хранится в PostgreSQL (`diagnostic_feedback`, миграция 00009). Frontend показывает карточки «Что хорошо» (освоенные проверенные ОР, пустая скрывается) и «Что доработать» (сгруппировано по составляющим: «Изучите тему» — полный пробел составляющей, «Повторите тему» — частичный пробел, отдельно — пропущенные вопросы). Отдельный `POST /assessments/overall-feedback` синтезирует фидбэк по переданному списку заданий; текущий UI его не вызывает. По решению встречи 10.10.2026 итог показывается без балла и пометки «Не проверено»: «Не проверено» убрано, но диагностический балл в итоге пока показывается. После итога — план обучения модуля `learning`.

## Учебные правила продукта

Основной оценивается в 0/1/3, базовый — в 0/1 по `max_score` контекста. Диагностическая сумма учитывает основные и предъявленные базовые. Максимум — 3 балла на компетенцию: 3 за сразу верный основной ответ (базовые пропускаются), либо 1 за частичный основной и до 2 за базовые. Пропуск задания (`/skip`) сохраняется как ответ с оценкой 0. Тренировочная шкала остаётся 0/1/2. Непроверенные ОР не считаются пробелами. Тренировка и план обучения не меняют исходную диагностику; ответы плана обучения проверяет наставник (верно/неверно), без баллов.
