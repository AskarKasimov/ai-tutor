# Оценивание голосового ответа

Состояние: 7 октября 2026. `POST /assessments/evaluate` остаётся действующим прототипом. Отдельный backend-модуль `diagnostic` реализует учебную сессию и сохраняет structured evaluation в памяти процесса. В mock он использует демонстрационный grader; в real режиме интеграция PR #10 ждёт context provider для снимков заданий варианта.

## Действующий прототип

`POST /assessments/evaluate` принимает transcription_id владельца, вопрос, варианты, голосовую инструкцию и необязательный эталон. LLM возвращает целый score 0…2 и ровно три строки feedback. Результат проверяется, но не сохраняется и не управляет прохождением. Ручка используется frontend и сохраняется.

2 — полностью верный ответ и требуемое объяснение; 1 — частичное понимание с ошибкой или пробелом; 0 — неверный ответ или отсутствие понимания. Если голосовая инструкция требует назвать вариант и объяснить выбор, prompt требует назвать вариант словами; одного номера недостаточно. Feedback содержит вердикт, причину и совет. Сбой модели возвращается ошибкой API.

## Интеграция с сохранённым вариантом

Variantgen сохраняет вопрос, варианты, инструкцию, эталон из `Ответ:`, criteria при наличии и профиль ОР с ОС. Серверный `variant.TaskReader` возвращает полный снимок по ownerID/variantID/variantTaskID и проверяет принадлежность. Публичный HTTP DTO скрывает эталон, criteria, ОС и сырой JSON снимка.

Позиция варианта имеет собственный устойчивый ID и роль main/basic. Сессия хранит `variant_task_id`, исходный `task_id`, снимок задания, транскрипцию, grader score, оценку сессии и ответный feedback. Публичное API не выдаёт эталон и criteria. Real grader пока не получает контекст из снимка, поэтому ошибка интеграции не становится нулевой оценкой.

Публичный контракт сессии: `POST /diagnostic-sessions`, `GET /diagnostic-sessions/{id}`, `GET /diagnostic-sessions/{id}/current/audio`, `POST /diagnostic-sessions/{id}/answers`, `GET /diagnostic-sessions/{id}/result`; схемы и ответы ошибок находятся в едином [OpenAPI](../api/openapi.yaml). `variantgen` по-прежнему не принимает ответы и не управляет фазами прохождения.

## Итоговый фидбэк диагностики

Отдельного модуля или API итогового фидбэка нет. Результат завершённой сессии агрегирует сумму по main, проверенные ответы, непредъявленные basic и пропущенные компетенции; итоговый текст не генерируется. Будущий feedback/training сервис сможет читать структурированный результат из session API, пока backend-процесс жив.

## Учебные правила продукта

Основной оценивается в 0/1/2, базовый — в 0/1. Диагностическая сумма учитывает только основные; базовые уточняют пробелы. Непроверенные ОР не считаются пробелами. Тренировка реализуется отдельно и не меняет исходную диагностику. Эти правила не являются поведением текущей прототипной ручки для базовых.
