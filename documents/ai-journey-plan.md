# Решения встречи 10.10.2026: сценарий для AI Journey

Статус: согласовано 10 октября 2026, в коде реализовано частично (см. таблицу ниже). Документ задаёт целевой пользовательский сценарий для демонстрации на AI Journey. Пока код не изменён, текущее поведение описывают [README](../README.md), [сценарий тренажёра](voice-trainer-scenarios.md) и [OpenAPI](../api/openapi.yaml). При расхождении целевого сценария с реализацией изменения вносятся в код, контракт и документы вместе.

## Принципы

- **Без «внутрянки».** Студент и демонстрация не видят загрузку карты компетенций. Карту будут генерировать отдельные процессы; импорт остаётся служебной операцией backend и администратора, но в демо-сценарии не показывается.
- **Один процесс.** Для пользователя нет двух разных процессов «диагностика» и «тренировка»: это один путь — проверка, план, тренировка. На backend модули `diagnostic` и `training` пока остаются раздельными; объединение выполняется в пользовательском сценарии.
- **Голос везде.** Студент отвечает голосом на все задания, включая multiple choice: вариант называется словами и объясняется. Возвращается кнопка с микрофоном.
- **Голос наставника.** TTS-голос — мужской, взрослый, низкий (визуальный и звуковой образ наставника).
- **Без оценок в процессе.** После ответа на вопрос результат не показывается: студента быстро проводят по вопросам, итог сообщается в конце.
- **Положительное закрепление.** Сначала отображается большее количество заданий, затем выполненные «схлопываются». Конкретный UX отображения заданий предлагает Марина.
- **Прогресс.** Пока — status bar в процентах.

## Целевой сценарий

1. Студент выбирает предмет и начинает. Отдельного выбора «Диагностика / Тренировка» нет.
2. **Проверка (диагностика).** Задания берутся из ОР с флагом TRUE; на компетенцию — одно основное и два базовых. При сравнении ОР для выбора основного таксономия (ранг Блума) важнее важности ОР. Ответы голосовые, без показа балла и вердикта после каждого вопроса; прогресс — процентами.
3. **Итог проверки.** Показывается общий фидбэк: в каких компетенциях всё хорошо и какие темы не освоены, с указанием образовательного результата (ОР). Балл и пометка «Не проверено» из итога убираются.
4. **Время на обучение.** По запросу заказчика 11.10.2026 после итога задаётся вопрос «Сколько у тебя часов?» (1 / 3 / 5 / 10+); от ответа зависят состав плана и подробность теории.
5. **План.** Все ОР компетенций, где основное набрало 0 или 1; важные — первыми, пока хватает часов, остальные — «если останется время». В карте два необязательных столбца «Время на теорию» и «Время на практику» (минуты, по умолчанию 15 + 15).
6. **Обучение.** Слева оглавление, справа чат: наставник генерирует теорию и вопрос на закрепление по ОР, студент отвечает голосом. Верно — следующий ОР; неверно — разбор ответа и новый вопрос; после трёх попыток ОР помечается «надо повторить». Сверху прогресс в процентах.

## Влияние на текущую реализацию

| Область | Сейчас | Целевое изменение |
| --- | --- | --- |
| Главная | Реализовано: карточка курса с одной кнопкой «Начать/Продолжить обучение», которая ведёт туда, где студент остановился, и четырьмя шагами «Пройдите проверку → Найдите пробелы → Получите план → Подготовьтесь по плану»; плитки тренировки нет. | Тренировка открывается автоматически после итога проверки (пока — кнопкой в итоге). |
| Ответ на задание | Реализовано: в диагностике и тренировке после ответа только «Ответ принят»/«Вопрос пропущен» и кнопка «Следующее задание» на месте записи; навигатор не окрашивает по баллу. Оценки сохраняются на backend. | — |
| Итог диагностики | Сумма основных и предъявленных базовых, разбор заданий. Общий фидбэк хранится после первой генерации: модель пишет общий абзац и тексты карточек «Что хорошо» (только полностью выполненные проверенные результаты, пустая скрывается) и «Что доработать» (по пункту на тему: что повторить в общем виде, по результатам темы и знаниям из карты). Баллы и состав пробелов определяются кодом; пропущенный или «командный» текст модели после одного повтора заменяется запасным текстом по теме, версия анализа 6 обновляет прежние тексты при следующем запросе. «Не проверено» убрано: ни непроверенных компетенций в общем фидбэке, ни непредъявленных базовых и не включённых в вариант компетенций в разборе (backend их по-прежнему возвращает). | Без балла и «Не проверено»; список освоенных компетенций и неосвоенных тем с ОР. |
| План обучения | Реализовано: вопрос о часах, план «компетенция → ОР» с временем на теорию и практику, уроки с генерацией теории и практики, голосовые ответы, статусы «пройдено» и «надо повторить». Прежний UI тренировки удалён; backend-модуль `training` сохранён. | Правила теории и практики уточняются (Марина). |
| Прогресс | Реализовано в диагностике: полоса прогресса в процентах под шапкой вместо навигатора; компетенция весит 1/N, слабое основное и каждый базовый — по трети доли, процент не уменьшается. В плане обучения — прогресс в процентах сверху и оглавление слева. | — |
| Голос | Озвучивается сохранённая голосовая инструкция через VoxCPM (`BACKEND_TTS_SEED`, `CFG_VALUE`, `INFERENCE_TIMESTEPS`; VoxCPM автоматически кэширует референс для seed/CFG/шагов, по умолчанию `use_reference=true`). Браузерный синтез отключён; пока WAV готовится, кнопка показывает загрузку, клиент проверяет статус раз в секунду. | Мужской басистый голос в сохранённой озвучке. Уже сохранённые WAV сохраняют прежнее звучание, а worker копирует готовый WAV с тем же текстом инструкции, поэтому смена голоса требует отдельной переозвучки. |
| Выбор основного ОР | Реализовано (`competency-map-v4`): наибольший ранг Блума, при равенстве — большая важность; базовые — два самых простых из остальных TRUE-ОР; свободная тренировка без FALSE. | — |
| Админка | Учитель импортирует карту через `/admin/competency-map`. | В демо-сценарии не показывается. |

Правила оценивания после обновления 14.10.2026: основной оценивается в 0/1/3, базовый — в 0/1, диагностическая сумма считается по основным и предъявленным базовым (максимум 3 балла на компетенцию), непроверенные ОР не объявляются пробелами, техническая ошибка не считается учебным нулём, тренировка не меняет исходную диагностику. Меняется только то, что показывается студенту.
