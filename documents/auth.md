# Авторизация

Контракт — [единый OpenAPI](../api/openapi.yaml). Описанные auth-операции реализованы.

## Запросы

| Путь | Результат |
| --- | --- |
| `POST /auth/register` | email, password, optional display_name → 201, пользователь, сроки и cookies. |
| `POST /auth/login` | email, password → 200, пользователь, сроки и cookies. |
| `POST /auth/refresh` | Refresh-cookie → 200, новые cookies и сроки. |
| `POST /auth/logout` | Необязательная refresh-cookie → 204, отзыв сессии и удаление cookies. |
| `GET /auth/me` | Access-cookie → текущий пользователь. |

Публичный префикс `/api/v1` удаляет Caddy. `/health` доступен без авторизации. Register/login публичные; refresh требует refresh-cookie; остальные учебные операции требуют access-cookie.

## Токены

Access/refresh — непрозрачные строки, значения только в двух отдельных `Set-Cookie`, не в JSON. Атрибуты: `Path=/; Secure; HttpOnly; SameSite=Lax`, без Domain. Frontend и API работают на одном HTTPS origin; браузер отправляет cookies.

Access действует до 15 минут и не дольше auth-сессии. Auth-сессия действует 30 суток от входа/регистрации; refresh этот срок не продлевает. Сроки в JSON — Unix seconds. Refresh одноразовый: успешная ротация заменяет его, повтор старого отзывает всю сессию. Потеря ответа ротации может потребовать нового входа.

Logout отзывает токены одного входа и удаляет обе cookies. Повтор, отсутствующая или неизвестная cookie возвращает 204. Другие входы пользователя сохраняются. Пароли хранятся Argon2id, токены — в виде SHA-256. Auth-ответы используют Cache-Control: no-store.

## Пользователи

Регистрация выдаёт student и сразу создаёт сессию. Public request не принимает role. Admin назначается SQL и получает право импорта карты; роль перечитывается со следующего запроса. Публичных CRUD курсов нет.

Email обрезается по краям и приводится к нижнему регистру. Пароль регистрации: 15–128 символов, Unicode/пробелы допускаются; проверяется локальный список простых комбинаций, внешней проверки утечек нет. Неверный email/пароль входа — одинаковый 401; занятый email — 409; неверные поля — 422. Подтверждения email, сброса пароля и MFA сейчас нет.

В планируемом API варианты принадлежат пользователю из auth principal. Чтение задания проверяет ownerID, variantID и variantTaskID; чужие или несогласованные ID возвращают 404. Приём ответов и учебные сессии реализуются отдельно. Auth-сессия и учебная сессия — разные сущности.
