# Архитектура backend

Дата: 7 октября 2026. Код находится в `services/backend`, Go-модуль — `github.com/AskarKasimov/ai-tutor/services/backend`.

## Реализованные части

| Путь | Ответственность |
| --- | --- |
| `cmd/api` | Запуск, миграции, healthcheck, shutdown. |
| `internal/app` | Конфигурация, зависимости, router, auth middleware и HTTP logging. |
| `features/auth` | Регистрация/вход, refresh/logout/me, PostgreSQL и Argon2id. |
| `features/voice` | STT/TTS, проверка входа, сохранение расшифровки владельца. |
| `features/competency` | CSV/XLSX парсер, атомарная замена карты, чтение дерева. |
| `features/taskbank` | SQL-каталог и профиль задания без эталона. |
| `features/assessment` | Синхронная прототипная оценка, результат не сохраняется. |
| `features/taskgen` | Генерация новых заданий, сохранение контекста, импорт материалов. |
| `features/variantgen` | Отбор ОР и аналогов, сохранение снимков, список и чтение вариантов. |
| `entities` | Пользователь, auth-сессия, карта, аудио, расшифровка, вариант и снимки профилей. |
| `shared` | Fault, security, HTTP helpers, миграции/SQLC. |

Каждый feature содержит `application`, `infrastructure`, `transport/http`. Application определяет сценарии и порты; инфраструктура реализует порты; HTTP переводит запросы/ответы. `app` связывает зависимости. Сценарии и entities не импортируют HTTP, pgx или собственные адаптеры. Features не импортируют сценарии друг друга; общие доменные типы находятся в entities.

Авторизация выполняется middleware: auth возвращает principal, HTTP handler передаёт его сценарию. Импорт карты/материалов повторно проверяет admin внутри application. `shared` не содержит учебных правил и не зависит от features/entities.

## Учебные данные

Карта: компетенция → составляющая → ОР → задания. Источник — текущий ML CSV/XLSX; старый парный формат поддержан кодом. ОС 1:1 с ОР. Задания хранят отдельные вопрос, варианты, инструкцию и эталон. Импорт выдаёт новую ревизию и ID и заменяет активную карту одной транзакцией.

Таблицы учебных сессий/выдач/ответов существуют как заготовки, HTTP-сценариев нет. Отдельные variants/variant_tasks со снимками добавлены миграцией 00002. `entities/session` относится к авторизации. Схема и импорт — [backend README](../services/backend/README.md#бд-и-импорт); наблюдения перед реализацией диагностики — [PLAN.md](../PLAN.md).

## Variantgen

Модуль `internal/features/variantgen` собирает вариант из текущей карты. Первичный фильтр требует три разных готовых TRUE-ОР. Основной выбирается по сумме ранга Блума и важности; для двух базовых также нужны ОР с меньшим рангом Блума. Недостаточные компетенции пропускаются с причиной. Ручных prerequisite-связей, утверждённых групп заданий и дополнительных документов нет.

Application выполняет детерминированный отбор ОР, используя chooser только для случайного выбора задачи того же ОР. Repository читает активную ревизию и атомарно сохраняет снимки в PostgreSQL. HTTP предоставляет создание, список, чтение варианта и отдельной позиции. Вариант не содержит seed, ответов студента, оценки или фазы прохождения. Доменный `variant.TaskReader` предоставляет грейдингу полный исторический снимок с проверкой владельца; публичные DTO скрывают эталон/criteria/ОС. Taskgen сохраняется без изменений. Правила отбора — [алгоритм](Алгоритм_составления_варианта.md), HTTP-доступ — [OpenAPI](../api/openapi.yaml).

## API и модели

Единственный контракт — [api/openapi.yaml](../api/openapi.yaml). `x-implementation` отличает работающие операции от планируемых; наличие planned в Swagger не означает наличие handler. Этапных контрактов больше нет.

Frontend вызывает общий HTTPS API `/api/v1`; Caddy удаляет префикс. STT/TTS/LLM вызываются backend через HTTP-адаптеры; настройки моделей находятся только на сервере. `/health` проверяет backend/БД, не модели.

Действующие конфигурация и маршруты taskgen/assessment сохраняются; их замена не входит в scope variantgen. Перенос старых данных разработки не требуется; новые варианты и выбранные задания должны сохраняться после restart/reimport.
