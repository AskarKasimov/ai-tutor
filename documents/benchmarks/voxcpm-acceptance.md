# Проверка скорости и качества VoxCPM2

Набор `voxcpm-cases.json` содержит 30 синтетических русских реплик без персональных данных: по 10 коротких, средних и длинных. Это технический набор для озвучки, не учебное содержание продукта. SHA-256 каждого текста позволяет воспроизвести одинаковую нагрузку. Порог выпуска задаёт [спецификация](../voxcpm-performance-spec.md).

## Подготовка

На одном CUDA-сервере сохранить неизменный референс рабочего голоса, его SHA-256, ревизию весов, torch/CUDA/driver, устройство, лимиты RAM/VRAM и настройки. Не сравнивать разные голоса: прежний автоматический референс зависел от числа шагов. Задать `VOXCPM_REFERENCE_WAV` на сохранённый WAV. Не удалять volume и старые WAV/S3-объекты. Отсутствующий явно заданный WAV должен блокировать readiness.

Создать вне Git файл окружения для каждого варианта, например:

```json
{
  "device": "<GPU model and VRAM>",
  "model_revision": "<immutable weights revision>",
  "reference_sha256": "<sha256 of the pinned WAV>",
  "torch_version": "<actual version>",
  "cuda_driver": "<actual runtime and driver>",
  "container_limits": "<RAM/CPU/GPU limits>",
  "optimize": "off",
  "reference_cache_size": 0
}
```

Инструмент использует только Python standard library; обращается к указанному TTS URL, не загружает веса и не управляет deployment. Используйте новый каталог результатов при каждом запуске; он содержит JSONL измерений и WAV для прослушивания и не должен коммититься целиком.

## Матрица

Сначала снять холодный старт с уже скачанными весами и длительность readiness по логам сервиса. Затем для каждой конфигурации дождаться `/ready` и выполнить прогрев и три прохода набора. При компиляции прогрев обязателен; его время не включается в steady-state.

| Метка | Optimize | Cache size | Steps | Режим |
| --- | --- | --- | --- | --- |
| baseline | off | 0 | 20 | wav |
| compile | on | 0 | 20 | wav |
| cache | off | 4 | 20 | wav |
| steps10 | off | 0 | 10 | wav |
| combined20 | on | 4 | 20 | wav и stream отдельно |
| combined10 | on | 4 | 10 | wav и stream отдельно |

Пример запуска из корня `ai-tutor` (URL и путь окружения заменить своими):

```bash
python3 scripts/benchmark_voxcpm.py \
  --url http://127.0.0.1:8001/synthesize \
  --label baseline --mode wav --steps 20 --runs 3 --warmup 1 \
  --environment /tmp/voxcpm-baseline-env.json \
  --output /tmp/voxcpm-baseline-results
```

Для потокового варианта использовать `--mode stream`; инструмент добавляет `/stream` к `/synthesize`. Каждое измерение включает длительность выходного WAV: обрезанное аудио нельзя засчитывать как ускорение. `first_pcm_seconds` — приход PCM HTTP-клиенту, не первый слышимый звук браузера. `client_rtf` включает транспорт и не заменяет модельный RTF по метрикам сервиса. В summary нет значений TTFA для WAV, поскольку полный файл не доказывает момент начала проигрывания.

Отдельно проверить два конкурирующих запроса и S3 hit/miss через авторизованный backend: один вариант запуска инструмента напрямую к TTS не измеряет очередь warmer/backend и не проверяет права владельца.

## Браузер и proxy

Локальный smoke действующего Caddyfile без настоящих моделей:

```bash
RUN_CADDY_SMOKE=1 python3 -m unittest discover -s scripts/tests
```

Тест использует уже имеющийся образ `caddy:2-alpine`, временный сертификат и изолированный контейнер с портом только на loopback. Он не трогает текущие сервисы, не скачивает образ и удаляет тестовый контейнер. Проверяет ранний PCM, отсутствие Content-Length/сжатия, снятие `/api/v1` и передачу disconnect upstream. Намеренно не выставляет `flush_interval -1`: этот режим Caddy может сохранять upstream-запрос после отключения клиента; неизвестная длина ответа уже обеспечивает немедленный flush. См. [официальное описание streaming в Caddy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#streaming).

В фактических целевых Chrome, Firefox и Safari записать версии и проверить:

- реплика >100 символов: первый звук до готовности всей части, TTFA от нажатия до первого AudioContext output, underrun;
- короткая реплика <200 мс доигрывается; частота устройства, отличающаяся от частоты модели, не меняет скорость/высоту;
- reply → question, повтор, смена реплики, stop, начало записи и уход со страницы;
- запрет autoplay, отсутствие streaming API, отключённый backend (406), старый provider (404/501);
- ошибка после первого аудио не запускает автоматический повтор и не сохраняет частичный результат;
- медленный клиент не удерживает модель после лимита drain, два слушателя не создают второй синтез.

Автоматическая проверка AudioWorklet в Chromium с синтетическим PCM полезна, но не подтверждает произношение, слышимость на устройстве пользователя и работу Safari/Firefox.

## Прослушивание и решение о выпуске

Два русскоязычных слушателя независимо сравнивают слепые пары 20/10 на одном референсе. Записать для каждой реплики полноту, числа/термины, тембр, артефакты, интонацию и последнее слово. Известное прежнее решение проекта от 17.10.2026: 20 шагов сохраняли паузу/интонацию вопроса, на 10–15 она терялась. Поэтому текстовая STT-проверка сама по себе не разрешает новый default 10.

Шаблон итогового отчёта:

| Проверка | Результат / артефакт | Допуск |
| --- | --- | --- |
| SHA обоих репозиториев, окружение и референс | Заполнить после запуска | Обязательно |
| Холодный старт, compile и прогрев | Логи отдельно от steady-state | Обязательно |
| Generation p50: combined против baseline | Не менее 20% улучшения | Не измерено |
| Полное время p95 | Не хуже baseline более чем на 5% | Не измерено |
| Browser TTFA p50, реплики >100 символов | Не менее 30% улучшения | Не измерено |
| Длительность WAV, ошибки, retries, RAM/VRAM | Без потерь текста/голоса; лимиты выдержаны | Не измерено |
| Слепое прослушивание двумя людьми | Без новых пропусков, повторов и смены голоса | Не выполнено |
| Chrome / Firefox / Safari | Версии, сценарии и результаты | Заполнить |
| Откат | Streaming false, steps20, optimize off; readiness после прогрева | Заполнить |

Без этих результатов значения по умолчанию остаются безопасными: 20 шагов, optimize off, streaming false. Готовность кода и тесты на fake-модели не являются доказательством ускорения CUDA или качества русского голоса.
