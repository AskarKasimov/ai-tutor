# Надёжная обработка материалов и сборка графа курса

Дата: 17.10.2026. Ветка: `optimized_Michael`. Спецификация подготовлена по чтению текущих исходников и работающих контейнеров. Существующие незакоммиченные изменения сохраняются. Разрешённая область реализации: загрузка → OCR → перевод → очистка/темы → связи/иерархия → граф в `/admin`; изменения не означают готовность всей диагностики Geek.

## Цель и ограничения

Пять уже загруженных PDF должны обработаться без повторной загрузки и дать доступный граф с проверяемыми источниками. Длительная полезная работа разрешена: длительность сама по себе не является ошибкой. Не вводить короткий общий deadline и не подменять полное OCR извлечением pypdf ради зелёного статуса. Сохранять распознавание формул, кода и изображений; помечать реальную неполноту. Частичный перевод допустим с предупреждением и сохранением исходного текста.

Не удалять модули, экраны, таблицы, исходники S3 или данные PostgreSQL. Не выполнять `down -v`, переимпорт курса или пересоздание загруженных материалов. Новые изменения схемы — следующей миграцией, SQLC — из запросов. Перед правкой frontend прочитать его AGENTS.md. HTTP DTO согласовать с единым OpenAPI и генератором контракта. Текущие изменения других задач не откатывать.

## Найденные дефекты и приоритеты

### P0. Холодная загрузка весов скрыта внутри пользовательского OCR

`get_converter()` и инициализация pipeline скачивают модели в первом запросе; access log появится только после ответа. Admin не отличает скачивание модели от OCR страниц или простоя. Повторные jobs могут снова ждать ту же инициализацию.

Реализация:

- Ввести явный управляемый bootstrap/preload требуемых моделей с тем же persistent HF cache. Команда подготовки должна иметь понятный результат: какие модели/ревизии готовы, какие нет. Не выполнять повторную загрузку весов на каждый material. Проверить наличие cache mount в обоих Compose.
- HTTP liveness оставить быстрым; readiness моделей показывать отдельно. При загрузке логировать `model_download_started/progress/completed/failed`, имя модели, bytes где доступны, elapsed, retry, transport. Не выдавать access token, полный remote URL, содержимое лекции.
- Перед изменением транспортного режима выполнить ограниченную проверку direct HTTP против XET: HEAD/Range небольшого блока того же публичного артефакта с connect/read timeout, без второй полной загрузки. `HF_HUB_DISABLE_XET=1` применять как явно конфигурируемый и проверенный fallback, устанавливать до импорта huggingface-hub. Не объявлять его универсальным ускорителем.
- Ограничивать сетевой connect/read stall и отдельные попытки скачивания, а не общее время полезной обработки документа. Сохранять готовые cache chunks; повтор после сетевой ошибки должен пользоваться кешем. Не удалять `.locks` по одному факту их существования.
- Запуск OCR до готовности моделей должен иметь явное состояние ожидания, не съедать учебные/рабочие попытки за отсутствие общих весов и не имитировать распознанный документ.

### P0. Владение задачами, длительность и восстановление после рестарта

Фиксированный длинный lease прячет потерянные задачи, короткий без heartbeat создаёт дубликаты. Cancellation HTTP не останавливает `run_in_threadpool` и не гарантирует завершение моделей. Увеличение lease не является восстановлением.

Реализация:

- Сделать короткий возобновляемый lease (например, heartbeat 10s, lease 60s; параметры на сервере) для OCR/cleaning/graph. Heartbeat обновляет только `(id, token, status=processing)`. Длительная работа продолжает владение, без предела по elapsed.
- Claim допускает retry истёкшего владельца; token сохраняет защиту позднего результата. Потеря ownership отменяет работу/публикацию. Finish и Fail проверяют token. После трёх реальных ошибок — failed; истёкший lease не должен позволять бесконечно увеличивать attempts без решения.
- На graceful shutdown освобождать только собственный token и переводить задачу в pending без расходования попытки за административную остановку. Crash восстанавливается после короткого lease. После backend restart не ждать 90 минут или сутки.
- Для OCR `0` означает отсутствие общего HTTP deadline; отрицательное/некорректное значение — ошибка конфигурации. Отдельно задаются dial/read stall safeguards, где они совместимы с протоколом. Убрать принудительный fallback120s для явно разрешённого `0`. Аналогично согласовать cleaning и graph: длительная полезная стадия не отменяется общим deadline.
- Python общие timeouts стадий не должны обрывать большой документ по elapsed. Ограничения отдельных LLM/network calls сохраняются; ретраи ограничены. Если требуется управляемое прекращение CPU стадии, использовать контролируемый subprocess и явный cancel, поскольку отмена async task не останавливает поток. Не создавать повторную тяжёлую работу при ещё живом старом запросе: request/job ID + singleflight/status или управляемая отмена исполнителя.
- До усложнения параллельности сохранить OCR capacity1. Pending не считается failed. Не запускать пять независимых копий Docling на CPU без измерений.

### P0. Фактическая полнота OCR и эффективность кода/формул

`NativeSyntaxGuard` сейчас вызывает generative enrichment, а затем возвращает исходный CODE при отличии. То есть дорогая генерация расходуется на результат, который затем отбрасывается; init CodeFormulaV2 возможен ещё раньше. `recover_native_programs()` работает после генерации.

Реализация:

- Перенести сохранение заведомо корректного нативного CODE до generative stage. Использовать текст из того же PDF прямоугольника и строгую проверку пригодности/полноты; при сомнении оставить полноценное enrichment. Не подменять формулу произвольной строкой текстового слоя.
- Для ошибочно размеченного Prolog сохранить `:-`, `?-`, имена предикатов, переменные, пунктуацию и порядок. Не менять поведение обычных математических формул.
- Не инициализировать тяжёлую generative модель, если в документе нет ни одной области, которой она реально нужна. Если архитектура Docling инициализирует модель заранее, доказать и изменить lazy-init, либо явно указать, что ускорение касается inference, а не cold start. Не утверждать устранение скачивания только по guard.
- Число threads CPU OCR/torch задать явно из серверного конфига и измерить на этом 12-CPU хосте; не множить OpenMP/torch pools при нескольких стадиях. Проверить качество и wall time, а не только число потоков.
- Сохранять structured OCR report в S3/БД: source hash, engine/model/config version, общее/экспортированные страницы, пропущенные страницы, code/formula/image warnings и длительности стадий. Сейчас Go клиент оставляет только markdown+warnings, теряя значительную часть report.
- Неполный Docling и pypdf fallback остаются доступны как результат с явным качеством; их нельзя тихо приравнивать к полному распознаванию. Кеш не должен закреплять неполное распознавание. Изменение моделей/настроек инвалидирует cache key.

### P1. Очистка и источники

Проверка `validCleaningResult` правильно сравнивает Unicode offsets и исходный hash, но проверяет только удаление; topics проверяются позже Python при сборке. Большой неделимый блок вызывает ошибку. Очередь не имеет явного ручного retry. Сообщение пользователю при ошибке очистки сейчас скрывает первопричину.

Реализация:

- Сохранить инвариант: результат — исходник минус проверенные spans; код/формулы/смешанный учебный блок не удаляются. Для каждого retained block есть тема или контекст. Координаты относятся к неизменённому parsed source, а не к cleaned markdown.
- До публикации ready проверить topics: уникальные IDs, source offsets/text/material ID, topic.text равен конкатенации sources; пустые/выдуманные карточки не публиковать.
- Реальный oversized protected block обрабатывать без обрезки: отдельный запрос допустимого размера или понятная ошибка с размером и параметром; не делить код/математику по случайной границе.
- Логировать chunk i/N, repair/split, число реальных LLM calls и elapsed; последовательно обрабатываемые chunks допускают долгую полезную работу. Не возвращать весь материал к первому LLM запросу при локальном repair.
- Сохранять техническую причину в структурированных логах/admin-safe detail; UI оставлять русским. Частичный перевод не должен терять исходный OCR или молча ломать блоки кода.

### P1. Достоверность итогового графа

В текущем `topics/graph.py` подтверждены рискованные эвристики: hardcoded `COMMON_CLUSTERS` задаёт предметную иерархию независимо от материалов; isolated тема прикрепляется к первому подходящему root только по файлу/неделе; `valid_evidence` может заменить несуществующую цитату короткой найденной подстрокой и переписать material/block. Эти механизмы не доказывают семантическую связь. Синтетический parent создаёт общий вопрос и `provides` без отдельной проверки, fallback источника может фабриковать координаты.

Реализация:

- Не прикреплять изолированную тему к произвольному root ради связности. Лес и независимые темы допустимы. Оба типа рёбер проверяются на существование концов и циклы; дерево темы/подтемы не смешивается с пререквизитами.
- Иерархия берётся из обоснованного parent_title/источников, не из словаря конкретного демокурса. Синтетический группирующий parent допускается только с реальными агрегированными sources и явной ролью группы; нельзя добавлять выдуманные знания, проверочные вопросы и координаты. Если текущий DTO не различает группу и проверяемую тему, сначала реализовать это различие или не создавать такую вершину автоматически.
- Evidence принимается из указанного материала/блока соответствующей темы. Допустима нормализация пробелов с сохранением точной найденной цитаты; запрещены подмена материала, удаление слов и подбор короткой совпавшей фразы ради принятия связи. Неподтверждённый ответ → ограниченный repair → unresolved/rejected с причиной. Это не доказанный учебный пробел.
- `requirements` покрывают входные пары ровно один раз; неизвестные/дублированные решения не игнорировать молча. Нет подтверждения → unresolved, не ложная связь. После отбрасывания циклов обновлять решения и метрики.
- Тексты, week/page, источники и дедупликация сохраняются. Не обещать экспертную семантическую точность по одному `acyclic=true`; оставить `not_expert_validated` и провести проверку реального результата.
- Публикация атомарна по fingerprint актуальных материалов/отчётов. Старый успешный граф сохраняется при ошибке, виден как stale. Материал, добавленный во время сборки, не должен быть исключён тихо.

### P1. Практический прогресс и повторный запуск

Admin должен видеть состояние каждого файла и общий граф без повторной загрузки.

- Стадия и фактический прогресс: `waiting_models`, `ocr`, `translation`, `cleaning/topics`, `graph/retrieval`, `graph/links`, `ready/failed`; elapsed, обновление heartbeat, страницы/chunks, только когда измерены. Не выдумывать проценты для неизвестного числа шагов.
- Минимально обязательны структурированные логи с material ID/job token/stage и причинами ожидания. Для реального `/admin` добавить безопасный status/progress DTO и обновление отображения, переиспользуя существующий polling; не показывать секреты или внутренний стек обычному пользователю.
- Admin retry для failed/stalled этапа должен переиспользовать raw/parsed/cleaned artifacts, проверять права, быть идемпотентным и не сбрасывать живого владельца. Не создавать дубликаты material rows. При отсутствии отдельной ручки на первом шаге предоставить проверенный узкий recovery script с token/status CAS, audit и dry-run; реализация не должна требовать повторной загрузки.

## Приёмочные проверки

### Автоматические

- OCR network/download fixture: медленный поток с реальными progress events продолжает работу; connect/read failure даёт ограниченный retry; отсутствующий cache не заявляется ready; warm cache не повторяет скачивание. Секретные URL отсутствуют в логах.
- OCR без общего timeout продолжает ответ дольше прежнего искусственного тестового лимита. Явно заданные ограничения валидируются; `0` не превращается в120s.
- Lease integration PostgreSQL: long-running heartbeat не даёт второму worker claim; crash/restart восстанавливается после lease; graceful shutdown освобождает владельца; старый token не публикует и не помечает failed новую попытку. Сетевая отмена не создаёт две OCR inference одного job.
- OCR quality fixture: текстовый PDF с Prolog передаёт точные операторы без ненужной CODE генерации; scanned code и реальные формулы вызывают нужный enrichment; изображения и partial/missing pages отражаются в report. Изменение config/models инвалидирует cache.
- Cleaning: русский Unicode offsets, protected blocks, mixed slides, большой блок, invalid JSON/repair, hash mismatch, пустые/ложные sources. Неполный результат не становится ready.
- Graph: выдуманная цитата с реальным коротким совпадением отклоняется; чужой material/block не исправляется молча; whitespace-normalized exact quote допускается; требования покрываются полностью, циклы rejected, отдельная тема остаётся самостоятельной, parent не получает вымышленные source offsets. Сохраняются источники при дедупликации.
- Backend/API: admin-only status/retry, идемпотентность, stale graph/fingerprint race и сохранение предыдущего снимка. Frontend проверяет фактические промежуточные статусы и ошибки без вечного spinner.

Запустить `python -m pytest -q` в course-graph, соответствующие Go tests и `go test -race ./... -count=1` с `TEST_DATABASE_URL` в изолированной схеме действующего PostgreSQL, команды frontend из его README/AGENTS. Если DB integration пропущены — явно указать это, не выдавать unit tests за DB проверку.

### Обязательная сквозная проверка на текущих данных

- Все пять исходных material ID и raw S3 objects сохранены; повторная загрузка не потребовалась.
- Каждый OCR завершён либо имеет обоснованную явную ошибку качества, нет вечного processing без живого heartbeat. Для 57-страничной лекции перечислены пропуски/предупреждения; наличие части текста не выдаётся за проверку всех слайдов.
- Для всех пяти есть ready cleaning с валидными source hashes/spans и карточками; переводы/предупреждения проверены.
- Для актуального fingerprint опубликован непустой граф, `stale=false`, его темы и связи видны в `/admin`. Проверены минимум код/формула, иллюстрация, учебное упражнение, межфайловая связь и независимая тема. По каждой выбранной проверке указаны материал/страница/цитата.
- Проверены restart recovery и повторное чтение графа после рестарта без удаления volume. Общее время обработки измерено; SLA не выдумывается до фактического прогона.
- Финальный отчёт перечисляет реально выполненные проверки, остаточные quality warnings и незакрытые ограничения. Если реальные пять PDF ещё не дали граф, задача не считается завершённой.

## Операционное восстановление

Перед контролируемым restart записать jobs/status/token/attempts/lease, material/raw keys и текущий граф. Не публиковать секреты из окружения. После исправления применить только новые migrations штатным механизмом и перезапустить только необходимые процессы. Убедиться в сохранности S3/HF/cache volumes. Вернуть pending только потерявшие владельца или failed jobs в пределах выбранного курса, CAS по status/token; не трогать ready и живые processing. Проверить фактическое получение новых lease и рост progress. При проблеме download сначала завершить/возобновить единственную подготовку модели, затем продолжить очередь. Предыдущий успешный граф остаётся доступным до атомарной публикации нового.
