# Авторская карта Geek: 16 согласованных вопросов

Подготовлена для импорта графа через «Импортировать карту компетенций» на экране материалов экзамена. Это импорт Geek (`/exam`), а не отдельный импорт карты режима `/learn`. Общий backend не объединяет их парсеры.

## Что использует текущий импорт

Geek читает **первый лист по порядку**: имя листа не участвует в выборе. В предоставленной книге первым стоит «Карта компетенций v2», поэтому используется он. Остальные листы этим импортом не читаются. Другая ручка импорта в `/learn` имеет собственный формат и выбирает второй лист, если он есть; она этой доработкой не меняется.

| Колонка | Использование Geek |
| --- | --- |
| Компетенция / Субкомпетенция | Вместе с составляющей определяет группу обычной карты |
| Составляющая | Значения обязательны; обычная карта выбирает главное и два базовых задания внутри составляющей |
| Образовательный результат | Название вершины, provides; в обычной карте также часть контекста оценщика |
| Таксономия / Уровень по Блуму | В обычной карте определяет главное и базовые задания; значения проверяются и в явной карте |
| Важность | Разрешает ничьи при отборе; целое число 1–5 |
| Что должно войти в тест | TRUE включает строку; FALSE исключает |
| Свидетельство | Необязательный контекст, когда нет отдельного текста темы |
| Задание 1, 2, … | Вопросы без переформулирования; несколько заданий одной строки — случайные варианты одной темы |
| Критерии оценивания… | Сопоставляются заданиям **по порядку колонок**, а не по числу в названии. Эталон становится контекстом, рубрика — assessment_guidance |

В примере Geek не использует «Уровень темы», DOK, ALDs, раздел/компетенции РПД, ОС, соответствие целям, тему/недели/материалы, «Код», примечания и остальные листы. Колонка с темами/неделями сама по себе не даёт оценщику теорию.

## Зачем расширение формата

Обычная карта сохраняет три ОР на составляющую: главный и два базовых; остальные отсеиваются. Группировка текущего master по паре «Компетенция / Составляющая» сохранена. Чтобы не терять авторские вопросы и не придумывать дублирующие задания, добавлен явно включаемый формат:

- **ID темы** и **Пререквизиты** должны присутствовать вместе. Тогда каждая включённая строка становится вершиной, без отбора трёх ОР. ID обязателен и уникален. Пререквизиты — ID через точку с запятой, запятую или перенос строки; пустая ячейка означает отсутствие зависимостей.
- **Текст темы** необязателен: позволяет передать исходную теорию, а не только формулировку ОР. Эталон из критериев добавляется к ней; рубрика не смешивается с теорией.
- Неизвестные зависимости, ссылки на исключённые строки, дубликаты ID и циклы отклоняются с указанием ячейки/строки. Половина пары заголовков не включает старый отбор молча.

Для авторского демо использовалась отдельная XLSX-карта: один лист, 16 строк с TRUE и по одному вопросу в каждой. Сам XLSX намеренно не включён в этот PR. Демо сохранено отдельно в ветке `demo/geek-authored-16`: готовый граф с вопросами, теорией, критериями и зависимостями лежит в `examples/geek-authored-16/graph.json`. Это снимок графа, а не файл для загрузки через XLSX-импорт; инструкция находится рядом в README. Критерии допускают разумные внешние примеры, требуют все запрошенные части и не штрафуют за разговорную форму. Даты, имена, примеры из лекции и дословность не требуются, если вопрос их не просит.

Все 16 тем будут в графе. Это не обещание задать каждому студенту все 16 вопросов: действующий обход по-прежнему может зачесть базовые темы по сильному ответу на вышестоящую.

## Применение и ограничения проверки

Сначала необходимо обновить backend кодом этой ветки; backend без поддержки явного графа проигнорирует новые заголовки и отберёт только часть вопросов. После обновления файл загружается той же кнопкой импорта. Импорт запускает штатную подготовку переформулировок и озвучки. Числовые рубрики заданий оцениваются по их пунктам с проверяемыми цитатами; нечисловые правила авторских вопросов сохраняют шкалу К1–К4. Подробности текущей оценки — в корневом README.

Фидбек перенесён с учётом общего backend. Парсер карты `/learn`, миграции и параметры модели не менялись. Наличие рубрики не устраняет противоречий самой карты: соответствие задания и его критериев должен проверить преподаватель.

Добавлены регрессии сохранения всех вопросов и связей, отказа на повреждённом графе, выбранного варианта карты и фидбека по решению движка. На исходной рабочей ветке проверены импорт 16 авторских тем, числовые рубрики новой КК, живые ответы и сохранение баллов через HTTP/PostgreSQL. После переноса на свежий master проверки кода выполняются повторно; локальные XLSX, прогоны и данные стенда в PR не входят.
