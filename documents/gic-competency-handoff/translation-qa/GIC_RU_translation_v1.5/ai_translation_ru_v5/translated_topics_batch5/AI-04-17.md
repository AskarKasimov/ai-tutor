[D22 | Week 6 Lecture.pdf | с.17 | core]
Алгоритм A* (псевдокод из лекции).
Каждый узел хранит координаты, стоимость и родителя.
Инициализируйте множества `CLOSED` и `BLOCKED` как пустые. Создайте очередь с приоритетами по стоимости `OPEN`, добавьте стартовый узел с оценкой 0.
Пока `OPEN` не пуста:
- `current ← POP(OPEN.top)` — извлеките лучший узел.
- Для каждого соседнего состояния X, которое не входит в `BLOCKED` и `CLOSED`:
  - если X отсутствует в `OPEN`, присвойте `X.cost = current.cost + costFromCurrentToX`, `X.parent = current`, добавьте X в `OPEN`;
  - если X уже есть в `OPEN` и новый путь дешевле `OPEN.X.cost`, обновите стоимость и родителя X (найден лучший путь).
- После проверки соседей добавьте `current` в `CLOSED`.
[На слайде очередь приоритетов описана лишь как `based on cost`; для корректного A* нужно использовать f=g+h, учитывать цель и завершение. Это учебный упрощённый псевдокод.]

[D22 | Week 6 Lecture.pdf | с.18 | core]
A* для нахождения пути. Процедура `REPORT_PATH(START, FINISH)`:
- Инициализировать пустой стек `PATH`.
- Выполнить `A*(START)`.
- Найти `FINISH` в `CLOSED`, начать с `Current ← FINISH`.
- Пока Current ≠ START: поместить Current в PATH; перейти к `Current.parent`.
- Вывести START.
- Пока стек PATH не пуст: извлекать из него узлы и выводить их.
Так восстанавливается путь от старта до финиша в прямом порядке.

[D22 | Week 6 Lecture.pdf | с.17 | core]
A* Algorithm
A node contains a location, a cost, and a parent
Initialize sets CLOSED and BLOCKED to be null
Initialize a priority queue based on cost of a node
called OPEN to be the starting location, set cost = 0
While OPEN is non-empty do
Current <- Pop OPEN.top
For all neighbouring locations X
If not in (BLOCKED or CLOSED)
If not in OPEN
X.cost = current.cost + costFromCurrentToX
X.parent = current
Push X to OPEN
Else if X is in OPEN
If current.cost + costFromCurrentToX < OPEN.X.cost
// we found a better path
OPEN.X.cost = current.cost + costFromCurrentToX
OPEN.X.parent = current
END FOR ALL X
Push Current to CLOSED
