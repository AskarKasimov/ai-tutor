Язык описания областей планирования (PDDL). Требуется формально задать:

[D04 | PDDL (Lecture +Tutorial).pdf | с.9 | shared]
Классическая задача планирования в PDDL описывается кортежем `<F, A, I, G>`:
`F` — набор булевых фактов (высказываний);
`A` — набор детерминированных действий с предусловиями и эффектами;
`I ∈ S` — начальное состояние;
`G` — целевое условие/состояние.
Множество всех состояний `S` является множеством всех подмножеств фактов `F`, то есть `S = 2^F`. [На исходном слайде математические символы перемешаны из-за извлечения; формула восстановлена по контексту.]

[D04 | PDDL (Lecture +Tutorial).pdf | с.10 | shared]
Классический PDDL предполагает:
- детерминированные и мгновенно выполняемые действия;
- описание мира булевыми высказываниями;
- изменение мира только вследствие выполняемых нами действий (внешних событий нет);
- полную наблюдаемость: начальное состояние `I` известно.

[D04 | PDDL (Lecture +Tutorial).pdf | с.11 | shared]
Классический PDDL может показаться слишком ограниченным, поскольку его допущения нереалистичны для некоторых практических задач. Почему он популярен?
- Он задаёт идеализированную модель для разработки автоматических планировщиков.
- Во многих случаях такой модели достаточно, например в контролируемой робототехнической среде.
Расширения: PDDL 2.1, вероятностный PDDL (PPDDL), RDDL и другие.

[D04 | PDDL (Lecture +Tutorial).pdf | с.12 | core]
Структура PDDL.
Для классического планирования используют два файла:
- `domain.pddl` — описание предметной области: предикаты (свойства мира), операторы/действия (как может изменяться состояние). Из них определяются множества фактов F и действий A, используя идеи логики первого порядка.
- `problem.pddl` — конкретная задача: объекты окружающего мира, начальное состояние и цель.

[D04 | PDDL (Lecture +Tutorial).pdf | с.13 | shared]
Решатели PDDL
Как найти план достижения цели?
- Решатель принимает файлы `domain.pddl` и `problem.pddl`, а на выходе генерирует план.
- Задачу планирования можно представить сетью состояний, в которой действия задают переходы между состояниями.
- Это задача поиска: могут использоваться, например, подходы A* или MCTS.

Синтаксис PDDL: файл предметной области `domain.pddl`.
```
(define (domain <domain-name>)
 (:requirements <requirements-list>)
 (:types <types-list>)
 (:predicates <predicate-list>)
 (:action <action-details>)
)
```
`<domain-name>` — имя моделируемого мира.
`:requirements` — используемые возможности PDDL.
`:types` — необязательное описание типов объектов.
`:predicates` — список свойств состояния, истинных или ложных фактов.
`:action` — список допустимых переходов между состояниями.

Синтаксис PDDL. Файл задачи `problem.pddl`:
```lisp
(define (problem <title>)
  (:domain <domain-name>)
  (:objects <object-list>)
  (:init <predicates>)
  (:goal <predicates>)
)
```
`<title>` — имя задачи; `<domain-name>` — имя домена, объявленного в `domain.pddl`; `:objects` — объекты мира, над которыми выполняются действия; `:init` — начальное состояние; `:goal` — целевое состояние или условия достижения цели.

Компоненты PDDL.
Мир моделируется множеством состояний, каждое содержит набор фактов и/или объектов.
Есть начальное состояние. Набор правил и ограничений определяет, какие действия разрешены в данном состоянии. Каждое действие обычно переводит систему в другое состояние.
На схеме указаны START, GOAL и OBSTACLE (начало, цель, препятствие).

[D26 | Week 9 Lab.pdf | с.5 | shared]
Компоненты модели мира PDDL:
- Objects — объекты, важные для задачи.
- Predicates — факты или свойства объектов, которые могут быть истинными или ложными.
- Actions/Operators — действия, меняющие состояние мира и истинность фактов.
- Initial state — исходное состояние; факты, истинные в начале.
- Goal specification — целевая спецификация; что должно стать истинным к концу выполнения плана.

Components of PDDL
- 
There are certain things we need to keep track of in the “world”:
○
Objects: Things in the world that interest us
○
Predicates: Facts that we are interested in (e.g. properties of
objects), which can be true or false
○
Actions/Operators: Ways of changing the state of the world, i.e.
things that happen that change the facts
○
An initial state: The state of the world that we start in, i.e.
things that are true at the start
○
Goal specification: The state of the world we want to end at,
i.e. things that we want to be true at the end
