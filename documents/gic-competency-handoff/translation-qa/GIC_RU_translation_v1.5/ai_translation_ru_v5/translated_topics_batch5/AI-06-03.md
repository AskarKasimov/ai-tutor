Синтаксис PDDL: файл предметной области `domain.pddl`.
```
(define (domain <domain-name>)
 (:requirements <requirements-list>)
 (:types <types-list>)
 (:predicates <predicate-list>)
 (:action <action-details>)
)
```
`<domain-name>` — имя моделируемого мира.
`:requirements` — используемые возможности PDDL.
`:types` — необязательное описание типов объектов.
`:predicates` — список свойств состояния, истинных или ложных фактов.
`:action` — список допустимых переходов между состояниями.

Синтаксис PDDL. Файл задачи `problem.pddl`:
```lisp
(define (problem <title>)
  (:domain <domain-name>)
  (:objects <object-list>)
  (:init <predicates>)
  (:goal <predicates>)
)
```
`<title>` — имя задачи; `<domain-name>` — имя домена, объявленного в `domain.pddl`; `:objects` — объекты мира, над которыми выполняются действия; `:init` — начальное состояние; `:goal` — целевое состояние или условия достижения цели.

Классический PDDL: пример
- У действия есть `:parameters` (параметры), `:precondition` (простые условия применимости), эффекты добавления (add effects) и удаления (delete effects).
- Выражения записываются в префиксном порядке: `(operator <arguments>)`, например `(and <conjunct1> … <conjunctN>)`.
- В обозначениях слайда: `par(a) ⊆ F`, `pre(a) ⊆ F`, `add(a) ⊆ F`, `del(a) ⊆ F`.
Пример `domain.pddl` (синтаксис не переводим):
```
(define (domain simple_switches)
  (:requirements :typing)
  (:types switch)
  (:predicates (off ?s - switch)
               (on ?s - switch))
  (:action switch_on
    :parameters (?s - switch)
    :precondition (off ?s)
    :effect (and (not (off ?s))
                 (on ?s))))
```
На схеме: ВЫКЛ / ВЫКЛ / ВКЛ.

Классический PDDL: пример задачи
- Домен называется `simple_switches`.
- Есть три объекта типа `switch`.
- Два переключателя из трёх выключены.
- Цель — все три переключателя включены.
- Один домен можно использовать с разными задачами!
Пример `problem.pddl`:
```
(define (problem switches_problem)
  (:domain simple_switches)
  (:objects s1 s2 s3 - switch)
  (:init (off s1) (off s2) (on s3))
  (:goal (and (on s1) (on s2) (on s3))))
```
Начальное состояние на схеме: ВЫКЛ / ВЫКЛ / ВКЛ.

Компоненты PDDL.
Мир моделируется множеством состояний, каждое содержит набор фактов и/или объектов.
Есть начальное состояние. Набор правил и ограничений определяет, какие действия разрешены в данном состоянии. Каждое действие обычно переводит систему в другое состояние.
На схеме указаны START, GOAL и OBSTACLE (начало, цель, препятствие).

[D26 | Week 9 Lab.pdf | с.5 | shared]
Компоненты модели мира PDDL:
- Objects — объекты, важные для задачи.
- Predicates — факты или свойства объектов, которые могут быть истинными или ложными.
- Actions/Operators — действия, меняющие состояние мира и истинность фактов.
- Initial state — исходное состояние; факты, истинные в начале.
- Goal specification — целевая спецификация; что должно стать истинным к концу выполнения плана.

Синтаксис PDDL.
Файлы обычно имеют расширение `.pddl`.
Два основных файла:
- `domain.pddl`: определяет предметную область, допустимые предикаты состояний и действия перехода.
- `problem.pddl`: определяет конкретный экземпляр области, начальное состояние и конечную цель.

Components of PDDL
- 
A world in PDDL is described by set of states each containing a
list of facts and/or objects
- 
A world begins with an initial state
- 
A world governed by a set of rules and constraints that limit
which actions can be taken in each state
- 
Each action generally represents a transition to a different state

Components of PDDL
- 
There are certain things we need to keep track of in the “world”:
○
Objects: Things in the world that interest us
○
Predicates: Facts that we are interested in (e.g. properties of
objects), which can be true or false
○
Actions/Operators: Ways of changing the state of the world, i.e.
things that happen that change the facts
○
An initial state: The state of the world that we start in, i.e.
things that are true at the start
○
Goal specification: The state of the world we want to end at,
i.e. things that we want to be true at the end

PDDL Syntax
- 
First thing you need to know, PDDL files usually have the extension
.pddl
- 
There are two PDDL files you need to learn the syntax of:
○
The Domain File (domain.pddl)
■
establishes the context of the world
■
determines what sorts of details the states can include
(predicates)
■
what can we do to move between states in the world
(actions).
○
The Problem File (problem.pddl)
■
represents an instance of the world we established in the
domain
■
determines what is true at the start of the plan (initial state)
■
what we want to be true at the end of the plan (goal
state).
