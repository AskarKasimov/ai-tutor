# Формат учебного текста

Вопросы, варианты ответа, учебное содержание, теория, подсказки и обратная связь — Markdown с GFM-таблицами. Frontend использует один `MarkdownContent`; первый абзац или Markdown-заголовок вопроса оформляется заголовком экрана. В разборе ответов уровни заголовков вопроса сдвигаются относительно h3. В сообщениях наставника первый абзац остаётся абзацем, а заголовки Markdown начинаются с h3 под заголовками страницы и темы. Ответы студента и голосовые инструкции остаются обычным текстом.

## Карта CSV/XLSX

Структура ячейки сохраняется: `Экран:`, необязательные `Варианты:`, `Голосовая инструкция:`, `Ответ:`. Markdown пишется непосредственно в содержимом; переносы строк в ячейке — настоящие, не буквальные `\n`. Для CSV многострочные ячейки заключаются в двойные кавычки; двойная кавычка внутри ячейки удваивается.

Код оформляется тройными обратными кавычками с языком. Отступы и строковые escape-последовательности сохраняются:

````text
Экран: Объясните вывод программы.

```python
for step in range(2):
    print("a\nb")
```

Голосовая инструкция: «Объясните вывод, не читайте код».

Ответ: На каждом шаге выводятся две строки.
````

Таблицы и пояснения после кода находятся после закрывающих кавычек блока. Формулы записываются читаемыми символами Unicode или inline-кодом, например `ŵ = (XᵀX)⁻¹Xᵀy`. LaTeX не подключён. Сырой HTML не исполняется.

Блоки кода подсвечиваются через Light-сборку React Syntax Highlighter. Подключены Python, JavaScript, TypeScript, SQL, Go, Bash, JSON, Java, C/C++, Rust, CSS и XML/HTML; поддерживаются короткие метки `py`, `js`, `ts`, `sh`, `rs` и другие стандартные алиасы. Цвета задаются токенами Radix в SCSS и адаптируются к теме. Inline-код, блоки без языка и неизвестные языки остаются обычным моноширинным текстом. Подсветка сохраняет переносы, отступы и escape-последовательности и не выполняет код.

Импорт выделяет поля задания и сохраняет их текст без эвристического исправления Markdown. Неполные ячейки по-прежнему остаются источником с предупреждениями, а не заданиями.

## LLM

Ответ модели остаётся JSON установленной структуры. Markdown находится внутри текстовых полей (`question`, `theory`, `feedback`, `assistant_text`, `summary` и других учебных полей). Внешний JSON не оборачивается кодовым блоком. Экранирование транспорта обрабатывает JSON-декодер; повторно заменять `\n` в декодированном тексте нельзя — это повреждает код.

Промпты явно задают формат; требования к длине, педагогике и структуре ответа сохраняются. Frontend отделяет переносом открывающий блок кода, если его разделитель склеен с пояснением на одной строке. Содержимое уже открытых блоков кода и inline-код не переписываются; остальная неверная разметка отображается как получена.
