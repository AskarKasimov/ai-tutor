## Задача

Сделать неделю и вид материала частью учебного конвейера. Преподаватель
классифицирует документы, граф сохраняет происхождение тем, студент получает
материалы для устранения конкретного пробела, а подготовка тренировки выбирает
теорию из лекций и практику из лабораторных и туториалов.

Документ определяет реализацию метаданных и источников. Сам режим тренировки
с диалогом, расписанием и оцениванием остаётся отдельной работой. В этой задаче
реализуется используемый результатом диагностики подбор материалов для него.

## 1. Сквозная модель происхождения

Единица происхождения — цитата из конкретной редакции материала. Тема может
иметь источники из нескольких документов, недель и видов; у темы нет одной
«главной недели», которая вытесняет остальные.

Материал, отправляемый backend в course-graph, содержит:

```text
id, markdown, topics?
week: positive integer | null
kind: string | null
filename: string | null
kind_label: string | null
material_revision: string | null
```

`material_revision` — непрозрачный стабильный идентификатор редакции исходника,
например SHA-256 внутреннего raw key. Внешние ответы не содержат S3 key.
Исполнитель выбирает конкретный способ вычисления, обеспечивая изменение при
замене PDF и стабильность при правке недели/вида. Сам текст и его контрольная
сумма используются отдельно для проверки цитат и пригодности кэша.

Каждый источник темы сохраняет существующие `material_id`, `block_id`, `start`,
`end`, `text`, `page`, `week` и получает `kind`, `filename`, `kind_label`,
`material_revision`. Номер страницы сохраняется только когда он достоверно
известен. Координаты и цитаты относятся к тому Markdown, по которому выполнено
извлечение; их единицы и существующая проверка точного среза не меняются.

Для новых сборок авторитет метаданных — snapshot материалов backend.
При использовании кэша тем Python обновляет метаданные источников из текущего
входного материала, сохраняя цитату, координаты, текст темы и material_id.
Метаданные не генерируются моделью и не угадываются по имени файла.
Источник с чужим material_id или не совпадающей с Markdown цитатой отклоняется.

Совместимость: старые входы и сохранённые графы без новых полей читаются.
Отсутствующие метаданные остаются null, источники старых Geek-графов — пустыми.
Виды — произвольные коды каталога, не закрытый enum из трёх значений.
Подписи каталога сохраняются в snapshot; код не выводится вместо русского
названия, если для него нет подписи.

## 2. Классификация и повторяемость сборки

Новая сборка курса допускается только когда все входные материалы обработаны
и у каждого есть положительная неделя и существующий код вида. Это проверяет
backend независимо от frontend. Отсутствующая классификация возвращает
структурированную 422 с кодом `MATERIAL_METADATA_INCOMPLETE` и ID материалов.
Наличие другого активного build по-прежнему даёт 409.

Согласовать `inputs_ready`, причины блокировки в UI и серверную проверку:
полностью обработанные, но неклассифицированные материалы не готовы к сборке.
Отсутствие метаданных — не бесконечная обработка и не повод постоянно
опрашивать сервер как при работающем OCR. Отдельно показывать нужду классификации.

Fingerprint входов включает семантически значимые значения каждого материала:
ID, готовую редакцию/отчёт обработки, week, kind. Использовать однозначную
каноническую сериализацию со стабильным порядком и явным представлением null.
Добавить также значения метаданных, которые входят в опубликованный snapshot
и могут независимо меняться, либо определить их отдельную согласованную
версию; опубликованная подпись не должна незаметно расходиться с входами.

Поведение PATCH:

- Фактическая правка week/kind сразу делает опубликованный граф `stale=true`.
- PATCH того же значения ничего не инвалидирует.
- OCR, перевод, очистка и извлечение тем повторно не запускаются. Их время,
  lease, попытки, текст и S3-объекты сохраняются.
- При пересборке пригодный кэш тем используется повторно; меняются metadata
  источников и зависимые этапы сборки.
- Стартовавшая сборка публикуется только для своего неизменившегося snapshot.
  Правка метаданных во время работы не позволяет опубликовать старые входы
  под новым fingerprint; состояние объясняет необходимость новой сборки.
- Действующий опубликованный граф доступен до успешной замены. Прежние правила
  отмены активных диагностик при публикации новой версии сохраняются.

Менять view/схему только новой миграцией со следующим свободным номером.
Учесть upgrade: старые fingerprint не должны ошибочно считаться новыми.
Допустимо пометить старую публикацию устаревшей до явной пересборки, сохранив
сам граф и прошлые результаты. Автоматический массовый запуск OCR запрещён.

## 3. Дедупликация с учётом недель

Сборщик выполняет два прохода:

1. Объединение повторов темы в материалах одной недели, включая разные виды.
2. Объединение повторов между неделями курса.

Сохранить текущую консервативную политику равенства нормализованных заголовков.
Семантическая похожесть сама по себе не даёт права склеивать разные понятия;
новый классификатор похожести и новые модельные вызовы в эту задачу не входят.

Оба прохода сохраняют объединение всех уникальных источников и имеющихся
requires/provides; ссылки на ID объединённых тем переводятся на канонические
ID. Источник уникален по материалу, редакции и координатам. Сборка одного
набора входов даёт устойчивый порядок и выбор канонических тем независимо
от порядка загрузки файлов. Итоговый текст остаётся согласован с цитатами.

Совместимые входы с неизвестной неделей обрабатываются отдельной группой
unknown, а не получают выдуманную неделю 1. Backend не создаёт такие новые
сборки; это правило нужно для старых вызовов Python и тестовых фикстур.
После дедупликации сохраняются существующие проверки зависимостей и циклов.

## 4. Источники в Geek и результате диагностики

Адаптер сохранённого графа переносит источники в доменную модель `exam.Node`
и snapshot графа внутри диагностической сессии. Источники и отсортированный
список уникальных известных недель переносятся в каждый пробел результата.
Результат завершённой сессии строится из её snapshot, а не из сегодняшней
таблицы материалов или новой версии графа.

Расширение HTTP-результата аддитивно: у gap появляются `weeks`, `sources` и
`learning_materials`; массивы сериализуются как `[]`, а не null. Названия полей
и типов привести к соглашениям действующего geek API. Старые фикстуры,
сессии, идемпотентные запросы и результаты читаются без миграции JSON вручную.

В результате студент видит для каждого пробела:

- известные недели темы;
- относящиеся к пробелу документы с названием, видом и неделей;
- разделение «Теория», «Практика», «Другие материалы» по правилам раздела 5;
- доступное действие открытия исходника и понятное состояние его недоступности.

Один документ не дублируется в списке ссылок из-за нескольких цитат; сами
цитаты сохраняются в данных. Если источников нет, показать нейтральное
сообщение «Материалы для этой темы пока не связаны». Это не ошибка оценки.
Новый текст интерфейса — через i18n.

Критерии оценки A–D, определение пробела, обход графа, выбор вопросов и правила
помощи на экзамене сохраняются. Источники показываются в завершённом результате;
показ теории во время активного экзамена этим документом не вводится.

## 5. Подбор учебных материалов

Реализовать чистую функцию подбора из источников темы, вызываемую при
формировании gap.learning_materials. Это рабочий потребитель метаданных,
который позже использует и режим тренировки:

```text
theory: references[]     # kind == lecture
practice: references[]   # kind == lab или tutorial
additional: references[] # прочие и неизвестные виды
```

Коды lecture/lab/tutorial — соглашение существующего каталога, не список
разрешённых значений API. Пользовательские виды остаются допустимыми и
попадают в additional; не угадывать роль по подписи. Расширение каталога
настраиваемыми учебными ролями — отдельное последующее решение.

Выбор ограничен реальными источниками данной темы. Запрещено подменять
отсутствующую практику произвольной лабой той же недели. При отсутствии
лекции theory пуст; при отсутствии практических источников practice пуст.
Порядок: известная неделя по возрастанию, затем устойчивые filename/material_id;
неизвестные недели — в конце. Используется весь подходящий материал, а не
единственный случайно выбранный PDF. Полноценный диалог тренировки в scope
не входит; в отчёте явно назвать реализованным именно подбор источников.

## Приёмка и доказательства

1. На примере «Матрицы» из лекции недели 1, туториала недели 1 и лабы недели 2
   после обоих проходов дедупликации остаётся одна тема со всеми источниками,
   неделями [1,2] и правильными видами/редакциями. Разные заголовки не склеены.
2. Новые метаданные доходят от PostgreSQL через backend/Python до сохранённого
   графа и результата диагностики. Цитаты и координаты проверяются по исходнику.
3. PATCH недели 1→3 меняет stale/fingerprint, сохраняет OCR/очистку и кэш.
   После явной пересборки источники содержат 3. PATCH 3→3 ничего не инвалидирует.
4. Редактирование метаданных во время сборки не публикует граф по старому
   snapshot как актуальный. Неполная классификация блокируется и через прямой
   HTTP-запрос, а UI показывает причину без бесконечного «обрабатывается».
5. Завершённая диагностика после PATCH/пересборки показывает старые недели и
   источники своего snapshot. Новая диагностика использует новую публикацию.
6. Пробел предлагает лекцию как theory, лабу/туториал как practice; неизвестный
   код как additional. Отсутствующий вид не заменяется посторонним документом.
7. Владелец сессии скачивает связанный неизменённый PDF. Чужая сессия и
   несвязанный материал дают 404. Заменённый/удалённый исходник даёт 410,
   исторический результат остаётся доступным.
8. Старые фикстуры, графы, сессии и ответы без новых полей остаются читаемыми.
   Оценки, статусы и обход экзамена сохраняются на существующих сценариях.
9. Новая миграция применяется к существующей БД, сохраняет материалы и графы,
   имеет осмысленный откат; применённые миграции не меняются.

Покрыть эти наблюдаемые сценарии сфокусированными Python/Go/frontend тестами,
включая DB-интеграцию для fingerprint и конкурентной публикации. Для приёмки
не требуются внешние модели: использовать fake gateway и локальные storage/
HTTP-адаптеры. Реальные модели/S3 — отдельный smoke при наличии конфигурации.

Выполнить проверки затронутых слоёв из AGENTS.md, регенерацию контрактов и
проверку отсутствия неожиданного diff генераторов. Указать фактические

## Что исполнитель решает сам

Внутренние имена структур, расположение чистого селектора на подходящем
доменном слое, формат fingerprint и способ получения непрозрачной редакции,
детали оформления ссылок и тестовые fixtures. Сохранить FSD frontend,
разделение Go features, приватность course-graph и gateway-only вызовы LLM.
Перед кодом составить короткий план по этой спецификации. Завершение означает
проверенные пункты приёмки либо точный отчёт о конкретном оставшемся блокере.
