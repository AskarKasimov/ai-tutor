Ветка: `perf/course-graph-ocr-cache`. Исходная точка:
`d01dc5beeea76f0f6e2c42f8c393ed724da3b240`; локальный master:
`c2546daf8b89695ac47c6a3ec3659cf895b472b0`.
Candidate — изменения рабочего дерева поверх исходной точки. Это проверка
отдельных страниц, а не подтверждение качества всего курса.

## Что изменено

- Исправлено подключение `NativePdfTextReader`: публичный
  `DocumentConverter.initialize_pipeline()` в Docling 2.139 возвращает `None`,
  pipeline нужно брать из `initialized_pipelines`. Раньше native-защита
  фактически не подключалась к конвертации PDF.
- Сохраняется строгое совпадение native-кода с тем же PDF-прямоугольником.
  Дополнительно разрешено склеивание строк пробелом только для целых
  однострочных Prolog-правил и заголовков `Solution N.`. Сами операторы,
  строковые литералы и внутристрочные пробелы должны совпасть. В результате
  сохраняются исходные переносы. Многострочные правила и Python этим
  исключением не пользуются.
- Разные OCR job ID с одинаковыми байтами, парсером и настройками используют
  одну задачу вычисления, включая случай без дискового кеша. Заголовок PDF
  формируется для каждого имени отдельно; отчёты не разделяют mutable-объекты.
  Отмена ожидающего coroutine не отменяет общее вычисление.
- TXT/Markdown не ждут слот Docling. Чтение кеша выполняется в thread pool,
  а после ожидания слота кеш проверяется повторно.
- Кеш `ocr-v8-content-cache` разделяет PDF и буквальный TXT/Markdown, проверяет
  структуру, SHA-256, конфигурацию и завершённость работы. Старые файлы кеша
  не удаляются. Их первое использование после изменения версии потребует
  новой конвертации.
- Стабильные нераспознанные формулы кешируются с предупреждениями. Частично
  завершённый Docling, временные ошибки визуального повтора и fallback после
  сбоя Docling не считаются завершённым финальным кешем.
- Native reader переиспользует до четырёх пар PDFium page/textpage, закрывает
  их при вытеснении и завершении. В повторе формул исправлены координаты crop
  для TOPLEFT/BOTTOMLEFT; страницы, bitmap и PIL-кропы освобождаются.
- Несовпадение токенов сгенерированного кода с доступным native-текстом даёт
  предупреждение и `content_complete=false`. Строковые литералы сравниваются
  целиком. При таком несовпадении текст автоматически не исправляется.

## Измерения

Изолированные Python-процессы в существующем OCR-контейнере, без изменения
запущенного приложения. В каждом запуске новый временный document cache;
веса уже скачаны, `HF_HUB_OFFLINE=1`. Время первого OCR включает инициализацию
конвертера и необходимых моделей в новом процессе. Контейнер разделяет CPU
с dev-стеком, по одному замеру на вариант: это диагностические измерения,
статистически устойчивое ускорение всех PDF ими не доказано.

| PDF / физическая страница | Baseline, с | Candidate, с | Inference batches до → после | Проверка результата |
| --- | ---: | ---: | ---: | --- |
| Tutorial 4. Prolog.pdf / 21 | 24,63 | 6,40 | 1 → 0 | Устранена подмена `=:=` на `==:`, сохранены native-переносы |
| Week 2 Lecture.pdf / 16 | 6,70 | 6,27 | 0 → 0 | Markdown побайтно совпал |
| Week 6 Tutorial_Covered.pdf / 16 | 28,28 | 20,38 | 1 → 1 | Отдельный блок `return on route` исправлен на исходный `return route`; оставшиеся ошибки явно отмечены |

Повторные чтения candidate: примерно 0,14–0,24 мс, пять на каждый документ,
ноль inference batches. Сам кеш baseline тоже был быстрым: его чтение не
стало быстрее, добавлены проверки пригодности. Основной эффект — устранение
лишних вызовов VLM и повторных конвертаций.

Микрозамер 200 чтений текстового слоя страницы Prolog:
34,67 → 3,89 мс (около 8,9 раза), SHA-256 текста совпал. Это ускорение одного
вспомогательного участка, не всего OCR.

Исходные JSON с SHA-256 PDF, конфигурацией, временами, RSS и отчётами, а также
полученный Markdown: [артефакты](ocr-performance-2026-10-18/).
В срезах выбранная исходная страница становится страницей 1; исходный номер
сохранён в поле `pages` benchmark JSON.

лимит контейнера 8 GiB. Python 3.11.17, Docling 2.139.0,
torch 2.14.1+cpu, pypdfium2 5.14.0, pypdf 6.21.1.

Воспроизведение из каталога сервиса с установленными зависимостями:

```bash
PYTHONPATH=. HF_HUB_OFFLINE=1 python scripts/benchmark_ocr.py '../../documents/materials/Tutorial 4. Prolog.pdf' --pages 21 --output /tmp/ocr-benchmark/prolog.json
PYTHONPATH=. python scripts/benchmark_ocr.py '../../documents/materials/Tutorial 4. Prolog.pdf' --pages 21 --native-only --output /tmp/ocr-benchmark/native.json
```

Для baseline тот же скрипт запускается с `PYTHONPATH`, указывающим на отдельную
копию `course_graph` из исходного SHA. Скрипт не пишет в S3/PostgreSQL и не
вызывает HTTP-операции приложения.

## Проверки и ограничения качества

- `python -m pytest tests -q` — **118 passed**, один существующий
  Starlette/httpx deprecation warning. Запуск в отдельной копии кода в `/tmp`
  OCR-контейнера; серверный код не заменялся, веса тесты не скачивали.
- `docker compose --env-file ../../.env.example config --quiet` из
  `services/course-graph` — успешно.
- `git diff --check` — успешно.
- Доступность моделей подтверждена фактическим `/ready/models`: `ready=true`;
  дополнительно выполнены реальные конвертации Docling, включая VLM.
- При Prolog и псевдокоде изменившиеся фрагменты сверены с текстовым слоем
  и изображением соответствующей страницы PDF.
- Backend/frontend/gateway/shared не менялись, их проверки не запускались.
  DB-тесты не запускались; интеграция с БД и применение миграций не проверялись.
  Контракт HTTP/protobuf и миграции не менялись.
- Полные 28 PDF, сканы, таблицы, rotated pages и сквозной upload → S3 →
  граф не прогонялись. Для crop есть unit-проверки обеих систем координат,
  освобождения ресурсов и временного сбоя; отдельного реального benchmark
  формул с визуальным повтором здесь нет.
- На странице simulated annealing общий code enrichment всё ещё искажает
  название алгоритма, символ Δ и часть псевдокода. Эти ошибки присутствовали
  в baseline; теперь результат содержит предупреждение,
  `content_complete=false`, `work_complete=true`. Такой стабильный результат
  кешируется. Он требует проверки исходника и отдельного улучшения
  распознавания кода; считать весь материал достоверно распознанным нельзя.
- Синтаксически валидная формула не гарантирует совпадения с исходником.
  Экспертная разметка и precision/recall не получены. Постоянный кеш регионов,
  контрольные точки страниц и независимый кеш перевода не реализовывались.
  Fingerprint финального кеша учитывает настройки и версию алгоритма,
  но автоматически не хеширует содержимое локальных файлов весов.
