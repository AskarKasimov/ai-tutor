# ТЗ: достоверный и быстрый OCR учебных материалов

Дата: 18.10.2026. Основание: ревью `perf/course-graph-ocr-cache`, коммит `dea6c4a`, и решения владельца продукта в текущей сессии.

**Статус: план реализации. Этот документ не подтверждает, что перечисленные изменения уже выполнены.**

## 1. Цель и согласованные ограничения

Получать текст, формулы, код и таблицы из материалов курса, не подменяя неизвестное предположениями. Повторная обработка неизменного материала должна использовать сохранённый результат. Дорогая повторная работа допускается только для конкретных проблемных областей.

Принятые пользователем решения:

- Скорость приоритетна; стабильный неполный результат с предупреждениями разрешено кешировать.
- Нераспознанная формула не должна останавливать весь материал.
- Восстанавливать формулы по смыслу, памяти модели или названию алгоритма запрещено.
- Общего таймера на документ и стадию обработки нет: `0` означает отсутствие такого таймера. В Docling передаётся `None`.
- Работы над семантическим качеством графа не входят в это ТЗ. Проверяется лишь совместимость конвейера с полученным текстом.

Ограничение достоверности: OCR может ошибиться даже при распознавании изображения. ТЗ обеспечивает отсутствие отдельного механизма смыслового додумывания, прослеживаемость результата к исходнику и явный учёт неопределённости. Оно не обещает автоматическую безошибочность любой формулы из любого PDF.

## 2. Фактическая архитектура и границы работы

- Python `services/course-graph` выполняет OCR. Точки изменения: `ocr/converter.py`, `ocr/enrichment.py`, `ocr/pictures.py`, `ocr/formulas.py`, `ocr/jobs.py`, `api.py`, тесты.
- Docling закреплён на `2.139.0`; уже есть чтение текста того же PDF-прямоугольника через `NativePdfTextReader` и обёртка `AuditedEngine`.
- Backend оркестрирует обработку, сохраняет исходники/результаты в S3 и состояние в PostgreSQL. Python не пишет в эти хранилища напрямую.
- Перевод выполняет backend через LLM gateway; код и формулы защищает `translator/protected.go`.
- Текущий gRPC `Message` содержит текст, без изображений. Передача crop в gateway потребовала бы отдельного изменения контракта и обеих сторон. В обязательную реализацию это не входит.
- Визуальное распознавание формул выполняется существующим OCR-движком Docling по пикселям исходника. Произвольный новый HTTP-вызов модели напрямую запрещён.
- Существующие ручки сохраняются. Расширение отчёта оформляется в `api/course-graph.yaml` и проверяется на стороне backend.
- Студенческий Geek, формулы оценок и обход экзамена не меняются. Админка меняется точечно.
- Volumes, исходники, миграции и результаты пользователей не удаляются. Отключить вызов опасного восстановления можно без удаления его модуля.

## 3. Обязательные инварианты

1. Нет вызова текстовой LLM для создания, исправления или дополнения математической формулы.
2. Изменить можно только заранее идентифицированный регион исходника; соседний текст не переписывается.
3. Уже распознанные формулы, код и числа не меняются при обработке другой области.
4. У региона есть исходный документ, физическая страница, прямоугольник и метод получения результата.
5. «Синтаксически корректная LaTeX» не означает «совпадает с PDF». Согласие двух OCR-проходов также не объявляется доказательством.
6. Неуверенный результат не превращается в формулу на основании контекста. Остаётся маркер с координатами.
7. Каждая обнаруженная область формулы имеет один итоговый статус; потерянных областей нет.
8. Число маркеров в Markdown — отдельная метрика, а не доказательство полноты распознавания формул.
9. Стабильный неполный кеш возвращается без повторного inference. Причина неполноты видна пользователю.
10. Сбой одного региона не уничтожает результаты остальных страниц.
11. Ожидание сетевого сервиса и перевод не удерживают ресурсный слот Docling.
12. Перезапуск не приводит к повторному распознаванию уже завершённых регионов с тем же ключом.

## 4. Целевой конвейер

`исходник → проверка подходящего кеша → анализ страниц → layout/текст → регионы формул → адресное визуальное распознавание → проверки → сборка Markdown → сохранение → перевод защищённого текста → очистка/темы → граф`

### 4.1. Формулы

Для каждого региона:

1. Получить page/bbox из структуры документа до экспорта Markdown.
2. Проверить наличие пригодного текста именно этого прямоугольника.
3. Использовать native-текст только при выполнении проверенных критериев сохранения порядка символов, операторов и индексов. Одного наличия текстового слоя недостаточно.
4. Иначе распознать изображение региона штатным визуальным OCR.
5. Проверить пустой ответ, обрезание по токенам, структуру и признаки повреждения.
6. При проблеме выполнить максимум один дополнительный проход по тому же региону с другой настройкой изображения.
7. Если надёжный кандидат не получен — оставить `unresolved` или `suspect`, указать источник и причину.

Сначала основной визуальный проход, затем максимум один адресный повтор. Повторный полный OCR всего документа для исправления одной формулы запрещён.

`suspect` не публикуется как достоверная формула: кандидат остаётся в отчёте для проверки, в основном тексте — маркер. Это сознательный обмен части полноты на защиту от ложного учебного содержания.

### 4.2. Представление результата

Различать **статус обработки** и **проверенность содержания**:

| Поле | Значения / смысл |
| --- | --- |
| `status` региона | `recognized`, `unresolved`, `suspect`, `failed_transient` |
| `method` | `native_pdf`, `visual_ocr`, `visual_retry` |
| `verification` | `not_expert_validated`, `expert_validated`; второй статус — только после фактической проверки человеком |
| `reason_code` | Машинный код причины, не поиск слов в предупреждении |
| `work_complete` | Все плановые операции завершены; не равнозначно полноте содержания |
| `content_complete` | Нет известных нераспознанных/сомнительных областей; не гарантия отсутствия ошибок детектора/OCR |

Минимальная запись региона: `region_id`, `source_sha256`, `page`, `bbox`, система координат, `kind`, `status`, `method`, версия движка/весов, параметры изображения, число попыток, итоговый текст либо кандидат, `reason_code`, `verification`.

Дополнительно: хеш crop, результат доступных структурных проверок и реальные показатели уверенности движка, если он их предоставляет. Если движок confidence не отдаёт, поле равно `null`; выдумывать вероятность запрещено.

Новые поля добавляются внутрь существующего `report`, не заменяя `markdown` и старые `warnings`. Имена схемы для первого выпуска: `schema_version: ocr-report-v2`, `formula_regions`, `formula_summary`, `work_complete`, `content_complete`. В `formula_summary`: `detected`, `recognized`, `unresolved`, `suspect`, `failed_transient`, `marker_count`. Статистика считается из реестра, а не независимо обновляемыми счётчиками. Известная нераспознанная область изображения также делает `content_complete=false`, даже если все обнаруженные формулы распознаны.

Канонический bbox: PDF points, начало в левом верхнем углу страницы после применения её поворота; четыре значения `left, top, right, bottom`, плюс размеры страницы в той же системе. Преобразование из Docling/PDFium задаётся в одном адаптере. Физическая страница — с единицы. Для просмотра оригинала обратное преобразование проверяется отдельным тестом.

### 4.3. Маркеры и координаты

- Идентификаторы связываются с элементами Docling до текстового экспорта; не сопоставляются угадыванием одинаковых строк после экспорта.
- У каждого маркера отдельный ID. Буквальный пример служебного маркера в пользовательском TXT/Markdown не становится командой для OCR.
- Нераспознанную область сохранять в представлении, которое переводчик и очистка защищают целиком. Точный формат фиксируется тестами обеих сторон.
- Хранить физический номер страницы отдельно от напечатанного номера слайда.
- Для просмотра исходника достаточно исходного PDF и bbox: не создавать отдельную публичную раздачу изображений из Python.
- При сохранении кандидата не добавлять к нему по предположению недостающие операторы, индексы, коэффициенты, условия или скобки.

## 5. Кеш и восстановление после сбоев

### 5.1. Три уровня

1. Кеш результатов регионов: пригоден для адресного повтора и продолжения после сбоя.
2. Контрольная точка страниц: завершённые результаты и незавершённые регионы.
3. Финальный кеш документа: собранный Markdown и отчёт.

Кеш не должен потребовать второй модели или второй конвертации для собственного чтения. Его формат — версионированный и проверяемый.

### 5.2. Политика состояний

| Состояние | Что сохраняем | Обычный повтор |
| --- | --- | --- |
| Распознано | Итог региона и документа | Возврат из кеша |
| Стабильное `unresolved`/`suspect`, попытки выполнены | Частичный итог и предупреждения | Возврат из кеша, без inference |
| Временная ошибка движка / незавершённые страницы | Контрольную точку; доступный частичный результат не теряется | Продолжение только незавершённых регионов в рамках политики очереди |
| Изменилась версия алгоритма/весов | Старые данные сохраняются, ключ результата другой | Пересчёт только необходимых стадий |
| Явный адресный повтор администратором | Новую ревизию выбранных регионов | Не повторять остальные регионы |

Временные ошибки нельзя превращать в бессрочный «готовый» кеш. Устойчивую нераспознанность после разрешённых попыток нельзя автоматически повторять при каждом чтении кеша.

### 5.3. Ключи и совместимость

- Ключ содержимого: SHA-256 исходника + версия конвейера + версия layout/OCR + fingerprint весов + влияющие настройки.
- Ключ региона дополнительно содержит страницу/bbox/хеш crop и параметры попытки.
- Имя файла не определяет содержимое OCR. Заголовок, зависящий от имени, формируется отдельно при выдаче результата; кеш не должен возвращать имя другого загруженного файла.
- Перевод имеет независимый ключ: хеш OCR-текста + целевой язык + версия переводчика/защитных правил.
- Старый `ocr-v6-native-syntax` не переиспользуется вслепую: в нём могли сохраниться догадки LLM, а формат и ключ этого не различали. Безопасный первый выпуск — новое пространство ключей. Старые файлы не удалять.
- Повреждённая/оборванная запись кеша — cache miss с безопасным предупреждением, не бесконечное падение задачи.

## 6. Скорость и ресурсы

- Сначала проверка кеша; только при cache miss — ожидание необходимых моделей.
- Чистые TXT/Markdown не требуют моделей. На стороне backend уже есть соответствующий быстрый путь — сохранить его.
- Совпадение с пригодным native-кодом позволяет сохранить существующий обход генеративного обогащения; критерии не ослаблять.
- Для формул обход визуального OCR включать только для подтверждённых тестами классов native-представления. Остальные идут в визуальный путь.
- Не растеризовать документ целиком в повышенном разрешении ради нескольких формул. Рендерить страницы/области по необходимости, освобождать изображения после использования.
- Начальная схема адресного повтора: базовый crop 144 DPI, единственный повтор 216 DPI с дополнительными 4 pt по периметру. Это стартовые параметры для измерения, не заявление об оптимальности; поправки записать после прогона набора.
- Одновременно работает один экземпляр тяжёлой Docling-конвертации. Если crop inference использует тот же mutable engine, он входит в тот же ресурсный лимит. Два независимых semaphores не должны случайно запускать его параллельно.
- Пакетное распознавание регионов разрешено только при поддержке engine; порядок выходов и память проверяются. Начальный batch — 1, дальнейшее увеличение — по измерению.
- CPU: сохранить float32/KV-cache и CPU wheels, проверять фактические параметры runtime. Не добавлять CUDA-зависимости в CPU-образ.
- Перевод и любые сетевые стадии выполняются вне блокировки Docling. Число переводов ограничено существующим worker pool.
- Для одинаковых одновременных запросов нужен singleflight по ключу содержимого, не только по ID HTTP-задачи. Разные загрузки имеют свои ID/права, но могут переиспользовать вычисление OCR.
- Не разрезать формулы/код при переводе и не повышать параллельность до роста RSS/OOM.
- Никакого общего таймера в 5/10/20 минут. Есть границы числа повторов, ресурсов, размеров и конкретных сетевых запросов.

## 7. Атомарный план реализации

Каждая задача закрывается наблюдаемым результатом. Коммит может объединять только тесно связанные задачи, если сохранена возможность отдельно проверить каждую. Обязательны этапы A–J; этап K выполняется после измерения необходимости.

### A. Зафиксировать исходную точку

- [ ] **A01.** Записать SHA ветки и master в отчёт. Готово: результат воспроизводится без зависимости от движущегося имени ветки.
- [ ] **A02.** Снять версии Python, Docling, torch, весов и конфигурацию CPU. Готово: сохранён fingerprint окружения без секретов.
- [ ] **A03.** Зафиксировать CPU/RAM/лимиты контейнера. Готово: сравнения производительности относятся к одному окружению.
- [ ] **A04.** Составить manifest PDF из `documents/materials` с SHA-256 и числом страниц. Готово: каждый тестовый исходник однозначно идентифицируется.
- [ ] **A05.** Выбрать PDF с native-формулами, сканами, кодом, таблицами и картинками. Готово: ни один класс не представлен только обычным текстом.
- [ ] **A06.** Подготовить ручную разметку регионов формул с page/bbox/ожидаемой записью. Готово: ожидаемый ответ получен визуально из PDF, не генерацией LLM.
- [ ] **A07.** Выделить отдельную контрольную часть набора, не используемую для подбора настроек. Готово: есть проверка вне настроечного набора.
- [ ] **A08.** Измерить baseline холодного OCR с готовыми весами. Готово: сохранены времена по файлам, страницам, число формул, RSS и предупреждения.
- [ ] **A09.** Отдельно измерить загрузку весов на пустом model cache. Готово: это время не смешано с конвертацией.
- [ ] **A10.** Измерить повторное чтение кеша. Готово: известны latency и фактические счётчики inference/сетевых запросов.

### B. Перекрыть смысловое додумывание

- [ ] **B01.** Отключить вызов `recover_formulas` через `ModelClient` из `run_ocr_job`. Готово: OCR с маркером делает ноль обращений к текстовой LLM.

- [ ] **B03.** Ввести новую версию/пространство кеша. Готово: старый результат с формулой, придуманной LLM, не попадает в новый конвейер.
- [ ] **B04.** Добавить тест запрета внешнего completer для OCR. Готово: любая попытка вызвать его в OCR-тесте приводит к падению теста.
- [ ] **B05.** Добавить регрессию на изменение соседнего числа, формулы и заголовка. Готово: обработка проблемного региона сохраняет остальное побайтно.
- [ ] **B06.** Добавить регрессию границы слайдов. Готово: `## Слайд 2` остаётся началом отдельной строки независимо от результата предыдущего региона.

### C. Описать регионы и отчёт

- [ ] **C01.** Ввести тип записи региона и перечисления из раздела 4.2. Готово: некорректные состояния отвергаются схемой.

- [ ] **C03.** Формировать стабильный `region_id`. Готово: тот же исходник и layout дают те же ID после перезапуска.
- [ ] **C04.** Собирать реестр формул до Markdown-экспорта. Готово: две одинаковые текстовые заглушки имеют разные source-привязки.
- [ ] **C05.** Считать итоговые статусы по реестру. Готово: сумма статусов равна числу обнаруженных регионов.
- [ ] **C06.** Разделить количество маркеров и количество нерешённых регионов. Готово: формула без маркера, но с признаком повреждения не считается автоматически успешной.
- [ ] **C07.** Ввести структурированные `reason_code` и предупреждения. Готово: логика кеша не ищет слово «частично» в русском тексте.
- [ ] **C08.** Добавить версию схемы отчёта. Готово: читатель различает старый и новый формат.
- [ ] **C09.** Описать расширение отчёта в `api/course-graph.yaml`. Готово: схемы и примеры соответствуют фактическому ответу.

### D. Безопасно использовать native-текст

- [ ] **D01.** Чтение native-текста ограничить тем же page/bbox. Готово: соседняя формула не попадает в регион.
- [ ] **D02.** Проверить нормализацию Unicode и недопустимые символы. Готово: повреждённые шрифтовые кодировки не принимаются за пригодный текст.

- [ ] **D05.** Сохранить существующий native-fast-path кода. Готово: Prolog `:-`, отступы, кавычки и экранирование остаются неизменными.
- [ ] **D06.** Проверить формулы с похожими символами: `1/l/I`, `0/O`, минус/тире, греческие буквы. Готово: неоднозначность не устраняется заменой по смыслу.

- [ ] **E01.** Исследовать точку штатного вызова `CodeFormulaVlmModel` для регионов Docling 2.139.0. Готово: минимальный эксперимент распознаёт реальный crop без текстового completer.

- [ ] **E04.** Связать первичное обогащение Docling с реестром регионов. Готово: успешная формула не проходит второй inference при экспорте.

- [ ] **E06.** Добавить структурные проверки LaTeX без смыслового ремонта. Готово: несбалансированные конструкции и явно оборванные выражения помечаются, а не дописываются.
- [ ] **E07.** Ввести максимум один дополнительный crop-проход. Готово: счётчик вызовов одного региона никогда не превышает установленный лимит.

- [ ] **F01.** Выделить единый расчёт fingerprint. Готово: изменение влияющей настройки меняет ключ; не влияющей — не инвалидирует OCR.

- [ ] **F04.** Валидировать запись при чтении. Готово: неверная схема/хеш/версия приводит к cache miss и диагностике.
- [ ] **F05.** Кешировать итоговый `unresolved`/`suspect`. Готово: повторный запрос не вызывает inference этих регионов.

- [ ] **F13.** Отделить общий кеш содержимого от привязки к материалу/курсу. Готово: две загрузки могут разделять вычисления, но не получают чужие имена, S3-ключи, material ID или права доступа.

- [ ] **G01.** Отделить чтение готового кеша от тяжёлого OCR-слота. Готово: кешированный файл не ждёт долгую конвертацию другого файла.

- [ ] **G03.** Исключить сетевые `await` из тяжёлого OCR-слота. Готово: задержка переводчика/gateway не задерживает свободный OCR следующего файла.
- [ ] **G04.** Обновлять heartbeat независимо от длительного inference. Готово: backend сохраняет владение задачей на протяжении долгой страницы.
- [ ] **G05.** Проверить штатную остановку и возврат задачи. Готово: нет публикации устаревшим владельцем и потери контрольной точки.
- [ ] **G06.** Сохранить отключённые общие таймеры. Готово: тест длительной операции не обрывается из-за общего лимита стадии.
- [ ] **G07.** Ограничить очередь ожидающих операций и расход памяти. Готово: 48 загрузок не держат 48 распакованных документов/растров одновременно.
- [ ] **G08.** Измерить batch 1 против небольшого поддерживаемого engine batch. Готово: выбран вариант с измеренным выигрышем без ухудшения точности/RSS; значение не повышается вслепую.
- [ ] **G09.** Сделать допуск PDF в backend cache-aware. Сейчас `OCRWorker` может не забирать PDF при неготовых моделях, ещё до вызова Python. Готово: существующий финальный кеш можно получить сквозным запросом через backend при недоступных моделях; cache miss ожидает подготовку без расходования попыток и без блокировки TXT/Markdown. - [ ] **G10.** Ограничить удержание входных файлов до конвертации. Готово: ожидающие загрузки используют ограниченный spool/очередь, а не неограниченный набор прочитанных `bytes`; лимиты входа и временные файлы имеют явный жизненный цикл.

## 8. Матрица обязательных проверок

| Сценарий | Ожидаемый результат |
| --- | --- |
| PDF с точным native-кодом | Код сохранён дословно; нет лишнего генеративного прохода |
| PDF с native-формулой и повреждённым порядком индексов | Нет слепого fast-path; визуальный путь или `suspect` |
| Формула только на изображении | Есть crop/source-привязка; попытки только по этому изображению |
| Неоднозначная MSE: `1/n` против `1/(2n)` | Коэффициент не выбирается по названию алгоритма |
| LP: `2x_1 + 4x_2`, ограничения и знаки неравенств | Каждый существенный символ сверяется с эталоном; синтаксическая правдоподобность не заменяет сверку |
| Дроби, степени, индексы, суммы с пределами, матрицы, кусочные функции | Нет потери структуры; неудача учтена в реестре |
| Формула выглядит синтаксически правильно, но OCR потерял знак | Ловится размеченным контрольным набором; нет ложного заявления о гарантии runtime-проверок |
| Два одинаковых маркера на странице | Два разных ID/bbox; замены не перепутаны |
| Буквальный маркер в примере кода/Markdown | Не запускает реконструкцию и не изменяется |
| Ответ движка пуст/обрезан | Не считается успешно распознанным |
| Сбой движка в одном регионе | Остальной документ сохранён, регион имеет причину сбоя |
| Повтор стабильного `unresolved` | Ноль новых inference |
| Второй upload того же содержимого с другим именем | OCR переиспользован, отображается актуальное имя |
| Два разных job ID одновременно, одинаковый исходник | Один OCR, два корректных результата/контекста загрузки |
| Кеш повреждён | Пересчёт без постоянного падения, исходник сохранён |
| Веса недоступны, финальный кеш есть | Быстрый ответ без ожидания bootstrap |
| Gateway недоступен | OCR завершается; перевод даёт существующий безопасный fallback |
| Остановка посередине длинного PDF | После запуска продолжение с контрольной точки |
| Утрата lease/token | Старый worker не публикует новый результат |
| 48 загрузок | Нет утраты/смешивания исходников, неконтролируемого RSS и голодания очереди |
| Пропала формула при очистке/переводе | Регрессионный тест падает; публикация результата с нарушением защиты не проходит |
| Повторный запуск Docker с сохранёнными volumes | Веса и результаты переиспользуются; скачивание подтверждается счётчиками/логами |

Реальные три `Optimization_Lecture_*.pdf` из прежнего обратного отчёта сейчас недоступны. Их успешную обработку заявлять нельзя. Для LP/анимационных страниц создать отдельные контролируемые примеры, а реальные материалы проверять из manifest A04.

## 9. Критерии качества и производительности

Пороговые значения ниже — цели приёмки, не измеренный результат текущей ветки.

### Жёсткие критерии

- Ноль вызовов текстовой LLM для восстановления формул.
- Ноль изменений текста вне адресуемых регионов в регрессионном наборе.
- Ноль потерянных страниц, исходных code-spans и обнаруженных регионов формул.
- Ноль тихих потерь формул/маркеров при переводе и очистке.
- Все нерешённые и сомнительные области имеют page/bbox/reason; пропуски детектора проверяются отдельно ручной разметкой.
- Повтор готового кеша: ноль OCR/formula inference и ноль запросов перевода при готовом translation cache.
- Ни одного старого кеша со смысловой реконструкцией в новом пространстве результатов.

### Контроль качества

- На контрольном наборе критических математических примеров все коэффициенты, операторы, индексы и ограничения совпадают с визуально проверенными эталонами либо явно оставлены нерешёнными.
- Отдельно считать долю правильных формул среди **всех размеченных** формул, полноту обнаружения и долю `unresolved`/`suspect`. Нельзя получить «100% точности», исключив все сложные формулы из знаменателя.
- Доля полностью правильно распознанных формул на отложенном наборе не ниже baseline; включать новую оптимизацию, снижающую этот показатель, запрещено.
- Для пригодного native-кода и TXT/Markdown — дословное сохранение с отдельно оговорённой нормализацией перевода строк.
- Не менее 50 вручную размеченных формул из минимум трёх PDF плюс синтетические пограничные примеры. Это минимальный регрессионный набор, не статистическая гарантия качества на произвольных курсах.

### Скорость

- Для повторного чтения документного кеша до 20 страниц и JSON-результата до 10 MiB: целевой p95 внутри course-graph ≤ 2 с на зафиксированном локальном окружении. S3, загрузка файла и frontend измеряются отдельно.
- Для PDF с пригодным текстовым слоем: целевой median времени OCR ≤ 70% baseline. Если цель не достигнута, отчёт должен назвать реальное узкое место; не объявлять оптимизацию завершённой только по отсутствию ошибок.
- Для сканов и насыщенных математикой PDF: время не более 110% baseline при неухудшенном качестве. Если адресные повторы выходят за пределы, параметры пересматриваются по контрольному набору, а не отключением учёта пропусков.
- При обработке пакета публикуются wall time, время каждого файла, p50/p95 регионов, число inference, hit/miss и peak RSS. Для малого пакета из пяти файлов не делать выводов о статистически устойчивом p95 по документам.
- Длительность 20 минут и более сама по себе не считается сбоем. Критерий сбоя — ошибка/потеря владения/нет корректного результата; прогресс и активная операция должны наблюдаться.

## 10. Порядок внедрения и точки остановки

Зависимости этапов: A предшествует сравнительным измерениям; B выполняется сразу после фиксации исходной точки. C нужен для D/E и новых записей F. D и E сходятся в F; G использует F и проверяется вместе с backend. H использует новый формат C/F. I использует C/F/H. J завершает весь конвейер. Проверки и CI добавляются вместе с соответствующим изменением, а не откладываются до конца J. Секция K не блокирует обязательную функциональность.

1. **Безопасный минимальный выпуск:** A, B, C и F05/F08/F11. Убирает додумывание и закрепляет быстрый стабильный кеш. Формулы, не распознанные прежним OCR, остаются явно нерешёнными.
2. **Распознавание по исходнику:** D, E, остальная F и G. Включать после сравнения качества с baseline.
3. **Сквозная сохранность:** H, I, J. Завершает защищённый перевод, просмотр проблем и адресный повтор.
4. **Дополнительная экономия:** K только при доказанном выигрыше.

Эти выпуски не равны завершению всего ТЗ. Для итоговой приёмки обязательны A–J и критерии раздела 9. Нельзя объявлять проект «полностью рабочим» после одного зелёного unit-теста или одного удачного файла.

## 11. Команды проверки и итоговый отчёт исполнителя

- Course-graph: `python -m pytest tests`.
- Backend при изменениях интеграции/перевода/очереди: `go test -race ./... -count=1`, `go vet ./...`, `go build -o bin/api ./cmd/api`; DB-тесты с реальным `TEST_DATABASE_URL` и изоляцией схем.
- Frontend при изменениях админки: `npm run format:check`, `npm run lint`, `npm run typecheck`, `npm test -- --run`, `npm run build`.
- OpenAPI: обновление источников и проверка генерации backend; сгенерированные файлы не править вручную.
- Compose: проверки с `.env.example`/`.env.prod.example` из AGENTS.md; `sh -n prod.sh`, `sh -n dev.sh` при изменениях запуска.
- Gateway/shared не менять для обязательного визуального OCR-пути. Если отдельное решение всё же меняет их контракт, выполнять проверки обеих сторон по локальным AGENTS.md.
- `git diff --check` и отсутствие секретов/весов/исходных пользовательских PDF в новых коммитах.

Исполнитель прикладывает: SHA, manifest, конфигурацию, результаты тестов, таблицу качества/времени «до/после», результаты пяти файлов, подтверждение рестарта и список оставшихся `unresolved`/`suspect`. Пропущенные проверки, в том числе DB без `TEST_DATABASE_URL`, называются прямо. Доступность моделей подтверждается фактическим запросом; чтение конфигурации и `/health` её не доказывают.
