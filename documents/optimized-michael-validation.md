пререквизитов после глобального гибридного поиска. Ветка `optimized_Michael`.
Запросы выполнялись реальной настроенной `gpt-oss-120b` через backend gRPC;
embeddings — `intfloat/multilingual-e5-small` на CPU.

## Проверка на notebooks

Источник: `notebooks/Dataset_100%__topics+pr+oc__v4.1.pdf/topics_reviewed_v2.json`.
Для поиска импортированы 110 карточек с непустым `clean_core_fragments`; всего
в датасете 137 карточек. Карточки без основного текста, включая RPD-only,
не использованы как доказанные учебные вершины. Разметка этого набора не является
экспертным эталоном зависимостей; часть `provides` шире фактического текста страниц.

На 110 карточках поиск обработал 205 требований за 10.6 секунды с загрузкой
embedding-модели. Отобрано 1025 кандидатов по требованиям, 960 уникальных
направленных пар тем. Полный перебор составил бы 11990 направленных пар.
Это сравнение объёма кандидатов, а не доказательство такого же ускорения по времени.
Векторный поиск сейчас точный, со сканированием индекса: вычисления поиска могут
расти квадратично; сокращается прежде всего работа LLM.

Второй проход проверен на четырёх целевых темах из общего каталога 110:
`AI-04-07`, `AI-04-08`, `AI-03-09`, `AI-08-07` — 11 требований, 55 кандидатов.
Получены 3 связи и 8 неподтверждённых требований за 53.36 секунды, 13 запросов

и реальные цитаты не доказывают педагогическую необходимость ребра.

## Какие проблемы исправлены по результатам прогонов

1. Отдельный ID на каждый короткий пункт слайда приводил к пропускам. Короткие
   слайды сгруппированы с сохранением исходных координат. Пропущенные ID явно
   возвращаются модели для исправления; затем порция при необходимости дробится.
2. Сравнены порции 4000 и 6000 символов на двух документах. На промежуточной
   версии D27: 20.73/29.64 секунды; D17: 23.97/18.89 секунды. Более крупная
   порция не всегда лучше. После ужесточения требований к вопросам итоговый
   D27/6000 занял 70.88 секунды: 13 тем, 14 сохранённых блоков, ноль непривязанных,
   четыре запроса. Ранние лучшие времена не выдаются за гарантированную скорость
   окончательной версии. Default 6000, серверная настройка
   `COURSE_GRAPH_TOPIC_MAX_CHARS`, автоматическое дробление при ошибках.
3. Модель генерировала вопрос о названии вводного слайда. Промпт уточнён;
   такие вопросы отклоняются и отправляются на исправление, обложка привязывается
   к содержательной теме.
4. При группировке благодарность приклеивалась к учебному тексту и сохранялась
   как смешанный блок. Вероятные организационные абзацы теперь остаются отдельными;
   решение об удалении всё равно принимает LLM. Регрессия покрыта тестом и
   повторным сквозным прогоном.
5. Проверка цитат ошибочно считала перенос строки OCR изменением текста.
   Допускаются только различия пробелов/переносов, после проверки сохраняется
   точный исходный фрагмент. Изменение слов не допускается.
6. Простое упоминание дифференцируемости давало лишнюю связь с обучением
   backpropagation. Промпт требует, чтобы кандидат действительно объяснял
   требуемое знание, а не сам использовал его. В повторной выборке лишнее ребро
   больше не добавилось. Это частная проверка, не общая гарантия качества модели.

Локальные JSON-артефакты и сырые ответы:
`notebooks/optimized_michael_validation/` (каталог игнорируется Git по действующим
правилам репозитория). Воспроизводимые команды находятся в
[README сервиса](../services/course-graph/README.md).

## Промежуточная проверка исходных PDF, 16.10.2026

Добавлен `scripts/validate_pdfs.py` для загрузки исходных PDF через backend,
сохранения промежуточных результатов OCR и перевода на русский и проверки

и изображениях. Настройка float32 для обогащения требует проверки скорости
на исходных документах; успешный сквозной результат для них пока не заявляется.

Перевод при загрузке подключён к общему клиенту LLM. Повторная локальная проверка:
39 Python-тестов прошли, выбранные Go-тесты затронутых пакетов и OpenAPI прошли.
Этот повторный запуск не включал интеграционные тесты с БД; результаты более
ранних проверок БД выше относятся к состоянию до последних изменений OCR
и подключения перевода к общему клиенту.

## Границы реализации

Дубли объединяются по одинаковому нормализованному названию; семантическое
объединение синонимов не реализовано. Номер недели отсутствует в текущем
контракте загрузки и без явных метаданных остаётся `null`. Старые материалы без
задач очистки автоматически не ставятся в очередь. Для уже готовых старых
отчётов без карточек worker умеет выполнить выделение тем заново при сборке.
Экспертная оценка качества и настройка recall поиска на размеченных зависимостях
остаются необходимой следующей проверкой, а не скрытой частью готового результата.
