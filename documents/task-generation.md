# Генерация тренировочных заданий по аналогии

Это расширение **вне MVP**. Базовый сценарий MVP использует только готовые задания
преподавателя и при неполном банке тренировки выдаёт доступные задания с причиной
`tasks_exhausted`. Данный документ описывает отдельную возможность: по выбранной теме
(образовательный результат, ОР) из импортированной карты компетенций построить новые
**тренировочные** задания, аналогичные уже имеющимся заданиям этой темы.

## Назначение и границы

- **Тема — это ОР.** Отдельной сущности «тема» нет (см. `CONTEXT.md`). Карта компетенций
  хранит `competencies → constituents → outcomes → tasks(question, criteria)`.
- Образцами для генерации служат **готовые задания выбранного ОР** из текущей карты.
  Если у ОР нет ни одного задания, генерация отклоняется: аналогию не из чего строить.
- Сгенерированные задания — **черновой тренировочный материал**. Они не публикуются в банк,
  не участвуют в диагностике, не влияют на диагностический балл и **не сохраняются** в БД
  (по аналогии с прототипной ручкой оценки). Повторный запрос создаёт новый набор.
- Генерацию выполняет та же OpenAI-совместимая модель, что и прототипную оценку
  (`ASSESSMENT_BASE_URL`, `ASSESSMENT_MODEL`, `ASSESSMENT_TIMEOUT`). Отдельные переменные
  окружения не вводятся.
- Технический сбой генерации — это **не** учебный результат и **не** ноль баллов. Клиент
  показывает ошибку и позволяет повторить запрос.

## HTTP API

Обе ручки защищены `access_token` cookie (`protect(auth, …)`).

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/outcomes` | Темы текущей карты с числом готовых заданий. |
| `POST` | `/outcomes/{outcomeId}/training-tasks` | Сгенерировать новые задания по теме. |

`GET /outcomes` возвращает `{"outcomes":[{"id","name","constituent_name","competency_name","task_count"}]}`.

`POST /outcomes/{outcomeId}/training-tasks` принимает `{"count": 1..5}` (по умолчанию 3) и
возвращает `{"outcome_id","outcome_name","tasks":[{"question","criteria","voice_instruction","options"}]}`.
`options` — всегда массив (пустой, если задание открытого типа).

Коды ошибок: `401` без сессии, `404 OUTCOME_NOT_FOUND` для неизвестной темы,
`404 OUTCOME_TASKS_EMPTY` если у темы нет заданий-образцов, `422` при некорректном `count`,
`502/503/504` при сбое модели.

## Правила генерации на сервере

1. Загрузить ОР и его задания (`question`, `criteria`) как образцы. Критерии передаются
   модели как есть, без интерпретации.
2. Запросить ровно `count` новых заданий, сохраняющих тему, уровень и формат образцов, но
   отличающихся формулировкой и предметным содержанием.
3. Проверить ответ модели: ровно `count` заданий; непустые `question` (≤ 5000), `criteria`
   (≤ 2000), `voice_instruction` (≤ 500); не более 12 вариантов по ≤ 500 символов; ни один
   вопрос не повторяет образец или другое сгенерированное задание (сравнение без учёта
   регистра и повторных пробелов). Несоответствие → `502 TASK_GENERATION_FAILED`.

## Frontend

Экран `/training` (`src/routes/training.tsx`) даёт выбрать тему и число заданий, вызывает
генерацию и показывает полученные задания. ОР без образцов нельзя выбрать для генерации.
Ответ на задание использует тот же голосовой контур, что и прототип (`useTrainerPrototype`):
запись → STT → оценка `0/1/2` с объяснением. Критерии сгенерированного задания передаются
модели как эталон для оценки и не показываются студенту. Клиентский слой данных:
`src/data/task-generation-api.ts` и `src/data/use-training-tasks.ts`.
Ссылка на экран добавлена в шапку прототипа (`/`).

## Проверка

- Юнит-тесты `features/taskgen/...` и `internal/app/taskgen_test.go` проверяют граундинг на
  заданиях темы, валидацию `count`, обязательность образцов и отбраковку некорректного
  ответа модели, а также коды `401/404`.
- Frontend-тесты `task-generation-api.test.ts` и `training.test.tsx` проверяют разбор ответа
  и отображение сгенерированных заданий.
