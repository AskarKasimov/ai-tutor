# Голосовой тренажёр

Состояние: 7 октября 2026. [Видение и термины](../README.md), [единый API](../api/openapi.yaml).

## Сейчас

Frontend использует семь фиксированных mock-заданий и хранит прогресс в памяти вкладки. В real-режиме auth, STT/TTS и прототипное assessment используют backend. Backend также собирает и сохраняет варианты; frontend пока их не запрашивает. TTS озвучивает вопрос и варианты.

Преподаватель может импортировать карту ML CSV/XLSX. Отдельный taskgen создаёт и сохраняет новые задания через LLM; импорт материалов реализован. Действующие модули сохраняются.

## Целевой сценарий

1. Преподаватель добавляет полные задания в текущую карту и увеличивает число ОР с TRUE. Формат прежний; ручных связей и дополнительных документов для сборки не требуется.
2. Студент создаёт вариант по всей карте без выбора темы. Первичный фильтр требует минимум три разных готовых TRUE-ОР. После выбора основного включаются только компетенции, где есть два готовых TRUE-ОР с меньшим рангом Блума для базовых. Недостаточные компетенции пропускаются с причиной. Если ни одна не подходит, вариант не создаётся.
3. Основной ОР выбирается по максимуму суммы Блума и важности; равенство суммы разрешается большей важностью. Случайно выбирается только конкретный аналог внутри выбранного ОР.
4. Вариант сохраняется со снимками заданий и профилей. Повторное чтение возвращает выбранные задания, в том числе после переимпорта карты.
5. Модуль прохождения принимает голосовой ответ и вызывает грейдинг. Основной с оценкой 2 пропускает базовые, с 0/1 требует базовых. Основной оценивается в 0/1/2, базовый — в 0/1.
6. Диагностическая сумма учитывает только основные задания включённых компетенций; максимум 2N. Технический сбой не превращается в учебный ноль; непроверенный ОР не объявляется пробелом.
7. Тренировка работает по проверенным пробелам и не изменяет исходную диагностику.

## Ответственность модулей

Variantgen реализует создание, список, чтение варианта и чтение отдельной позиции. Публичное чтение сразу возвращает main и оба basic без эталонов, criteria, ОС и сырого снимка; внутренний reader предоставляет полные данные и связанные свойства грейдингу. Чтение позиции не выбирает новое задание и не управляет показом базовых.

Приём ответов, оценки, очередность предъявления и тренировка реализуются другим разработчиком. Их HTTP-контракт определяется отдельно. Согласование голосовой инструкции при интеграции также относится к прохождению.

Правила отбора — [алгоритм](Алгоритм_составления_варианта.md); HTTP-контракт — [OpenAPI](../api/openapi.yaml).
