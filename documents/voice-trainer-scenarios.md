# Голосовой тренажёр

Состояние: 9 октября 2026, целевой сценарий обновлён по решениям встречи 10 октября 2026. [Видение и термины](../README.md), [решения встречи](ai-journey-plan.md), [единый API](../api/openapi.yaml).

## Сейчас

В real- и mock-режимах frontend использует один экран диагностики и одни API-модули. В real карточка курса предлагает одно действие «Начать/Продолжить обучение»; явная кнопка запуска создаёт вариант и сессию на backend, показывает задания карты и отправляет аудио в API. Диагностики, ответы, тренировки и история чата сохраняются в PostgreSQL. В mock те же typed-контракты обслуживаются демонстрационными данными в памяти; grading, transcript и audio не отражают оценку реального ответа, а новый вход сбрасывает демо.

Преподаватель может импортировать карту ML CSV/XLSX. Отдельный taskgen создаёт и сохраняет новые задания через LLM; импорт материалов реализован. Действующие модули сохраняются.

## Целевой сценарий

Решения встречи 10.10.2026 для AI Journey. Отличия от текущей реализации перечислены в [ai-journey-plan.md](ai-journey-plan.md).

1. Преподаватель добавляет полные задания в текущую карту и увеличивает число ОР с TRUE. Формат прежний; ручных связей и дополнительных документов для сборки не требуется. В демо-сценарии загрузка карты не показывается: карта будет генерироваться отдельными процессами.
2. Студент выбирает предмет и начинает один процесс: проверка → итог → план → тренировка. Отдельного выбора «Диагностика» или «Тренировка» нет.
3. Вариант строится по всей карте без выбора темы из готовых TRUE-ОР с допустимыми таксономией и важностью. На компетенцию выбираются основной и ровно два базовых разных ОР; компетенция с меньше чем тремя такими ОР пропускается с причиной. Если ни одна не подходит, вариант не создаётся.
4. При сравнении ОР для выбора основного таксономия важнее важности: основной — наибольший ранг Блума, при равенстве — большая важность. Базовые — два самых простых из остальных ОР (`competency-map-v4`). Случайно выбирается только конкретный аналог внутри выбранного ОР.
5. Вариант сохраняется со снимками заданий и профилей. Повторное чтение возвращает выбранные задания, в том числе после переимпорта карты.
6. Студент отвечает голосом на все задания, включая multiple choice: называет вариант словами и объясняет. Кнопка микрофона обязательна. Голос наставника — мужской, взрослый, низкий.
7. Backend диагностической сессии принимает голосовой ответ и вызывает assessment application с variant ID и ID позиции. Грейдер получает сохранённый снимок и роль. Основной оценивается в 0/1/2, basic — в 0/1; сессия использует роль-зависимую оценку без преобразования. Основной с оценкой 2 пропускает базовые, с 0/1 требует базовых. После ответа балл и вердикт студенту не показываются; прогресс — status bar в процентах, выполненные задания «схлопываются».
8. Итог — общий фидбэк: в каких компетенциях всё хорошо и какие темы не освоены, с указанием ОР. Балл и пометка «Не проверено» не показываются. Внутренняя диагностическая сумма учитывает только основные задания включённых компетенций, максимум 2N. Технический сбой не превращается в учебный ноль; непроверенный ОР не объявляется пробелом.
9. После итога студента спрашивают, сколько у него есть времени на тренировку; до AI Journey этот шаг не показывается. Затем выдаётся план «тема — ОР» с временем на теорию и на отработку и кнопка «Начать тренировку».
10. Тренировка работает по проверенным пробелам и не изменяет исходную диагностику. По завершении — обратная связь, прогресс-бар слева и кнопка «Продолжить тренировку». Стратегию тренировки, правила теории и практики и промпты генерации заданий и теории готовит Марина.

## Реализованное API сессии

Состояние сессии и принятые ответы хранятся в PostgreSQL и переживают перезапуск backend. Реализованы запуск, чтение прогресса, сохранённая озвучка инструкции, голосовой ответ и результат диагностики. Отправка ответа требует `Idempotency-Key`; повтор принятого запроса возвращает сохранённый результат. Истёкшая lease позволяет повторить обработку после сбоя.

Сессия вызывает assessment application; в mock используется mock grader, в real — настроенный model grader. Ошибки STT/grading не записывают score и не меняют позицию. Frontend показывает диагностику и её общий фидбэк, позволяет выбрать предмет/действие и подключает preview и прохождение тренировки.

## Предметный frontend flow

Ниже описано текущее поведение; по решениям встречи 10.10.2026 preview будет заменён планом «тема — ОР».

Главная не создаёт вариант при загрузке или выборе предмета. Отдельной плитки тренировки нет: одна кнопка «Начать обучение» запускает диагностику, «Продолжить обучение» возвращает туда, где студент остановился, — в незавершённую диагностику или в тренировку. Тренировка требует завершённую диагностику этого предмета; preview показывает точные категории «Неосвоенные темы» и «Частичные пробелы в знаниях», либо «Свободная тренировка». Продолжение использует сохранённые цели и упражнения. В real это состояние переживает перезапуск благодаря PostgreSQL; браузерный mock сбрасывает демонстрационные данные при новом входе. Аналогичные упражнения, генерируемые LLM, остаются будущим отдельным provider; текущий сценарий не обещает каждый раз новое содержание.

## Ответственность модулей

Variantgen реализует создание, список, чтение варианта и чтение отдельной позиции. Публичное чтение сразу возвращает main и два basic (в снимках `competency-map-v1`/`v2` — от нуля до двух) без эталонов, criteria, ОС и сырого снимка; внутренний reader предоставляет полные данные и связанные свойства грейдингу. Чтение позиции не выбирает новое задание и не управляет показом базовых.

Приём ответов и порядок диагностики реализованы модулем `diagnostic`, итоговый фидбэк — `diagnosticfeedback`, тренировка — `training`. Перед запуском тренировки backend preview возвращает «Неосвоенные темы» и «Частичные пробелы в знаниях»; frontend автоматически создаёт новую сессию или сразу открывает существующую. Без завершённой диагностики запуск возвращает конфликт. При отличном результате режим свободный и включает все готовые TRUE-задания выбранного предмета. После последней цели начинается новый раунд; выход из экрана не завершает сессию. Чат упражнений, проверки и попытки сохраняются отдельно от исходной диагностики. Под инструкцией упражнения студент пишет или записывает голосовую реплику; репетитор помогает вопросами и подсказками. Обычная реплика не создаёт попытку и не меняет упражнение. «Проверить ответ» запускает отдельную оценку 0/1/2 на backend, без показа балла студенту. После новой реплики требуется повторная проверка. Переход выполняется явно через «Следующий раунд»; предыдущий диалог доступен только для чтения.

Тренировочный чат поддерживает текст и голос. Server Tutor использует отдельный Socratic prompt из версии `training-tutor-v1`; student content всегда передаётся как пользовательские данные. Сервер сохраняет исходную реплику, STT transcript, статус retry/cancel и результат атомарно. Ошибка STT/assessment/Tutor не создаёт попытку с нулевым баллом. Настройки Tutor задаются через `BACKEND_TUTOR_*`; URL и модель по умолчанию наследуются от assessment. При выключенном Tutor чтение истории доступно, а отправка возвращает 503.

Правила отбора — [алгоритм](Алгоритм_составления_варианта.md); HTTP-контракт — [OpenAPI](../api/openapi.yaml).
