# Голосовой тренажёр

Состояние: 9 октября 2026. [Видение и термины](../README.md), [единый API](../api/openapi.yaml).

## Сейчас

В real- и mock-режимах frontend использует один экран диагностики и одни API-модули. В real студент выбирает предмет и действие; явная кнопка запуска создаёт вариант и сессию на backend, показывает задания карты и отправляет аудио в API. Диагностики, ответы, тренировки и история сохраняются в PostgreSQL. В mock те же typed-контракты обслуживаются демонстрационными данными в памяти; grading, transcript и audio не отражают оценку реального ответа, а новый вход сбрасывает демо.

Преподаватель может импортировать карту ML CSV/XLSX. Отдельный taskgen создаёт и сохраняет новые задания через LLM; импорт материалов реализован. Действующие модули сохраняются.

## Целевой сценарий

1. Преподаватель добавляет полные задания в текущую карту и увеличивает число ОР с TRUE. Формат прежний; ручных связей и дополнительных документов для сборки не требуется.
2. Студент создаёт вариант по всей карте без выбора темы. Для включения достаточно одного готового TRUE-ОР с допустимыми таксономией и важностью. К основному добавляются до двух готовых TRUE-ОР с меньшим рангом Блума для базовых; их отсутствие не исключает компетенцию. Компетенции без подходящих ОР пропускаются с причиной. Если ни одна не подходит, вариант не создаётся.
3. Основной ОР выбирается по максимуму суммы Блума и важности; равенство суммы разрешается большей важностью. Случайно выбирается только конкретный аналог внутри выбранного ОР.
4. Вариант сохраняется со снимками заданий и профилей. Повторное чтение возвращает выбранные задания, в том числе после переимпорта карты.
5. Backend диагностической сессии принимает голосовой ответ и вызывает assessment application с variant ID и ID позиции. Грейдер получает сохранённый снимок и роль. Основной оценивается в 0/1/2, basic — в 0/1; сессия использует роль-зависимую оценку без преобразования. Основной с оценкой 2 пропускает базовые, с 0/1 требует базовых.
6. Диагностическая сумма учитывает только основные задания включённых компетенций; максимум 2N. Технический сбой не превращается в учебный ноль; непроверенный ОР не объявляется пробелом.
7. Тренировка работает по проверенным пробелам и не изменяет исходную диагностику.

## Реализованное API сессии

Состояние сессии и принятые ответы хранятся в PostgreSQL и переживают перезапуск backend. Реализованы запуск, чтение прогресса, сохранённая озвучка инструкции, голосовой ответ и результат диагностики. Отправка ответа требует `Idempotency-Key`; повтор принятого запроса возвращает сохранённый результат. Истёкшая lease позволяет повторить обработку после сбоя.

Сессия вызывает assessment application; в mock используется mock grader, в real — настроенный model grader. Ошибки STT/grading не записывают score и не меняют позицию. Frontend показывает диагностику и её общий фидбэк, позволяет выбрать предмет/действие и подключает preview и прохождение тренировки.

## Предметный frontend flow

Главная не создаёт вариант при загрузке или выборе предмета. Диагностика начинается только после явного нажатия. Тренировка требует завершённую диагностику этого предмета; preview показывает точные категории «Неосвоенные темы» и «Частичные пробелы в знаниях», либо «Свободная тренировка». Продолжение использует сохранённые цели и упражнения. В real это состояние переживает перезапуск благодаря PostgreSQL; браузерный mock сбрасывает демонстрационные данные при новом входе. Аналогичные упражнения, генерируемые LLM, остаются будущим отдельным provider; текущий сценарий не обещает каждый раз новое содержание.

## Ответственность модулей

Variantgen реализует создание, список, чтение варианта и чтение отдельной позиции. Публичное чтение сразу возвращает main и доступные basic (от нуля до двух) без эталонов, criteria, ОС и сырого снимка; внутренний reader предоставляет полные данные и связанные свойства грейдингу. Чтение позиции не выбирает новое задание и не управляет показом базовых.

Приём ответов и порядок диагностики реализованы модулем `diagnostic`, итоговый фидбэк — `diagnosticfeedback`, тренировка — `training`. Перед запуском тренировки preview показывает «Неосвоенные темы» и «Частичные пробелы в знаниях». Без завершённой диагностики запуск возвращает конфликт. При отличном результате режим свободный и включает готовые FALSE-задания выбранного предмета. После последней цели начинается новый раунд; выход из экрана не завершает сессию. История и текущие баллы сохраняются отдельно от исходной диагностики.

Правила отбора — [алгоритм](Алгоритм_составления_варианта.md); HTTP-контракт — [OpenAPI](../api/openapi.yaml).
