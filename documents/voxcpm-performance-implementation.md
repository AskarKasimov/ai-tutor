# Реализация ускорения VoxCPM2 — 18.10.2026

Работа выполняется по [спецификации](voxcpm-performance-spec.md) и [плану](voxcpm-performance-plan.md) в отдельных ветках `feat/voxcpm-performance` двух репозиториев. Это отчёт о коде и проверках, не подтверждение ускорения на целевом GPU.

## Что добавлено

- TTS: `VOXCPM_OPTIMIZE=off|auto|on`, загрузка и прогрев перед readiness, явный fallback только в auto; закреплённый голос через `VOXCPM_REFERENCE_WAV`; ограниченный LRU признаков референса; `/synthesize/stream` с PCM NDJSON, отменой и ограниченной очередью. Коммит `tts-stt`: `50296d2` (база `d859c76`).
- Backend: защищённый endpoint потока, проверка протокола и профиля голоса, совместный producer для WAV/stream/warmer и публикация только полного WAV в S3. Коммит `71ca469`.
- Frontend: инкрементальный PCM reader, AudioWorklet с ограниченной очередью и ресемплингом, последовательность reply/question, отмена, повтор и совместимый WAV fallback. Коммит `ae9d25f`.
- Приёмка: 30 реплик с SHA-256, HTTP-инструмент измерений, smoke текущего Caddyfile и воспроизводимый браузерный smoke.

## Подтверждённые проверки

| Область | Фактический результат |
| --- | --- |
| TTS HTTP, CPU fake-model | 76 тестов пройдены, включая настоящий ASGI send/flush/disconnect; без весов и CUDA. |
| TTS конфигурация | CPU и GPU Compose валидны; compileall и diff check пройдены. |
| Benchmark/proxy | 4 unittest пройдены с `RUN_CADDY_SMOKE=1`; настоящий изолированный Caddy из существующего образа передаёт первый PCM до завершения ответа, сохраняет no-store и не сжимает поток; disconnect доходит до upstream. |
| Настоящий Chrome | Headless Chrome `155.0.8059.82`, реальный AudioWorklet и вход 16 кГц: early-start до end, полное завершение 50-мс фрагмента, отмена reader по stop. Синтетический PCM; новых underrun в этих сценариях нет. |
| Backend | `go test -race ./... -count=1`, `go vet ./...`, сборка — PASS. Все DB-интеграции выполнены в изолированных схемах локального PostgreSQL; DB-тесты не пропущены. Настоящий HTTP с auth/logging middleware выдаёт PCM до конца provider-потока. |
| API и конфигурация | OpenAPI сгенерирован дважды с одинаковым результатом; root/backend Compose с обоими env-примерами и `sh -n prod.sh` — PASS. |
| Frontend | Форматирование, lint, typecheck — PASS; Vitest: 36 файлов / 304 теста; production build включает отдельный Worklet asset. |

Caddyfile менять не понадобилось: неизвестная Content-Length уже обеспечивает ранний flush. Режим `flush_interval -1` не добавлялся, чтобы не потерять отмену upstream при disconnect клиента. Smoke использовал временный сертификат/контейнер, действующие сервисы не перезапускались.

Frontend Vitest выводит существующие предупреждения jsdom о HTMLMediaElement/navigation и Node о localstorage-file; Vite — существующее предупреждение о размере bundle >500 кБ. Ошибок тестов/сборки нет; предупреждения не скрывались. Для восстановления отсутствующих установленных пакетов выполнен `npm ci` по действующему lockfile, файлы зависимостей не менялись.

Команды самостоятельного повторения:

```bash
RUN_CADDY_SMOKE=1 python3 -m unittest discover -s scripts/tests
python3 scripts/benchmark_voxcpm.py --help
```

Для браузерного smoke запустить Vite frontend на loopback, затем из корня вызвать:

```bash
node scripts/smoke_voxcpm_browser.cjs \
  http://127.0.0.1:5188 \
  /absolute/path/to/playwright \
  /absolute/path/to/chrome
```

Нужны локально установленные Playwright и Chrome; новые зависимости продукта для этого не добавлены. Скрипт не загружает настоящую модель, не записывает микрофон и не обращается к авторизованным данным. Автоматическое прохождение не означает слышимость на физическом устройстве или поддержку Firefox/Safari.

## Условия включения

По умолчанию сохранены **20 шагов, optimize off и streaming false**. Код поддерживает запрос с 10 шагами, но проект ранее фиксировал ухудшение интонации при 10–15. Новое значение по умолчанию допустимо только после независимого прослушивания на одном референсе.

Перед включением нужно закрепить фактические model revision и SHA-256 голоса в настройках TTS/backend, дождаться readiness и пройти [матрицу приёмки](benchmarks/voxcpm-acceptance.md). Не менять веса/байты закреплённого референса без обновления профиля кеша backend.

Не выполнены: CUDA-бенчмарк на целевом сервере, измерение реальной Browser TTFA с VoxCPM через весь production-конвейер, слепое прослушивание двумя людьми, прогоны Firefox/Safari и проверка отката на целевом deployment. Численного заявления об ускорении пока нет. Деплой, push и merge в этой работе не выполнялись.

## Решения реализации

- Сохранены чистые checkout обоих репозиториев, работа идёт в feature-ветках без дополнительных worktree. Исходных пользовательских изменений не было.
- Частота PCM ограничена целыми 8000–192000 Гц одинаково на всех границах; это инженерное уточнение отражено в спецификации. Для будущей модели вне диапазона потребуется расширить контракт.
- Идентичность модели/референса задаётся явно оператором; значения неизвестного deployment не выдумываются. Ошибка pinning способна смешать профили, поэтому это обязательный шаг выпуска.
