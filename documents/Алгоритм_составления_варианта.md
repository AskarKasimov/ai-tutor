# Алгоритм сборки варианта

Дата: 7 октября 2026. Основа — текущая карта ML CSV/XLSX. Реализация сборщика ещё не начата; будущие операции описаны в [OpenAPI](../api/openapi.yaml).

## Фильтр компетенций

Обработать всю карту без выбора темы. Для каждого ОР оставить только TRUE, допустимые таксономию/важность и хотя бы одно готовое задание. Компетенция включается при наличии минимум трёх таких **разных ОР**. Несколько аналогов одного ОР считаются одним ОР.

Недостаточные компетенции пропускаются; вариант сохраняет список пропусков с причинами. Если не прошла ни одна, вернуть ошибку без создания пустого варианта.

## Выбор ОР

Для основного: максимум `ранг Блума + важность`; равная сумма — большая важность; полное равенство — порядок карты.

Для двух базовых: исключить основной и выбрать два других готовых TRUE-ОР той же компетенции. Детализация для ревью: ранг Блума по возрастанию, важность по убыванию, затем порядок карты. Ранг ниже основного предпочтителен, но не обязателен; три ОР одного ранга проходят общий фильтр. Составляющие могут отличаться.

Текущие ранги: знание=1, понимание=2, применение=3, анализ=4; важность=1…5. Смысловые prerequisite-связи не задаются преподавателем и не доказываются этим автоматическим выбором.

## Выбор конкретных заданий

Каждый выбранный ОР имеет пул готовых аналогов с одинаковыми унаследованными свойствами. Случайно и равномерно выбрать одно задание внутри **того же ОР**. Если оно единственное, взять его. У main/basic разные ОР и task ID; подмена аналогом другого ОР не допускается.

При полном равенстве метаданных используется порядок источника, затем стабильный fallback имени/ID. Все остальные решения детерминированы. Seed и воспроизводимость генерации не требуются; выбранные задачи фиксируются в БД и не меняются при повторном чтении.

## Источник и результат

Колонки/формат карты остаются прежними. Преподаватель добавляет полные Задание N и больше TRUE. Полная ячейка содержит Экран:, Голосовая инструкция: и Ответ:; варианты необязательны. Неполные фрагменты не считаются заданиями. Ручные роли, связи, группы и дополнительные документы не требуются.

LLM-генератор taskgen сохраняется отдельным действующим модулем; готовые задачи того же ОР могут участвовать в пуле наряду с авторскими.

Для каждой включённой компетенции результат содержит main + два basic и снимки вопросов/профилей. Сохраняются исходные ID, данные для грейдинга и пропущенные компетенции. История читается после переимпорта.

Планируемый доступ: создание и список вариантов, чтение варианта и отдельной позиции. Публичный API скрывает эталоны, criteria, ОС и сырой снимок; серверный reader для грейдинга возвращает полный снимок с проверкой владельца. Ответы, оценки, переходы и тренировка реализуются другим разработчиком; в scope variantgen входит только сборка, хранение и чтение.
