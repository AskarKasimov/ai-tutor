# Изолированная проверка промптов Geek

Дополнительные наборы: `-cases testdata/geek-eval/automation.json` проверяет объяснение и пример, в том числе одинаковый ответ на вопросы с требованием примера и без него; `-cases testdata/geek-eval/coverage.json` проверяет полноту разных частей без обязательного примера. Основные случаи дают фиксированные ожидания для ручной проверки, а не универсальную автоматическую метрику качества.

`-cases testdata/geek-eval/adversarial.json` — 40 сценариев на всех 16 сохранённых вопросах: разумные короткие ответы, тавтологии, предметные ошибки, неполнота, вымышленные факты и подложные инструкции. Хороший ответ с инъекцией тоже проверяется: знания должны засчитываться, а команда сменить формат — игнорироваться. Результаты короткого промпта: [отчёт](../../../../documents/geek-grading-stress-test.md). При одном ответе сценарий может закончиться на уточнении без итоговой оценки; это не D и не провал транспорта.

Нужны Go и доступ к удалённой модели. Docker, БД, S3, OCR, TTS/STT и Python-сборщик графа не запускаются. Используется готовый `api/fixtures/intro-to-ai.weeks-1-2.ru.graph.json`; исходный файл не меняется.

`-cases testdata/geek-eval/paraphrases.json` проверяет короткие правильные ответы, корректную замену слов, пустые повторы, называние терминов без запрошенного вывода и правильный ответ с инъекцией поставить нули. [Результат итераций промпта](../../../../documents/geek-paraphrase-grading.md); ожидания пограничных ответов требуют содержательного решения преподавателя, а не совпадения текста с лекцией.

Команды выполняются из `services/backend`.

```powershell
# Просмотр настоящих запросов без обращения к модели:
go run ./cmd/geek-eval -preview

# Реальный прогон на явно указанном оператором OpenAI-совместимом endpoint:
go run ./cmd/geek-eval -endpoint http://MODEL_HOST:PORT/v1 -model gpt-oss-120b

# Один собственный эксперимент:
go run ./cmd/geek-eval -task evaluate -only correct-short-no-slide-details -endpoint http://MODEL_HOST:PORT/v1

# Только новые вопросы; сохранённые вопросы графа здесь не переиспользуются:
go run ./cmd/geek-eval -task questions -nodes AI-01-13,AI-01-14 -endpoint http://MODEL_HOST:PORT/v1

# Отдельный отчёт для сравнения reasoning:
go run ./cmd/geek-eval -task evaluate -reasoning medium -endpoint http://MODEL_HOST:PORT/v1 -out bin/geek-medium.json
```

Для своих ответов измените копию `testdata/geek-eval/cases.json` и передайте `-cases path/to/cases.json`. В каждом случае указаны id вершины, фиксированный вопрос, последовательность ответов студента и ожидаемое поведение для ручной проверки. `expected` — заметка проверяющего, не автоматическая оценка качества модели. Восемь случаев — небольшой smoke-набор, не калибровка судьи на всём курсе.

Запуск сохраняет JSON со всеми реальными запросами, сырыми ответами (включая usage и rationale, если модель их вернула), задержками и состояниями. Рядом создаётся читаемый Markdown. По умолчанию это `bin/geek-eval.json` и `bin/geek-eval.md`. Запросы последовательные, таймаут одного вызова — 90 секунд (`-timeout`), reasoning по умолчанию — production (сейчас low для всех вызовов Geek); -reasoning low|medium|high принудительно меняет его для всех вызовов; явно ограничен ответ модели 4096 токенами. Ответ на допвопрос или переформулировку берётся из следующего элемента `answers`. Если ответы закончились, тема может остаться незакрытой — смотрите `next` и последний вопрос, дополните сценарий.

Стенд вызывает **те же** `Gateway.Question` / `Gateway.Evaluate`, построитель промптов, парсер, повтор невалидного JSON и `Exam.Apply`, что приложение. Зависимости подменены только транспортом и файлом графа. Кнопка «Не знаю», БД, озвучка, очереди gateway и качество Python-генерации графа этим прогоном не проверяются; произнесённое «не знаю» проверяется как обычный текстовый ответ.

Генерация новых вопросов и оценивание намеренно разделены: сохранённый хороший ответ нельзя честно оценивать по случайно изменившемуся вопросу. В блоке генерации просматривайте новые вопросы; в блоке оценивания фиксируйте пару вопрос–ответ для воспроизводимого сравнения промптов.

Прямой endpoint — явный режим этого тестового инструмента, добавленный по предоставленному пользователем адресу для локальной проверки без инфраструктуры. Боевые вызовы приложения по-прежнему идут через LLM gateway. Флаг `complexity` в прямом эксперименте не маршрутизирует запрос: модель выбрана оператором. Встроенные unit-тесты используют транспорт в памяти и не обращаются к реальным моделям.

Для сравнения без изменения самого текста промпта: `python -X utf8 cmd/geek-eval/ablation.py --endpoint http://MODEL_HOST:PORT/v1`. Скрипт требует сохранённых `bin/geek-compact-stress.json` и `bin/geek-compact-followup.json`, берёт девять зафиксированных запросов оценивания и выполняет по два повтора low/medium с текстом темы и без него. Реплики, вопрос, системная инструкция, индивидуальные правила и список пререквизитов сохранены; меняются только `reasoning_effort` и содержание темы. JSON с запросами, сырыми ответами, usage и временем пишется после каждого вызова в `bin/geek-reasoning-ablation.json`. Это сравнение отдельных вызовов без пересчёта `Exam.Apply`, нового диалога и автоматического повтора парсера. [Результат и ограничения](../../../../documents/geek-reasoning-ablation.md).
