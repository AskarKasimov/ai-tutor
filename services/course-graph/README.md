# Course Graph (Граф курса и распознавание)

Сервис `services/course-graph/` отвечает за построение графа курса из учебных материалов (лекций, лабораторных и туториалов). Сервис вынесен в отдельный контейнер с FastAPI из-за объёмных зависимостей анализа документов (PyTorch, Docling) и изоляции ресурсов от Go-backend.

## Конвейер обработки

Обработка материалов курса состоит из 7 этапов:

1. **OCR и конвертация** (`course_graph/ocr/converter.py`): извлечение структурированного Markdown с LaTeX-формулами из PDF/Markdown/TXT через Docling с резервным извлечением текста через pypdf. — **Реализован**.
2. **Очистка (Cleaning)** (`course_graph/cleaning/cleaner.py`): один LLM-проход по пачкам, удаляющий только явно организационные блоки без переписывания текста. — **Реализован**.
3. **Юниты (Units)**: извлечение атомарных подтем (вершин графа) с привязкой к неделе и источникам. — *Запланирован*.
4. **Дедупликация (Dedup)**: склейка пересекающихся понятий между лекциями и лабами. — *Запланирован*.
5. **Пререквизиты (Prerequisites)**: выявление зависимостей между юнитами и построение ацикличного графа. — *Запланирован*.
6. **Валидация (Validation)**: проверка ацикличности и связности. — *Запланирован*.
7. **Экспорт в PostgreSQL**: фиксация версии графа курса в базе данных. — *Запланирован*.

## API и интеграция

- `GET /health` — проверка работоспособности сервиса (`{"status": "ok", "service": "course-graph"}`).
- `POST /ocr/convert` — конвертация документа в Markdown (multipart-форма с полем `file`). Возвращает `{"markdown": "..."}`. Поддерживается также алиас `POST /convert`.

В общей инфраструктуре сервис запускается в контейнере `course-graph` (`services/course-graph/docker-compose.yaml`), доступен backend по адресу `http://course-graph:8000` через переменную `BACKEND_COURSE_GRAPH_URL`.

## Автоматическая очистка материалов

После успешного сохранения OCR-текста в S3 backend атомарно сохраняет материал
и задачу в `material_cleaning_jobs`. Фоновый обработчик читает текст из S3 и
вызывает внутренний `POST /clean` (`{"markdown":"..."}`). Загрузка не ждёт очистку.
Старые материалы миграция автоматически не ставит в очередь.

Текст разбивается на блоки с исходными символьными координатами. Пачка — до
12 000 символов и 100 блоков; одновременно обрабатываются до четырёх пачек.
Модель возвращает только ID удаляемых блоков и категорию причины. Формулы, код,
изображения, таблицы и слишком большие неделимые блоки сохраняются целиком.
Учебные задачи и примеры сохраняются; правила сдачи, баллы, контакты и пустые
благодарности удаляются. Сомнительные или смешанные блоки остаются.
Если модель предлагает удалить более 60% текста, возвращается оригинал с
предупреждением в отчёте. Это эвристика защиты, а не гарантия качества разметки.

Python не обращается к моделям напрямую: `COURSE_GRAPH_LLM_GRPC_TARGET`
(по умолчанию `api:8003`) указывает на внутренний backend gRPC-шлюз.
`BACKEND_LLM_BASE_URLS` задаёт от одного до четырёх URL совместимых API с `/v1`,
через запятую; `BACKEND_LLM_MODEL` — общую модель. Пустые настройки используют
`BACKEND_ASSESSMENT_BASE_URL` и `BACKEND_ASSESSMENT_MODEL`.
`BACKEND_LLM_API_KEY` необязателен. Все настройки и ключ остаются на сервере.
Пул допускает один запрос на каждый endpoint; при одном endpoint запросы
к модели выполняются последовательно. Остальные прежние потребители моделей
пока используют свои существующие адаптеры.

Оригинал остаётся в `parsed/`, результат и JSON-журнал удалений — в
`subjects/{subject_id}/cleaned/{material_id}/{attempt_token}.{md,json}`.
Backend проверяет SHA-256 исходника и точное соответствие результата журналу.
`GET /admin/subjects/{subject_id}/materials` возвращает дополнительное поле
`cleaning`: статус `pending / processing / ready / failed`, число попыток,
очищенный текст, S3-ключи результата и отчёта, сообщение ошибки.
`parsed_text` и прежний OCR-статус сохраняют своё значение.
Предупреждения о сохранении всего текста находятся в JSON-журнале;
`ready` означает завершение обработки, а не экспертное подтверждение качества.

Очередь переживает перезапуск backend. Задача резервируется на 7 минут,
работа ограничена 6 минутами; после ошибки — до трёх попыток с задержкой
30 и 60 секунд. Истёкший lease можно забрать повторно; устаревший обработчик
не может перезаписать результат нового. Ошибка очистки не удаляет исходник.
После исчерпания попыток автоматическая обработка прекращается; повторная
загрузка создаёт новую задачу. Отдельной ручки повторного запуска пока нет.

Для локального запуска: `docker compose up -d --build course-graph api` из корня.
Если остался контейнер старого сервиса `ocr`, сначала остановите его: он занимает
тот же порт 8005. Внутренний gRPC-порт 8003 не публикуется на хост и в Caddy.

## Проверки

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q
```

Для генерации gRPC-кода установите также `grpcio-tools==1.70.0`, затем из корня:
`bash services/backend/scripts/generate-llm-proto.sh`.
Тесты проверяют сохранность текста/формул, смешанные слайды, неверные ответы
модели и ограниченную параллельность. Очередь и S3-адаптер проверяются Go-тестами
backend с `TEST_DATABASE_URL` (HTTP-фикстура S3, изолированная схема PostgreSQL).

### Лёгкая dev-сборка

`COURSE_GRAPH_INSTALL_DOCLING=false docker compose build course-graph` из корня
собирает образ без Docling/PyTorch. Очистка доступна полностью; PDF обрабатываются
через pypdf, а Markdown/TXT — напрямую. Эта сборка не распознаёт текст на сканах
и не восстанавливает формулы средствами Docling. Полная сборка по умолчанию
сохраняет Docling: `docker compose build course-graph`.
Собранный образ можно запустить командой `docker compose up -d --no-build course-graph api`.

### Повторное использование готового OCR-образа

Если локально уже есть образ OCR с Docling, его можно использовать как базовый,
чтобы не скачивать PyTorch и остальные тяжёлые пакеты заново:

```bash
COURSE_GRAPH_BASE_IMAGE=ai_tutor-ocr:latest docker compose build course-graph
```

Зависимости проверяются из `requirements.txt`, затем в образ копируется актуальный
код `course_graph`, включая `/clean` и gRPC-клиент. По умолчанию базовый образ —
`python:3.11-slim`; повторное использование локального образа необязательно.
