# Frontend AI Tutor

Экран выбора часов персонального плана обучения показывает вопрос и варианты времени без отдельной карточки «Курс» сверху. Кнопка «К курсу» сохраняется.

React 19, TypeScript, Vite 8,
TanStack Router (файловые маршруты), TanStack Query, i18next / react-i18next,
SCSS Modules, Vitest и Testing Library. Для UI используется Radix Themes.

## Запуск

Требуется Node.js 22.12+ и npm. Из этой директории:

```bash
npm ci
npm run dev
```

Откройте http://localhost:5173. На `/` находится общий вход и выбор направления; `/learn` открывает обучение, `/exam` — Geek с запуском экзамена и историей.
Для микрофона нужен HTTPS или localhost. Фронтенд всегда использует HTTP API backend.

## Geek: устный экзамен

На `/exam` студент видит курс, кнопку «Начать проверку знаний» (или «Продолжить
проверку знаний», если есть незавершённая) и список своих проверок — диагностик курса
(`GET /api/v1/exam/diagnostic-sessions?subject_id=…`): у завершённых — оценка и
кнопка «Открыть итог». Открытый экран (диалог или итог) переживает перезагрузку
вкладки через `sessionStorage`. Правила экзамена — в [корневом README](../../README.md).

Диалог — экран-чат по референсу `documents/photo_2026-10-16_13-59-35.jpg`:

- шапка с курсом и шагом «Диагностика», под ней прогресс диагностики
  (`progress_percent` сессии, с 0%) — космический `CosmicProgress` из `shared/ui`;
- реплики Geek слева (Markdown, подпись вида реплики: вопрос, дополнительный
  вопрос, переформулировка) с кнопкой озвучки. Новая реплика озвучивается сразу:
  сначала реакция на прошлый ответ (`.../audio?part=reply`, если поле `reply`
  не пустое), затем вопрос (`part=question`). Вопрос запрашивается, когда реакция
  уже пришла: сервис синтеза обрабатывает запросы по очереди. WAV хранятся
  в памяти для повторов; заблокированный браузером автозапуск не считается
  ошибкой, студент может нажать «Прослушать»;
- открытая активная диагностика перечитывается раз в 20 секунд; если курс
  пересобран и диагностика отменена, появляется всплывающая плашка «Курс обновлён»
  (`Toast` из `shared/ui`);
- ответы студента — тёмные пузыри справа;
- диалог следует за последней репликой и на desktop, и при прокрутке страницы
  на мобильном экране; новые сообщения прокручиваются плавно без нативного
  scroll anchoring (с учётом prefers-reduced-motion); чтение старых реплик приостанавливает автопрокрутку
  до возвращения к концу;
- внизу поле «Ответить на вопрос» (Enter отправляет, Shift+Enter — перенос
  строки) и кнопка микрофона. Голосовой ответ записывается (до 90 с),
  распознаётся через `POST /voice/transcriptions` и отправляется сразу, без шага
  проверки и перезаписи;
- пока ответ обрабатывается, в ленте видны ответ студента и анимация «Geek думает…»
  (три точки). Реплика Geek на ответ остаётся скрытой за ней, пока не начнёт звучать
  первая часть озвучки, — текст и голос появляются вместе. Если озвучка не пришла
  (ошибка, заблокированный автозапуск или 20 секунд ожидания), реплика показывается
  без неё; поле ответа до этого заблокировано.

Ответ уходит синхронно в `POST /api/v1/exam/diagnostic-sessions/{id}/answers`. Ключ
`Idempotency-Key` выводится из реплики и содержимого ответа, поэтому «Отправить
ещё раз» после сбоя (например, 503 — модель недоступна) повторяет тот же запрос
и не создаёт второй ответ. 409 означает, что диагностика ушла вперёд в другой
вкладке: экран перечитывает её. После завершения появляется карточка итога
с кнопкой «Посмотреть итог» — только когда озвучка последней реплики Geek
закончилась, не удалась или остановлена; открытая уже завершённой диагностика
показывает её сразу. Карточка выезжает снизу, по рамке один раз пробегает
«комета», галочка рисуется; при `prefers-reduced-motion` — только проявление;
прерванная из-за пересборки графа диагностика предлагает вернуться на главную.

Итог (`GET /api/v1/exam/diagnostic-sessions/{id}/result`) показывает предварительную оценку
A–D с процентом, пробелы и слабые места (темы на C, отдельным блоком в той же панели)
с известными неделями, цитатами и разделами «Теория»,
«Практика», «Другие материалы», и проверенные темы со статусом и оценкой: темы,
до которых диагностика не дошла (`unchecked`), не показываются. Внизу — карта
проверенных тем (`pages/trainer/lib/result-graph.ts`): карточки с названием,
статусом и оценкой в колонках от пререквизитов (поле `requires` темы итога) к
опирающимся на них темам. Связь через скрытую непроверенную тему сохраняется,
транзитивные связи не рисуются, длинное ребро идёт своей дорожкой мимо чужих
карточек. Темы верхнего уровня подсвечены, связь от пробела — красный пунктир.
Ссылка
скачивает только источник, связанный с snapshot этой диагностики. 410
`SOURCE_UNAVAILABLE` локально заменяется сообщением у ссылки; остальной итог
остаётся доступен. Старые результаты без sources разбираются как пустые массивы.

## Авторизация

Общий вход доступен на `/`; после входа пользователь выбирает `/learn` или
`/exam`. Гости видят форму входа и регистрации на стартовой. Учитель входит
passwordless через `/api/v1/auth/teacher`, student — через login/register.
Админка использует общий аккаунт teacher. `/admin/courses` показывает единый список
и создание курса; выбор курса открывает `/admin/courses/{subject_id}` с вкладками
«Материалы для обучения» и «Материалы для экзамена». Обе вкладки используют один ID.
Обе вкладки отрисовываются в общем shell: имя курса, возврат к каталогу и навигация
расположены одинаково; ниже меняются заголовок, готовность и содержимое направления.
Ровно одна вкладка помечена активной визуально и через `aria-current`. Прямая ссылка
использует `?direction=learn|exam`, а ссылка без query открывает обучение.
Если загруженный каталог не содержит указанный ID, либо проверка ресурса получила
404 и повторный запрос подтвердил удаление курса, маршрут заменяется на `/`.
Pending-загрузка не перенаправляет; ошибка сети/5xx оставляет экран повтора.
Неизвестный ID не выводится вместо названия курса.
На `/admin` backend-запросы
получают `X-AI-Tutor-Portal: admin`; student и admin cookies и refresh locks
разделены, поэтому обе сессии могут работать параллельно в одном браузере.
Меню профиля ведёт к выбору режима, logout возвращает к форме на `/`.

## Админ-панель: подготовка курса

Список `/admin/courses` и подготовка `/admin/courses/{subject_id}` доступны только
пользователям с ролью `admin`. На общем списке показаны все курсы и курс создаётся один раз
(`POST /api/v1/exam/admin/subjects`). Клик по курсу открывает вкладку обучения; вкладка экзамена
использует тот же ID. В обеих вкладках видны имя курса и ссылка ко всем курсам. Экран обучения
содержит отдельную CSV/XLSX загрузку карты, экран экзамена проходит этапы
«Материалы → Граф тем → Готов студентам». PDF-файлы
загружаются с индивидуальными неделей и видом из справочника backend
(`GET /api/v1/exam/admin/material-kinds`) через `POST /api/v1/exam/admin/subjects/{subject_id}/materials`. Очередь принимает до 500 PDF общим размером до 250 МиБ; ZIP распаковывается в браузере. Метаданные
каждого файла можно исправить через PATCH без повторного OCR и по одному полю, включая старые записи без недели или вида; до заполнения обоих полей сборка заблокирована. При ошибке введённые значения остаются в форме; сохранение можно повторить. Список показывает статус
распознавания, размер, классификацию и число символов; материал можно открыть в
предпросмотре распознанного текста, скачать исходник
(`GET .../materials/{material_id}/raw`) и удалить после подтверждения.

Построение графа блокируется, пока материалы обрабатываются, не классифицированы
или их изменение ещё не завершено. Интерфейс использует граф и серверный конвейер
из master: `GET .../graph` возвращает сохранённый граф и состояние задачи,
`POST .../graph/build` запускает сборку. Отдельный `GET .../graph/build` не используется.
Исходные карточки, формы, единый список, сортировка по неделям, стрелки и
перетаскивание, Markdown-предпросмотр и три блока подготовки курса сохранены.
Граф показывается интерактивной картой (`@xyflow/react`, отдельный ленивый чанк;
раскладка — чистый модуль `widgets/course-graph/lib/course-graph-view.ts`): каждый
раздел — остров, темы внутри идут слева направо по пререквизитам (связь «раздел →
подтема» учитывается, только если не противоречит им), клик или Enter открывает
карточку темы, есть поиск, легенда разделов, мини-карта и полноэкранный режим.
Подсветку задаёт последнее действие: новый поиск или выбор раздела закрывает выбранную
тему, выбор раздела очищает поиск, новый поиск снимает раздел; фильтр раздела,
которого нет в пересобранном графе, сбрасывается. Подписи встроенных кнопок React Flow переведены
через `ariaLabelConfig`. Режим «Списком» — прежнее дерево иерархии и пререквизитов.
Граф курса можно собрать по материалам кнопкой «Собрать граф тем» или по exam
XLSX-карте кнопкой «Импортировать карту компетенций» в той же карточке графа,
сразу после разделителя под кнопкой сборки. Подтверждение, ошибки, статус последней
карты и `graph_source` остаются внутри выбранного общего курса. Для карты читается
первый лист, варианты заданий берутся по прежнему алгоритму; карта может подготовить
exam-направление без PDF. Учебный CSV/XLSX импорт остаётся отдельным API и parser,
не меняющим exam-граф.
Графа по умолчанию нет: пока граф не собран, его нет и в админке.
Кнопки замены и удаления документа скрыты, пока он находится в очереди или проходит
OCR, перевод и очистку; после завершения или ошибки обработки они доступны.

В очереди до 500 PDF суммарно до 250 МиБ; один PDF — до 50 МиБ. Отправка идёт
последовательно пакетами до 48 файлов с исходным manifest `items` и корреляцией
`client_id`; неудачные файлы остаются для повтора. Неделя и тип сохраняются кнопкой
«Сохранить» без повторного OCR. Замена PDF сохраняет метаданные и ставит новое
фоновое задание OCR → перевод → очистка, отменяя устаревшие результаты старого файла.

Пересборка требует подтверждения; успешная замена графа отменяет активные диагностики
курса. Дата последней успешной публикации сохраняется после ошибки пересборки.
Идущая сборка показывает этап, «этап i из 5 · шаг k из M» и процент в `CosmicProgress`
(тёмный звёздный трек, градиентная комета; без анимации при `prefers-reduced-motion`)
по полю `progress` снимка; пока course-graph не сообщил этап — «Подготовка задачи…»
и бегущая комета без процента. Прогноза времени нет.

Cookies сессии передаются вместе с запросами. Backend требует авторизацию;
при HTTP 401 интерфейс показывает сообщение о необходимости войти.
Таймаут ответа Geek — 240 секунд (оценка модели и следующий вопрос), озвучки реплики — 120 секунд, чтения — 30 секунд. Сервисы моделей вызывает backend, их адреса
во фронтенде не нужны.

Настройки находятся в общем корневом `.env` монорепозитория
(игнорируется Git), образец — корневой `.env.example`:

```dotenv
VITE_API_BASE_URL=/api/v1
VITE_API_PROXY_TARGET=http://127.0.0.1:8002
```

Авторизация, диагностика, STT и озвучка реплик используют backend. Локальных источников данных нет.

Vite читает env из корня монорепозитория, в том числе при запуске из
`services/frontend`. В dev-режиме Vite проксирует `/api/v1` на локальный backend и удаляет префикс.
После изменения env перезапустите `npm run dev`.
Для проверки сессии с Secure cookies используйте HTTPS через Compose.
В Compose запросы идут на тот же origin через Caddy. Значение `/api/v1`
используется по умолчанию. Корневой dev Compose передаёт `VITE_API_BASE_URL` как env Vite; после изменения `.env` пересоздайте dev frontend. Для runtime image `VITE_API_BASE_URL` встраивается при сборке, поэтому изменение адреса требует пересборки образа.
Прямой `docker build` поддерживает `--build-arg VITE_API_BASE_URL=...`.

Frontend использует один API base (`VITE_API_BASE_URL`, по умолчанию
`/api/v1`). Режимы маршрутизируются внутри SPA: `/learn`, `/exam`,
`/admin/courses` и вложенный `/admin/courses/{subject_id}`; отдельного host bridge нет.
HTTP-контракт и сценарии проверяются тестами. Backend использует API моделей
для STT/TTS; их настройки обязательны и задаются в корневом `.env`.

Макет: https://www.figma.com/design/0QMZU6tpUJCFmtZKMkYn4B/?node-id=186-6.
В `public/assets/voice-trainer/` хранятся только два SVG: `logo.svg` и
`microphone.svg`, собранные из исходных слоёв макета, а также локальные Inter
Regular/Bold и их лицензия. Фоны, рамки, кнопки, прогресс и волна оформлены CSS.
Приложение не запрашивает шрифты или временные ассеты Figma во время работы.

## Структура

- `src/bootstrap/` — app-layer alias и composition root: entrypoint, providers, HTTP DI и router shell. Имя `bootstrap` выбрано вместо стандартного `app`; `src/app/` и `src/application/` не создаются.
- `src/routes/` — тонкий технический реестр TanStack Router с неизменными URL; `src/routeTree.gen.ts` генерируется автоматически.
- `src/pages/trainer/`, `src/pages/learning-trainer/`, `src/pages/mode-selection/`, `src/pages/admin-courses/`, `src/pages/competency-map/`, `src/pages/learning-competency-map/` — уникальные экраны и их композиция. Trainer page содержит главную с историей, диалог Geek и итог без импорта другого page slice.
- `src/features/` — сценарии `auth`, `diagnostic-session` (данные диагностики, ответ голосом, озвучка реплик), `subject-selection`, `import-competency-map` (сейчас — только материалы курса) и `course-graph-build` (граф курса и его сборка), включая локальные hooks, порты и UI действий.
- `src/entities/` — общие `user` и раздельные Geek/learning subjects, assessment, competency map, diagnostic session, plan and training models; exam и learning query keys namespaced.
- `src/shared/api/` — HTTP transport и auth refresh; `src/shared/lib/` — браузерные audio/waveform adapters; `src/shared/i18n/` — локализация.
- Слои импортируют только вниз; slices одного слоя изолированы. Межслайсовые импорты используют `index.ts`; внутренние импорты slice относительные. Для взаимных entity типов разрешены только минимальные `@x/<consumer>` APIs.
- Чистые сценарии находятся в `model`/`lib` owning slice. `bootstrap` собирает per-slice providers и HTTP-адаптеры; предметные контракты не агрегируются в `shared`.
- `tests/` — отдельная иерархия тестов, зеркальная относительно `src/`: например, `src/features/auth/model/use-auth.ts` проверяется в `tests/features/auth/model/use-auth.test.tsx`.
- `tests/setup.ts` настраивает тестовую среду; `tests/support/query-wrapper.tsx` предоставляет общий wrapper для React Query тестов. Тесты и вспомогательные тестовые модули не размещаются в `src/`.

`src/routeTree.gen.ts` генерируется плагином Router при запуске Vite/Vitest или
сборке. После добавления маршрутов сначала запустите npm run dev либо npm run build,
затем typecheck. Правила разработки находятся в AGENTS.md.

## Проверки

Для форматирования исходников и конфигурации используйте `npm run format`.
Prettier использует одинарные кавычки и не добавляет точки с запятой в TS/JS.
Сгенерированный `src/routeTree.gen.ts`, lock-файл и статические ассеты исключены.

```bash
npm run format:check
npm run lint
npm run typecheck
npm test -- --run
npm run build
```

Эти же проверки выполняются в Frontend CI. `npm run preview` запускает
предпросмотр готовой сборки.

## Docker

Из корня монорепозитория:

```bash
docker build -t ai-tutor-frontend services/frontend
docker run --rm -p 8080:80 ai-tutor-frontend
```

Сборка обслуживается nginx на http://localhost:8080 с fallback для SPA-маршрутов.
Фронтенд включён в общий Docker Compose. Для общего dev-стека выполните
`./dev.sh -d` из корня после настройки `.env` и установки mkcert
по корневому README. Скрипт подготовит localhost-сертификаты и dev-сеть. Адрес определяется HTTPS bind/port и именем сервера; Caddy
направляет `/api/v1` и `/api/v1/*` в backend, удаляя префикс `/api/v1`.
Проверка backend доступна на `/api/v1/health`; остальные пути идут во frontend.
Порт nginx доступен только внутри Docker-сети.

Для отдельной пересборки из этой папки:

```bash
docker compose --env-file ../../.env up -d --build
```

Локальный Compose подключается к внешней сети `ai-tutor_default`; nginx доступен Caddy как `frontend:80`.
Настройки `VITE_*` применяются при сборке. Для общего dev-стека продолжайте
использовать корневой Compose; не запускайте оба варианта одновременно.

## Live reload в Docker

Корневой `./dev.sh -d` использует Dockerfile target `dev`: Vite слушает порт 80
внутри контейнера, а Caddy проксирует HTTPS и HMR WebSocket. Исходники смонтированы
из `services/frontend/`, `node_modules` находится в отдельном Docker volume.
Polling включён только в контейнерном dev-стеке через `DEV_POLLING=true`.
Настройки `VITE_*` передаются как env; изменение `.env` требует пересоздания контейнера.
При изменении npm-зависимостей выполните `docker compose restart frontend` из корня:
при старте контейнер выполняет `npm ci`.

## Загрузка материалов курса

В админке можно добавить один PDF или ZIP. ZIP раскрывается только в браузере; архив принимается целиком, если все записи — обычные PDF, без скрытых и служебных файлов. Каждый PDF получает собственные неделю и вид из справочника backend (по умолчанию первая доступная опция). Кнопка «Отправить всё» отправляет файлы последовательно пакетами до 48 PDF с результатом по каждому файлу; ошибки сохраняются для повтора. Замена материала принимает один PDF и сохраняет прежнюю версию при ошибке обработки. Построение графа остаётся отдельным ручным действием после загрузки; если набор исходных материалов изменился после публикации, граф помечается «Не актуален». Лимиты архива: 250 МиБ на ZIP, 500 файлов, 50 МиБ на PDF, 250 МиБ на суммарный размер очереди.

Результат загрузки, ошибки выбора/отправки и предупреждение о частичной загрузке показываются в `react-modal`: закрытие кнопкой, Escape или кликом на фон. Успех подтверждает сохранение файлов; распознавание и обработка продолжаются в фоне. Ошибки отдельных файлов остаются в карточках для повторной отправки.

Карточки материалов показывают текущий этап (очередь, ожидание моделей, OCR, перевод, очистка) и статус «Готов к графу» только после завершения обработки. Сводка графа отдельно считает готовые материалы, обрабатываемые и ошибки; текст блокировки относится ко всей обработке.

## Student course shell

Student routes `/learn` and `/exam` share a course header with a selector when
the active direction has multiple available courses and a «К выбору режима»
link to `/`. The selected course is user-scoped and shared across both modes;
an explicit `subject_id` URL takes precedence. Explicit selection updates that
URL, so reload and browser Back/Forward restore the matching course and scoped
history/state. Ready task audio uses `/learn/task-audio/{id}/file` through the
shared authenticated audio adapter. The student screens have no direction tabs.
Mode-specific title, intro, history and session content stay below the shared
header. Returning to mode selection leaves active Geek and learning intents in
`sessionStorage`, so reopening a mode resumes its session.
An explicit shared course selection or `subject_id` URL takes precedence over
an older resumable session view; the session intent remains available when the
student selects that course again. Historical learning state can be restored by
the shared course ID or learning intent, with loading and retryable error states.
Lesson mutations belong to the current auth session epoch, so late responses
cannot replace progress after logout and login.

Перед новой диагностикой на главной `/learn` показывается удобный интерактивный граф
«Ваш путь обучения» в стиле Сириус.Курсов: в центре — название предмета, от него
расходятся цветные ветки компетенций, а от компетенций — составляющие блоки,
отобранные для диагностики. По клику на составляющую открывается карточка темы с
выбранными для проверки основным и базовыми образовательными результатами.
Доступны масштабирование, центрирование и полноэкранный режим.
На `/learn` под четвёртым шагом «Подготовьтесь по плану» показано «Подтяните слабые места»; над графом убраны пояснение «Блоки карты, выбранные для диагностики» и счётчики компетенций, тем и результатов.
Данные читаются через `GET /learn/subjects/{subject_id}/diagnostic-outline`:
backend применяет тот же отбор `constituent-map-v1`, что и при создании варианта,
и возвращает только выбранные компетенции, составляющие и основной/два базовых ОР.
Пропущенные компетенции и составляющие остальных ОР в граф не попадают.
Просмотр не сохраняет вариант и не начинает диагностику. Связи графа ведут от
центрального предмета к компетенциям и от компетенций к составляющим.
После диагностики персональный план по пробелам создаётся прежним механизмом.
Ошибка загрузки допускает повтор и не блокирует старт диагностики.
